# 5種類の UI レイアウトとカスタマイズ

設定画面の「デザイン」から、画面の構成を5種類のどれかに切り替えられます。どれを選んでも、データ・計算エンジン・機能・URL は同じです。変わるのは見た目、配置、ナビゲーション、情報の並び順、密度です。

| ID | 名前 | 根拠（`claude/sharp-hopper-ylg33o` の `design-research/`） | 骨格 | スマホ |
|---|---|---|---|---|
| `original` | Original（現在の標準） | 改修前のアプリ | 左サイドバー 236px | 下部タブ4つ＋その他 |
| `research` | 研究室向け Pipeline Ledger | `A-research-lab/`（案C 4.30点） | 上部パンくず／左「段のリスト」（資料→解析→計算→知見→計画→レポート）／右「根拠パネル」／下「ジョブモニター」。本文 13px の高密度 | ホーム・解析・クラウド＋その他 |
| `public` | 公共向け 3層レイヤー | `B-public/`（案C 4.42点） | 識別帯（公式情報ではないことを明示）／文字サイズ切替（標準・大・特大）／上部の主要5項目／左「画面」一覧と「データの状態」。ホームは 第1層 結論 → 第2層 比較 → 第3層 根拠 の順。本文 16px、操作対象 48px | ホーム・資料・レポート＋その他 |
| `commercial` | 商用向け Outcome Hub | `C-commercial/`（案C 4.37点） | 上部ヘッダー（検索・操作、主操作「レポートを開く」）／左レール 208px（成果物→作成→資料の順）。ホームは成果物カード（レポート・計画・データ・試算）から | ホーム・解析・レポート・設定＋その他 |
| `enterprise` | 大企業品質 Federated Shell | `D-enterprise/`（案C 4.36点） | スコープバー（研究室 › 研究 › 保存先）／アイコンレール 76px ⇄ 展開 232px／右に「証跡」列／配色切替・Ctrl+K | ホーム・資料・解析・シミュ＋その他 |

色・文字・余白などの値は、各分類の `design-system.md` と `recommended-design-system.md` §4 の値です（`frontend/src/ui/layouts.css`）。

### 存在しない機能は作っていない

研究成果のプロトタイプにある次の要素は、このアプリに対応する機能がないため**表示していません**。

- Public の光化学オキシダント注意報バナー、多言語切替
- Commercial の料金プラン・課金表示（Pro・税込価格など）
- Enterprise の組織切替・ロール切替・承認の受信箱

Enterprise のスコープバーには、実際の範囲（研究室・研究・保存先）だけを表示します。ロールは「単一利用者（権限管理なし）」と表示します。根拠パネルと証跡列に出すのは、画面・URL・保存先・接続状態・資料取得日・知見数・クラウドジョブ数・版です。どれも実在する情報です。

## 設定の切替（設定 → デザイン）

1. カードを押すと、画面全体がそのレイアウトでプレビューされます。設定はまだ保存されません。画面上部に「プレビュー中」の帯が出て、別の画面に移動してもプレビューが続きます。
2. 「適用」を押すと保存されます（`localStorage` のキー `aqros-ui-prefs-v1`）。保存した設定は再読み込みしても残ります。
3. 「取り消す」を押すとプレビューを捨てます。「Original に戻す」は1回押すだけで標準デザインに戻して保存します。「元に戻す」を押すと直前の設定に戻ります（最大5段）。
4. 「詳細カスタマイズ」では、主色（文字とのコントラスト比も表示。ダーク配色では、選んだ色を読める明るさに自動で調整して使います）、文字の大きさ、情報密度、サイドバーの位置と表示（展開・アイコンのみ・隠す）、カード（枠線・影・フラット）、角の丸み、配色（端末に合わせる・ライト・ダーク）を変えられます。サイドバーを隠しても、☰ のメニュー（Original では下部のメニュー）から全機能を開けます。
5. スマホでは、5種類のカードを2列のサムネイルで並べます。

保存先はこの端末のブラウザだけです。研究データ（IndexedDB またはサーバーの SQLite）とバックアップファイルには触れません。保存できない環境（プライベートモードなど）でも動きます。その場合、設定は再読み込みすると元に戻り、画面にもそう表示します。壊れた保存値や未知の ID が入っていた場合は Original で起動します。

## 構成（責務の分離）

```
frontend/src/
├─ core/            共通基盤: API・計算エンジン（models.ts）・統計・IndexedDB・クラウド — 今回変更なし
├─ pages/           画面の業務ロジック（10画面）— Settings に「デザイン」を1行追加、Dashboard はブロックをレイアウトの指定した順（homeOrder）に並べる
├─ components/ui.tsx 共通部品 — Card に section 属性、進捗バーとスライダーに読み上げ名、横にはみ出す表の枠（TableWrap）を追加
├─ app/             共通: ナビゲーション定義（navigation.ts）・ルーティング（AppRoutes.tsx）・シェル状態（useShellState.ts）・ホームのブロックの名前と既定の順（homeSections.ts）
└─ ui/              表示層
   ├─ prefs.ts           設定の型・検証・保存（React に依存しない純関数。prefs.test.ts）
   ├─ UiPrefsContext.tsx 保存済み／プレビュー中の設定、<html> への反映
   ├─ LayoutFrame.tsx    全レイアウト共通の枠（main とルートの位置を固定）
   ├─ parts.tsx          共有部品（通知帯・プレビュー帯・コマンドパレット・その他シート・下部ナビ・根拠パネル）
   ├─ DesignSettings.tsx 設定「デザイン」
   ├─ layouts.css        トークンと骨格（Original 以外、またはカスタマイズ時だけ効く）
   └─ layouts/           original / research / public / commercial / enterprise ＋ registry.ts
```

- **計算・業務ロジックは1つだけです。** 5つのレイアウトは、同じ `AppRoutes`（同じページ部品）を同じ位置に描きます。レイアウト側の部品は `core/api.ts` を読むだけで、計算処理を持ちません。
- **切り替えても入力が残ります。** `LayoutFrame` は子要素の並び（読み上げ領域、スキップリンク、上部、左、main、右、下、シート、パレット）を固定し、使わない位置は `null` にします。そのため React はページ部品を作り直しません。URL も変わりません。
- **Original は改修前と同じです。** Original かつカスタマイズなしのときは、`<html data-ui="original">` だけを付けます。`layouts.css` の規則は効かず、`styles.css` は変更していません。
- **ホームの並び順は DOM の順で変えます。** 各レイアウトの `homeOrder`（`LayoutSpec`）の順に `pages/Dashboard.tsx` がブロックを並べます。CSS の `order` は使いません（`order` だと Tab 順・読み上げ順が見た目と食い違うため）。ブロックには key が付いているので、切り替えても作り直されず位置だけが入れ替わります。Original の順は改修前の DOM と同じです。
- **起動時の配色は先に付けます。** `frontend/public/ui-init.js` が、本体の JS より前に保存済みのレイアウトと配色を `<html>` に付けます（配色を「ダーク」に固定した利用者に、明るい画面が一瞬出ないようにするため）。保存値がないときは何も付けません。
- **全機能に到達できます。** メニュー項目は `app/navigation.ts` だけに書きます。各レイアウトはその並べ方を決めるだけで、どのレイアウトのメニュー・コマンドパレット・「その他」シートにも全10機能が出ます。

## 6種類目を追加する手順

1. `src/ui/prefs.ts` の `LAYOUT_IDS` に ID を足す。
2. `src/ui/layouts/<id>.tsx` に `LayoutSpec` を作る。スロット（Top / Side / HomeIntro / Aside / Bottom / More）と、名前・説明・スマホのタブ・ホームの並び順（`homeOrder`）・既定の密度などを書く。
3. `src/ui/layouts/registry.ts` の `LAYOUTS` に足す。
4. `src/ui/layouts.css` に `:root[data-ui="<id>"]` のトークン（ライト・ダーク）と `.ux-<id>` の骨格を足す。
5. `public/ui-init.js` の ID の一覧に足す（`npm test` が `LAYOUT_IDS` と一致するか確かめる）。
6. `node e2e/ui-layouts.cjs` と `node e2e/final-checks.cjs` を実行する。`LAYOUTS` 配列のレイアウトは、全機能への到達・計算結果の一致・スマホの重なり・axe-core の各検査に自動で入る（`final-checks.cjs` の `HOME_ORDER` には並び順を書き足す）。

ページ・計算・保存処理には手を入れません。

### Original について
- `styles.css` は変えていません。Original の修正は `layouts.css` の末尾（「Original のコントラスト修正」「最終点検（スマホ・横向き）での修正」「アクセシビリティ監査での修正」）にあります。

- サイドバーの位置・表示だけを変えた Original は、サイドバー以外（本文）が改修前と画素単位で同じです（同じ検査の後半）。
