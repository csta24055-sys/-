# S5 再現手順と独立確認の記録

## 1. 再計算の方法

```
python3 scripts/quant_recompute.py      # research/quant_outputs.json を書き出す
python3 scripts/build_tables.py         # SOURCES.md と COVERAGE_TABLE.md を台帳から再生成
python3 scripts/sync_registry.py        # テーマの進捗と競合の検証状態を台帳から再計算
python3 scripts/ledger.py stats         # 台帳の件数
python3 scripts/research_gates.py check # 工程ゲートの機械検査
python3 -m unittest discover -s tests   # 否定テストと台帳整合性テスト
```

外部ライブラリは使っていない（Python標準ライブラリのみ）。乱数も使っていないため、同じ台帳からは同じ結果が出る。

## 2. 何をどこから計算しているか

| 出力 | 入力 | 計算 |
|---|---|---|
| Wilsonの95%区間（8件） | `registry/quant_results.csv` の値と標本数。区間を付けるのは、回答者の割合で標本数が分かり、`model_id` が M_WILSON95 の行だけ | 二項割合のWilsonスコア区間（z=1.959964） |
| 他社の転換率を当てはめた人数 | 他社の中央値3つ（S040）と、仮の導入人数3通り | 掛け算のみ。ASSUMPTION_ONLY |
| 製品案の最大後悔 | `scripts/decision_inputs.json` の順序点（-2〜+2） | 各シナリオの最良点との差の最大値。全セルを±1動かした53通りと、シナリオを1つ除いた4通りを再計算 |

## 3. 独立確認として行ったこと

- 区間は、台帳に記録した値（登録時に別の関数で計算）と、再計算スクリプトの値が8件すべて一致することを確認した。
- 最初の版では、標本数がアプリ数である行（QR12, QR13）にも区間を計算していた。アプリ数は回答者数ではなく二項試行ではないため誤りであり、該当行を除外するよう修正した。
- 台帳の整合性は `tests/test_live_ledger.py` が検査する（採用資料は原文確認済みであること、数値が採用資料に結び付くこと、識別不能の行に数値が入っていないこと、画像やアプリのコードがGitに入っていないこと）。
- 証拠の本文（引用した数値）は、取得した原文の該当行を表示して読み取った。読み取りは1人（1回）で、第三者による照合は行っていない。

## 4. 再現できないこと

- 取得した外部ページの本文はリポジトリに保存していない。数値を確かめるには、台帳のURLを開き直す必要がある。ページは更新・削除され得る（確認日時は台帳に記録）。
- 白書の標本数、Stanfordの2026年調査の標本数は原文で確定できておらず、該当行には区間を付けていない。
- 検索結果は検索エンジン側で変わるため、同じ検索語でも同じ結果になるとは限らない。検索語と実行時刻は `registry/search_log.csv` にある。

## 5. 第三者に確認してほしい点

1. `decision_inputs.json` の順序点。分析者1人の判断であり、点を付け直すと結論が変わる可能性がある。
2. 証拠台帳の `claim_text` が原文の内容と合っているか（特に S003, S004, S020, S031, S035, S043）。
3. 大学生協連の第61回調査（2026年2月発表）と白書の調査概要。原文を読めていない。
