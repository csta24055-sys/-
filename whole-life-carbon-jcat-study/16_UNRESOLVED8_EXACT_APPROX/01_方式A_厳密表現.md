# 方式 A（厳密）：2 構造の範囲での厳密な表現

使う構造は既存の 2 つだけである：**マスク付き積和**（`sp`：各行で因子の積を項ごとに足す。因子は列・定数・1 列の有理関数・述語。グループ和も含む）と、**最初の一致の検索**（`match`：キーが等しい最初の行への参照）。節点スペクトル Σ_k c_k [t_k ≤ x] は定数をもつ `sp` そのものである。エンジン（`msp.py`）は一切変更していない。変えたのは、指示で許された**数値表現、文字コードの配列化、索引集合、補助列、ステップ数、節点の設計**だけである。外部関数で答えを計算して渡すことはしていない（定数表は Unicode・cp932 などの**データに依存しない**規格の表と、10 のべきなどの定数に限る）。

以下、「参照評価器」は原版の算定規則の表計算ソフトとしての意味（キャッシュ値 3,818,483 セルで照合済み）をコードにしたもので、方式 A はこれを**再現**する。

## A-1. 文字列を「位置と文字符号の組」の索引集合として持つ

**表現。** テキスト値は、行が（式の実例 g、位置 p、文字符号 c、有効 v）である子表の集まり（**区分**）で表す。区分は次の 4 種類で、どれもエンジンの表（索引集合）にすぎない。

1. **セルのテキスト**：セルの値がテキストなら、その文字を 1 文字 1 行に並べたもの（データ配置。テキストを文字に分解するのは表現の設計であり、計算ではない）。
2. **数値の一般形式の文字**：実例ごとに 24 行（スロット s = 0..23）の表。各スロットの文字符号と有効性を `sp`・`match` で**計算**する（A-2）。
3. **定数の文字列**（式の中の文字列定数、TRUE/FALSE）：長さ L の定数を実例ごとに L 行。有効性はマスク（例：セルが論理値の真のときだけ "TRUE" が有効）。
4. 空白セルは区分なし（長さ 0）。

**連結。** a & b & … の出力位置は、各区分の位置に「それより前のオペランドの長さの和」を足したもの。長さは区分ごとのグループ和 Σ_rows [有効] で、すべて `sp`。エラーは左のオペランドから先に伝播（first_error）。結果のテキストは、有効な行を位置の順に読むだけ（読み出し）で得られる。

**正しさ。** 各区分の有効な行の位置は 0..長さ−1 を 1 回ずつとり、オペランドの区分のうち有効なのは型に応じて 1 つだけ（テキスト／数値／TRUE／FALSE は排他的なマスク）。したがって有効な行の（位置, 文字）の集合は、参照評価器の to_text(a) + to_text(b) + … と 1 対 1 に対応する。

## A-2. 数値の一般形式（15 桁）を `sp` と `match` だけで文字にする

参照評価器の規則：x = 0 なら "0"；整数で |x| < 10^15 なら整数の 10 進表記；それ以外は "%.15g"（15 有効桁、2 進値の偶数丸め）で、指数 E が −5 < E < 15 なら固定小数点（末尾の 0 を除く）、それ以外は「仮数（末尾の 0 を除く）E±dd」。

1. **厳密な 10 進の桁位置 E = ⌊log10 |x|⌋。** 節点 c_k ＝「10^k 以上の最小の倍精度数」とすれば、どの倍精度数 x についても [c_k ≤ |x|] = [10^k ≤ |x|] が**厳密に**成り立つ（c_k の定義から）。E = Σ_{k=−340}^{308} [c_k ≤ |x|] − 341。
2. **厳密な 15 桁の仮数 M（"%.15g" と同じ偶数丸め）。** |x| = M·10^{E−14}、M ∈ [10^14, 10^15)。
   - 10^{−8} ≤ |x| < 10^{15}：y = |x|·10^{14−E} を two-product で 2 倍長 (yh, yl) として**厳密に**得る（10^{14−E} ≤ 10^{22} は倍精度で正確）。整数部 ⌊yh⌋ は整数格子の節点スペクトル（2 分法、53 ステップ）、端数 (yh − ⌊yh⌋) + yl と 1/2 の比較は厳密な倍精度比較の組合せで、偶数丸めを決める。
   - 10^{15} ≤ |x| < 10^{37}：正しく丸めた割り算 |x|/10^{E−14}（Dekker の残差による補正）と、厳密な残差 R = |x| − q·10^{E−14}（2 倍長）で丸めを決める。
   - |x| < 10^{−8} または |x| ≥ 10^{37}：10^{14−E} を 2 のべきで倍率を変えた **3 倍長**の定数（誤差 2^{−159} 相対）で掛け、誤差のない変換で (y0, y1, y2) に正規化する（誤差 2^{−156}|y| ≤ 2^{−106}）。端数の 1/2 との比較は、y0 の端数 a が 1/2 でなければ a だけで厳密に決まり（|a − 1/2| ≥ ulp(y0) > |y1 + y2|）、a = 1/2 のときだけ y1 + y2 の符号で決まる。その距離が 2^{−100} 以下のときだけ判定不成立（欠損）とする。この範囲では**ちょうどの同点は起こり得ない**（同点には 5^{|E−14|} が 2^{53} 未満の仮数を割り切る必要があり、|E − 14| ≥ 23 では不可能）。レビューで見つかった 2 倍長の判定の甘さ（約 2^{−45} の閾値で、近接同点の倍精度数が 10 進桁ごとに数百個欠損になっていた）は、この 3 倍長化で解消した（同じ列挙で欠損 0）。
   - 仮数が 10^{15} に繰り上がった場合は M = 10^{14}、E + 1 に正規化。
3. **桁の数字。** q_j = ⌊M/10^j⌋（積 M·10^{−j} の床を、整数の厳密な残差で 1 だけ補正）、D_i = q_{15−i} − 10 q_{16−i}。末尾の 0 の個数 tz = #{j = 1..14 : q_j·10^j = M}（整数の積は厳密）、有効桁数 k = 15 − tz。
4. **スロットの文字。** 形式（固定小数点の正／負の指数、指数表記）・符号・桁数・小数点の位置・指数の 2 桁／3 桁から、スロット s の文字を、述語のマスクと「桁番号 i をキーにした数字表への `match`」で決める。長さ以上のスロットは無効。

**正しさの範囲。** 有限のすべての倍精度数（正規化数・非正規化数・±0・最大値）。3 倍長の判定が成立しないのは、真の値が 15 桁の丸めの中点から 2^{−100}（15 桁目の単位で）以内にある倍精度数だけで、試験した近接同点の列挙（10 進桁 −9・37 などで各 3 千件）でも 0 件だった。連結のどこかがエラーのとき、結果はエラーで、数値の文字には依存しないので、その判定は結果に影響させない。

## A-3. 条件付き合計（SUMIF / COUNTIF）の条件が連結で作られる場合

条件テキスト（区分の和集合＝1 つの索引集合）に対して、参照評価器の criterion の意味をそのまま実現する。

1. **演算子の接頭辞。** 位置 0, 1 の文字（`match` で取り出す）から、正規表現 ^(<=|>=|<>|=|<|>)? と同じ優先順位で演算子と長さ（0〜2）を決める（述語の積）。残り（rest）の位置は p − 長さ。
2. **数値・空の条件の静的除外。** 最後のオペランドが定数テキスト s で、(a) s に < > = 以外の文字が含まれ（接頭辞は先頭の < > = しか取らないので、その文字は必ず rest に残り、rest は空にならない）、(b) s の最後の空白でない文字が、空白除去と全角の半角化のあとで数字・小数点・% のどれでもない（rest は数値として読めない）とき、条件の数値・空の分岐は起こり得ない。このことを式の構造から**静的に証明**して、該当する分岐を除く。条件を満たさない式は方式 A の対象外として変換しない。（レビューで、s が演算子の文字だけ（例 "="）のとき rest が空になり得ることが指摘され、条件 (a) を加えた。）
3. **ワイルドカード照合（= と <>）。** 対象範囲の各セル（実例 × セルの組の索引集合 P）のテキストの文字位置 j = 0..長さ の行を持つ表 D を作り、**パターンの位置ごとに 1 回の遷移**（ステップ数は固定の L_max = 255）で動的計画法を進める：
   - 文字：new[j] = old[j−1]·[文字が一致]
   - `?`：new[j] = old[j−1]
   - `*`：new[j] = [j ≥ j_min]、j_min ＝ old = 1 となる最初の j（`match` が表の順で**最初の行**を返すことを使う）
   - `~` による退避（~*, ~?, ~~）とパターンの末尾より先：new = old
   照合結果は j = セルのテキストの長さでの値。「文字が一致」は Python の正規表現の大文字小文字無視（sre の規則）を再現する定数表（大文字小文字の区別がある文字か、単純小文字の同値類の代表）による述語の和で書く。区別のない文字は完全一致。
4. **順序の比較（<, >, <=, >=）。** 各文字の照合キー（小文字化した文字の cp932 の符号、なければ ff ff + UTF-16）を定数表から得て、最初に異なる位置（`match` の最初の一致）で大小を決め、異ならなければ長さで決める。文字ごとのキーの比較がバイト列の比較と一致することは cp932 の符号が接頭辞符号であることによる。**例外**：U+0130（小文字が 2 文字）、U+F8F3（cp932 の 1 バイト 0xFF がフォールバックの接頭辞になる）、U+03A3（小文字が文脈で変わる）が決定位置以前にあるときは一致を保証できないので**欠損**とする。
5. **改行の扱い。** 参照評価器の照合は Python の正規表現で、`$` は文字列の末尾のほか「末尾の 1 個の改行の直前」にも一致する。したがって参照評価器では、テキスト t + 改行 のセルも t と一致する。方式 A はこれも再現する（スイッチ `NL_DOLLAR`。表計算ソフト本体はおそらくこう振る舞わないので、本体に合わせるときは切る）。
6. **合計とエラー。** 一致した組の数値の和（グループ和）。一致した範囲で最初のエラー（セル順）を返すのは「条件を満たす最初の行」の `match`。

**適用範囲。** rest が 255 文字以下（ステップ数の設計値）。上の 3 文字の例外を除くすべてのテキスト・数値・論理値・空白・エラー。

## A-4. VALUE(LEFT(x, n))

1. **LEFT。** to_text(x) を A-1・A-2 の区分の和集合とし、位置 < n の行を使う。
2. **VALUE（テキスト → 数値）。** 参照評価器の to_float_text（前後の空白除去、全角 ０-９．，－＋％ の半角化、末尾の % と再度の空白除去、正規表現 [+-]?(\d{1,3}(,\d{3})+|\d+)(\.\d*)?([eE][+-]?\d+)? | [+-]?\.\d+([eE][+-]?\d+)?、float()、% なら /100）を、**19 状態の決定性有限オートマトン**で表す。位置ごとに 1 回の `sp`：state' = Σ_{(s,c)} [state = s][class = c]·T(s, c)。文字の分類（空白・数字・符号・小数点・桁区切り・指数・%）は定数表への `match`。同じ遷移で、仮数の数字 N、小数部の桁数 f、指数 e と符号を積和で累積する。
3. **10 進から倍精度への正しい丸め。** 値は N·10^k（k = ±e − f）の最近接の倍精度数。|k| ≤ 22 では 10^{|k|} が正確なので、**1 回の IEEE 演算**（積、または正しく丸めた割り算）で厳密に正しく丸まる。23 ≤ k ≤ 308、−290 ≤ k ≤ −23 は 2 倍長の積と判定（k = 23 は 10^{23} = ph + pl が正確で積も正確なので常に正しい）、−340 ≤ k ≤ −291 は 2^{1074} 倍してから整数に丸めて非正規化数を作る。k < −340 は 0。% は正しく丸めた割り算 /100 を**すべての倍精度数**について行う：商が正規化数なら v = 2^e f（2 進格子による厳密な分解、f ∈ [0.6875, 1.4375)）として f/100 を継承の正しく丸めた割り算（引数がその有効範囲の内側）で求め、2^{e−1}·2 を掛ける（正規化数の範囲で厳密）。商が非正規化数なら m = |v|·2^{1074}（2^{59} 未満の整数、厳密）を 100 で割った商を、two-product と Sterbenz の補題による厳密な剰余で補正し、偶数丸めして 2^{−1074} を掛ける。（レビューで、2 のべきの倍率だけでは継承の割り算の補正が働かない帯域が残ることが見つかり、この形に改めた。）
   2 倍長の判定では、結果が 2 のべきで真の値がそれより 0 側にあるとき、丸めの境界は ulp/4 の位置にあることを考慮する。
4. **適用範囲。** n ≤ 15（仮数の数字 N が 2^{53} 未満で厳密であるための設計値）で、float() が無限大に溢れる場合（参照評価器が inf を返す。表計算の値ではない）以外のすべての入力。LEFT の中が連結でもよく、LEFT の文字数を省略した形（1 文字）も扱う。n = 4 では溢れも判定不成立も起こり得ず、**全入力で厳密**。−0 は +0 として返る（表計算ソフトには −0 がない）。

## A-5. ROUND / ROUNDDOWN / ROUNDUP（定数の桁数 d = 0..22）

参照評価器の丸めモデル：float(Decimal("%.15g" % x).quantize(10^{−d}, 四捨五入／切り捨て／切り上げ))。

1. A-2 の厳密な (符号, M, E) を得る（"%.15g" と同じ）。
2. j = 14 − d − E（M のうち 10^{−d} より下の桁数）。j ≤ 0 なら値は M·10^{E−14} の最近接の倍精度数：E ≤ 36 では正確な積または正しく丸めた割り算、E ≥ 37 では A-4 の 10 進→倍精度の正しい丸め（10^{E−14} の 2 倍長定数との積と判定。k = 23 は常に正確）。1 ≤ j ≤ 15 なら q = ⌊M/10^j⌋ と剰余 r（整数の厳密な残差で補正）から、四捨五入は [r ≥ 10^j/2]、切り上げは [r > 0] で N = q + inc。j ≥ 16 なら q = 0, r = M。
3. 結果 N/10^d を正しく丸めた割り算で倍精度にする（float(Decimal) と同じ最近接丸め）。

**引数の計算。** ROUND の引数の中の四則演算は、方式 A では割り算も**倍精度の全範囲で正しく丸める**（仮数を [0.6875, 1.4375) に正規化してから継承の割り算、指数を戻す。溢れは無限大、非正規化数の商は厳密な剰余で 2^{−1074} の格子に丸める）。継承の割り算は商が 2^{±300} の外で補正が働かず、レビューで極端な除数（例 5×10^{−324}）での誤りが見つかったため。引数が無限大・非数のときは参照評価器と同じく #NUM!。

**適用範囲。** 参照評価器が定義されるすべての入力（10 進の桁 E と桁数 d について E + 1 + d ≤ 60。それを超えると参照評価器自身が 60 桁の精度を超えて例外になる）。2 倍長の判定が成立しない入力は欠損だが、試験では 0 件。

**原版ソフトとの一致について。** このモデルが表計算ソフトの ROUND と常に同じかは、原版のキャッシュ値では判別できなかった（丸めの境界付近の呼び出し 6,101 件のうち、モデル間で結果が異なる入力は 0 件）。LibreOffice の再計算では、境界の 1 件で異なる値（−0.001 と −0）が出た。したがって方式 A は「参照モデルとの厳密一致」であって、原版ソフトとの厳密一致は主張しない。

## A-6. 非整数乗・常用対数

実数としての厳密表現は不可能（03_不可能性の証明.md）。方式 A は有限精度での正確な実現（真値の正しい丸め、証明書つき）。
