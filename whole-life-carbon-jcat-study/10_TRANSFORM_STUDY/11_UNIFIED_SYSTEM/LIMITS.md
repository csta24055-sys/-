# 成立範囲・数学的な限界・未解決事項

## 1. 証拠の水準

- この統合系の「一致」は、架空データの上での**数値の一致**である（証拠水準 N）。確認者は実装者だけで、独立の検査・外部のレビューは受けていない。
- 恒等式として示したのは次のものに限る（`DERIVATIONS.md`）：条件分岐と指示関数の積の等価（D-01）、年重みの和と clip の和の等価（D-03 (1)）、
  クリップ・ランプの切断べき表示（D-03 (4)）、べき零行列のレゾルベントの因数分解（D-08 (c)(d)、SymPy・SageMath で厳密に確認）、区間形と跳び形が同じ関数であること（D-09）。
- 「70 単位のすべての出力が任意の入力で一致する」という定理は示していない。示したのは、各単位の式の構成と、1,293 組での一致である。
- 対象は独立概念モデルである。他のツールの式・係数・結果と等しいとは述べていない。実測されていない近似の実用上の精度は保証しない。

## 2. 入力の範囲

| 条件 | 外れたときの扱い |
|---|---|
| 0 < T ≤ H（H は年次表の長さ、架空データでは 130 年） | 統合系は T を拒否する。基準計算は年次表が足りないと例外で止まる |
| H < 256（冷媒の積和 8 段） | 仕様の `NDBL` を増やす必要がある（未実施） |
| 事象の時刻が T・整数年から相対 1e-10〜1e-8 の帯に無い | 比較から除外（境界条件 `life_near_divisor` の 2 組）。帯の中での一致は未検証 |
| 旧研究の索引 6.1 節の 9 条件（有限の値、正の周期、None の無い表、擬似キーと衝突しない係数 ID など） | 条件の外では基準計算の値そのものが定義文と食い違うか例外になる。比較の対象にしていない |
| 経路の比率・年次表・明示の一覧に None が無い | 基準計算は例外で止まる。統合系の挙動は確かめていない（欠損として伝わるか、`Unusable` で止まる） |

欠陥入りシナリオ（欠損、単位の不整合、使用許諾なし、比率の合計の誤り、期間外の事象、面積の不整合）は有効範囲の外だが、基準計算が例外を出さない範囲で比べ、不一致 0 だった（別扱いで報告）。

## 3. 2 構造の外に置いた処理（判断が要る点）

| 処理 | 理由 | 見方 |
|---|---|---|
| 文字列の分割（「/」、`名前[番号].残り`） | 単位「単位/year」、電力係数の単位、状態の上書きのキーを読むため | 入力の符号化。全文字列列に一律で、単位の種類は知らない。積和の演算ではない |
| 行の並べ替え（用途別面積） | 基準計算の足す順序（用途名の昇順）を再現するため | 添字集合の順序づけ。順序を無視すると残差が 1e-12 程度ずれる |
| 相異なる値の表（材料区分、周期の値） | まとめる先の表が入力に無いため | 添字集合の構成 |
| 節点の格子（n·c、一覧）と年セルの番号 | 事象の位置 | 節点スペクトルの一部 |
| 名前付きの値の並べ直し（`TT`、`U`） | スペクトルの値と単位の値を次の積和の入力にするため | 算術なし |
| 読み出しでの重複の除去と整列 | 違反一覧（場所の集合）を基準計算と同じ形にするため | 算術なし。件数と合否は積和だけで出る |
| 節点スペクトルの区間形（B1-04） | 跳び形が桁落ちするため | 跳び形と同じ関数の別の表現で、評価は節点の探索による。これを別の構造と見る立場では、同じ値を与える積和の局所形（`System(..., b14="local")`）を使えばよい。2 つは毎回両方計算している |
| 「最初に合う行」（`match`） | 検索と優先順位 | 積和の構造の中の順序つきの演算として数えている（2026-11-11 からの未決事項） |

これらを「前処理に隠した個別計算」と見るかどうかは、利用者の判断に委ねる。排出量の算術（数量・係数・率・時間の重み）は、すべて積和と節点スペクトルの中にある。

## 4. 数式と実装の対応

- 仕様（`specs/`）が実行される式そのものである。`DERIVATIONS.md` と `UNITS_70.md` の式は、仕様から人が書き起こした。両者を機械的に照合する仕組みは無い。
- 対応の確かさは、(1) 基準計算との全出力の一致、(2) 仕様を 1 か所壊すと該当の単位が不一致になること（24 件）、(3) `UNIT_MAP.md`（コードから自動生成）による。

## 5. 数値の限界

- 最大の相対差：X-13 の 2.2e-12（発注量を `Q·(1/(1−w))` で作る丸め）。それ以外では B3-01 の 5.7e-13（26,300 行。行数とともに増える）。
- 倍精度で完全に一致しない量が多い（足す順序、除算を逆数との積で行うこと、積和 8 段の積の順序が基準計算と違う）。ビット一致の割合は `VERIFICATION.md` の 2 節。
- 跳び形の節点スペクトルは、強く減衰する状態量（冷媒の期末残存量）では桁落ちする。区間形で 6.6e-15、跳び形では漏洩率 35％・60 年で 4e-6、60％で破綻（EXP-U1）。
- `1 − r·w` が 0 に近い場合（漏洩率と年重みの積が 1 に近い）は、基準計算も同じ引き算をするので、どの表現でも相対精度が下がる。

## 6. 比べていないもの

- 基準計算の内部の受け渡し用の値（名前が `_` で始まるキー：行ごとの活動量の一覧、使用した係数の集合など）。公開出力を通して間接的に確かめているだけである。例外は冷媒の状態で、これだけは内部状態と直接比べた（EXP-U3）。
- 基準計算が例外を出す入力での挙動。
- 計算時間の体系的な測定。参考値（1 回の実行、`results/verification_*.json` の `seconds_system`・`seconds_reference`）：評価用集合（60 建物 × 5 期間）で統合系 約 17 秒・基準計算 約 24 秒、最大規模（1 建物 × 2 期間）で 約 6 秒・約 3 秒。
  建物ごとの準備が重く、評価期間を増やすほど有利になる（1 期間あたり約 0.01〜0.05 秒）。
- 実在の建物のデータ、他のツールの式。
