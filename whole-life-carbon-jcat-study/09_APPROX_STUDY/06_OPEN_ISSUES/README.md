## D. 精度について検証できていないこと

1. **実建物での実用精度。** 一致を確認したのは、独立に設計した基準計算と統合モデルの間だけである。基準計算そのものが現実の排出量をどれだけ正しく表すかは、この研究の対象外である。
2. **他のツールの結果との一致。** 比較していない。比較や結果の公表には権利者の確認が要る（第1章 1-B の 4）。
3. **基準計算の正しさの独立な確認。** 基準計算と統合モデルはどちらも主担当（自動の AI エージェント）が書いた。両者は書き方が違う（逐次計算と、単一走査＋閉形式）ので互いの誤りは検出しやすいが、同じ定義の読み違いは両方に入り得る。初版に対して 3 つの独立した自動検査を行い、定義の穴（係数の単位・対象段階を確かめていない単位があった、記述子と年次表の食い違いで結果が分かれた、など）が見つかったので改めた（[04_VERIFICATION/INDEPENDENT_REVIEW.md](../04_VERIFICATION/INDEPENDENT_REVIEW.md)）。改めた後の版に対する独立検査は、まだ行っていない。人による確認、手計算との全面的な照合も行っていない。
4. **数値の丸め。** 相対 1e-9 を許容差とした。表示上の丸め（桁数、端数処理）は扱っていない。
5. **規模の外挿。** 資材 2 万行までしか測っていない。
6. **単位単独の代理モデル。** M5（高度な代理モデル）は、建物全体の水準（AP-11・AP-16）と段階の水準（AP-15）でだけ測定した。評価単位ごとの代理モデルは作っておらず、「候補なし」は理由による判断である。
7. **測定せずに見送った段階。** 進捗台帳の「候補なし」は、測定をしていない判断である。件数は [05_DECISIONS/PROGRESS.md](../05_DECISIONS/PROGRESS.md) の段階別の表にある。

## E. 測定についての注意

- 計算時間・命令数・メモリは、純粋な Python の実装どうしを同じ機械で比べた値である。実装言語や実行環境が変われば絶対値は変わる。
- 時間は、ごみ集め（GC）を止めて測った値を使う。GC を動かすと、一時オブジェクトを多く作る基準計算のほうが遅くなり、式の効果ではない差が加わる（初版はこの差を含んだ数字を掲げていた）。主な指標は実行した命令数である。
- 軸 A の順位は、架空ベンチマークの行数の比率（資材 : 設備 : 冷媒機器 = 200 : 60 : 5 など）に依存する。
- 軸 B は 3 つの自動評価（AI エージェント。人ではない）の判断で、評価が割れた単位（X-17、X-13、X-15、X-10、SUM-08、B2-01）がある。順位は着手順の参考にだけ使った。採点は初版の台帳に対するものである。
- 原版ブックの計算時間は測っていない（実行していない）。数式ノード数は繰り返しの多さの代理指標にすぎない。

## H. 次の段階に向けて

- 材料分類のデータ構造は [07_MATERIAL_TAXONOMY](../07_MATERIAL_TAXONOMY/README.md) に設計案を置いた。実データがないため、分類の粒度や操作数の妥当性は未検証。
- 統合モデルの「行」（段階・係数 ID・活動量・乗数のパラメータ）は、材料データを計算につなぐ共通の受け口になる。材料分類の側で、1 行に必要な項目（数量の単位、係数の参照、更新周期、修繕率、廃棄経路）を欠けなく決められるかが次の論点である。
