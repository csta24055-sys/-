## 1. 位置づけ（次段階の構造調査であり実装ではない／実データ未入手）

本書は、計算式の研究の次に行う材料データ整理に向けて、データ構造と手順の形だけを先に調べたものである。材料データの整理そのものではなく、UI・画面・アプリのコードも含まない。本書の「候補」「既定」「並び順」は、解決手順が返すデータの性質を指し、画面の設計ではない。

| 項目 | 状態 |
|---|---|
| 実在の材料データセット（品目一覧・単位・係数） | **未入手**。材料が何件あるか、名称ゆれ・単位違い・重複がどれだけあるか、本設計が実データにどの程度合うかは、何も言えない |
| 実建物の数量内訳書・設備機器表 | 未入手 |
| J-CAT の分類表・コード表・原単位・更新周期・修繕率など | 他の算定ツールへの流用は禁止（[第1章](../../01_COMPLIANCE/README.md)）。本書は参照も、記憶からの再現もしていない |
| 分類表・集計表ワークブック | シート名だけが [ALL_198_SHEETS.json](../../02_SOURCES/ALL_198_SHEETS.json) にある。内容は利用できない。シート名から読めるのは「建築と設備職種ごとに表が分かれているらしい」「複合品や配管・配線の表があるらしい」という程度で、本設計はその内容に依拠せず、中身を推測して埋めることもしていない |
| 分類名・列挙値 | 一般的な建築用語から本研究で選んだ暫定案。どの既存分類表の写しでもない |
| 例示レコード | すべて架空。係数・耐用年数・修繕率・密度・構成比の値を含まない |

本書は、独立に作成した3つの設計案（分類体系を先に決める案、正規化を先に決める案、指定の手数を先に決める案。いずれも作業用の草案で、本リポジトリには収録していない）を比較し、統合したものである。比較と採否は6章に示す。

**言えること**：3つの JSON が構文として正しく、例示レコードの参照・列挙値・必須項目・同一性キーが定義と矛盾しないこと（python3 で読み込んで検査した）。
**言えないこと**：それ以外のすべて。特に、階層の深さや粒度が妥当か、操作が実際に減るか、代表レコードを使ったときの精度がどうなるか。

## 2. 分類体系（階層と9区分の対応）

### 2.1 2つの軸

分類を1本の木（部位 → 材料 → 仕様）にすると、複数の部位で使う材料が部位ごとに枝分かれして重複する。そこで「どこで・何の役割で使うか」と「それが何であるか」を別の軸にし、対応表でつなぐ。

```
部位軸（どこで・何の役割で使うか）          品目軸（それが何であるか）
 1 区分       DIVISION                      1 素材・品目系統  SUBSTANCE_CLASS
  └ 2 部位グループ GROUP  ← 指示書の9区分      └ 2 品種        material_type
     └ 3 部位要素  ELEMENT ───配置 placement───── └ 3 正規材料レコード canonical_material
```

| 軸 | 階層 | 名称 | 分類の原理 | その階層で決まること |
|---|---|---|---|---|
| 部位 | 1 | 区分 | 建物本体か設備か | 集計の大区分（選択には使わない） |
| 部位 | 2 | 部位グループ | 指示書第7章の区分 | 報告・集計の標準単位 |
| 部位 | 3 | 部位要素 | 数量を拾い分ける単位（建築は部位、設備は系統） | 配置の受け皿、部位に依存する前提の参照先 |
| 品目 | 1 | 素材・品目系統 | 主たる素材、または機器・線状品・複合品の種別 | 品目別集計の単位 |
| 品目 | 2 | 品種 | 宣言単位と仕様属性の定義が共通になる範囲 | 数量の単位、仕様属性、別名の主な付け先 |
| 品目 | 3 | 正規材料レコード | 品種＋同一性に効く仕様値 | 計算行が参照する最小単位、重複判定 |

- **配置**（`placement`）は「部位要素 × 品種」の許される組合せを1件ずつ持つ多対多の表である。同じ品種を複数の部位で使うときは、品種を複製せずに配置を増やす。
- 厚さ・強度区分・口径・容量区分などは階層にせず、品種の**仕様属性**にする。階層にすると組合せの数だけ枝が増えるためである。
- 品種と正規材料レコードは、実データが無いと1件も根拠を持って定義できないので、[classification_tree.json](classification_tree.json) には含めていない。

### 2.2 指示書の9区分との対応

| 指示書の区分 | 区分 | 符号（`code`） | 部位要素の草案 | 未確定の境界 |
|---|---|---|---|---|
| 基礎 | 建築 | `FOUNDATION` | 杭・地業／基礎本体／基礎梁 | 基礎梁・地下部分・土間を躯体とどう分けるか |
| 躯体 | 建築 | `STRUCTURE` | 柱／梁／床／耐力壁／階段 | 耐力のある外壁、屋根の架構 |
| 屋根・外壁 | 建築 | `ROOF_EXTERIOR_WALL` | 屋根仕上・防水／屋根断熱／外壁仕上／外壁下地／外壁断熱 | 耐力壁の外側の層をどこまでここに置くか |
| 開口部 | 建築 | `OPENING` | 外部窓／外部扉／内部建具 | 内部建具を内装に置くか |
| 内装 | 建築 | `INTERIOR` | 床仕上／壁仕上／天井／間仕切 | 天井に組み込む設備器具 |
| 電気設備 | 設備 | `ELECTRICAL` | 受変電／幹線・配線／照明／通信・弱電／発電・蓄電 | 発電・蓄電の所属 |
| 空調設備 | 設備 | `HVAC` | 熱源／空調機／ダクト／空調配管／換気／自動制御 | 換気・自動制御の所属 |
| 給排水設備 | 設備 | `PLUMBING` | 給水／給湯／排水／衛生器具 | — |
| 搬送設備 | 設備 | `CONVEYANCE` | エレベーター／エスカレーター／その他搬送 | 「その他搬送」が受け皿になる懸念 |

- 屋根と外壁は、指示書の区分に従って1つの部位グループとし、部位要素で分ける。
- 指示書の「など」に備え、外構（`EXTERNAL_WORKS`）、仮設（`TEMPORARY_WORKS`）、その他設備（`OTHER_SERVICES`）を**予約**（`RESERVED`）として置く。算定範囲に含めるかを決めるまで使えない。
- 「未分類」「その他」という受け皿のグループは作らない。配置できない行は行の側の状態（`placement_state = UNPLACED`）とし、部位別集計では「未配置」として別掲する。0 として扱うことも、近い部位に寄せることもしない。
- 部位の判定の考え方（暫定）：物質や施工する業者ではなく建物の中での機能で決める。多層の構成は層ごとに分ける。荷重を支える役割と仕上げを兼ねるものは荷重を支える側に置く。決まらない境界は、ノードの定義に「含む・含まない」を書き足して解消し、行ごとの場当たりの判断で済ませない。

### 2.3 品目軸の第1階層（草案）

| 種類 | 系統（符号） |
|---|---|
| 素材で分けるもの | コンクリート・セメント系（`CEMENTITIOUS`）／鉄鋼（`FERROUS_METAL`）／非鉄金属（`NONFERROUS_METAL`）／木材・木質材料（`TIMBER`）／組積・窯業系（`MASONRY_CERAMIC`）／石材・骨材・土（`STONE_AGGREGATE_EARTH`）／ガラス（`GLASS`）／樹脂・プラスチック（`POLYMER`）／塗料・仕上塗材（`COATING`） |
| 機能・形態による括り（素材へ分け直す可能性あり） | 無機質ボード（`MINERAL_BOARD`）／断熱・保温材（`INSULATION`）／防水・シーリング材（`WATERPROOFING_SEALANT`） |
| 種別で分けるもの | 建具・金物などの成形品（`FORMED_PRODUCT`）／機器本体（`MACHINE_UNIT`）／器具・端末（`TERMINAL_FIXTURE`）／盤・制御機器（`PANEL_CONTROL`）／配管・ダクト・配線（`DISTRIBUTION_LINE`）／複合品（`COMPOSITE`） |

設備の品目は職種（電気・空調・給排水・搬送）ではなく物理的な種別で分ける。ポンプ・配管・保温材・ケーブルなどは複数の職種で使われうるので、職種で分けると同じ品目が職種の数だけ重複するためである。職種は部位軸の側で表す。この分け方が妥当かは、設備の品目データが職種別に別の値で提供されているかを見ないと決められない（7章 U-04）。

### 2.4 属性をどちらの側に持たせるか

| 属性 | 持たせる場所 | 理由 |
|---|---|---|
| 係数への参照、質量への換算 | 品目側（製品・正規材料レコード・品種） | 物質と仕様で決まる |
| 宣言単位、単位換算 | 品種（換算は正規材料レコードごとにも登録できる） | 物質の性質で決まる |
| 耐用年数・修繕率・廃棄経路への参照 | 品目側と部位側の両方に束縛できる | どちらで決まるかは実データが無いと決められない（U-07） |
| 部位、区分（棟・階） | 配置と計算行 | 使われ方で決まる。品目の同一性に含めない |
| その部位で数量を入れる単位、その部位での代表 | 配置 | 使い方で決まる |
| 報告・集計の区分 | 部位グループと素材・品目系統 | 2通りの集計を両立させる |

### 2.5 ID・符号・版

| 規則 | 内容 |
|---|---|
| ID | 意味を持たない連番（接頭辞＋6桁以上）。親・階層・名称・単位・出典側のコードを埋め込まない。再利用しない。レコードは物理削除しない |
| 符号（`code`） | 人が読むための英語の符号。区分・部位グループ・素材系統では集計の見出しになるので、有効化後は変えない。参照には必ず ID を使う |
| 改名・移動 | ID は変えない。旧名は別名に残す |
| 統合・分割・廃止 | 対象を廃止状態にし、後継 ID を記録する。分割された分類へ、既存の案件行を自動では振り分けない |
| 版 | レコード定義・正規化規則・データのそれぞれに版を持つ。計算行は解決に使った版を記録し、公開した版の内容は変えない |

## 3. 正規化（名称ゆれ・類似材料・単位違い・重複の扱い）

### 3.1 原則

1. 受領した姿は書き換えない。受領レコードは追記専用で残し、正規化結果は再生成できる派生物とする。
2. 誤統合は取りこぼしより悪い。統合漏れは操作が1回増えるだけだが、誤統合は計算結果を黙って変える。迷ったら統合しない。
3. 数値は統合しない。出典の違う係数参照や換算根拠を、平均・代表値の選択・上書きで1つにまとめない。
4. 不明は不明のまま止める。欠損を 0・1・「一般的な値」で補わない。
5. ライセンスは最も厳しいものが伝わる。派生レコードの状態は、寄与したすべての出典のうち最も制限の強い状態とする。

### 3.2 手順の全体

| 順 | 手順 | 出力 |
|---|---|---|
| 0 | **ライセンス関門**。出典を台帳に登録し、中身を読む前に許諾を判断する。許可（証拠あり）でない出典は取り込まず、中身を保存せず、理由だけを記録する。名称一覧・分類ラベルも「中身」として扱う | `source` |
| 1 | 受領。名称・仕様・単位・見出しだけを写し、係数などの数値列は写さない。同じ出典の同じ内容の行は受領時に1件へ集約する | `raw_record` |
| 2 | 名称欄の正規化（3.3）。規則一式に版を付け、変更したら全件を再正規化して差分を確認する | 名称キー、仕様トークン |
| 3 | 単位欄の解析（3.5）。名称欄とは別の解析器で扱う | 単位コード |
| 4 | 名称の解決。別名表を名称キーの完全一致で引き、品種を決める。仕様トークンを品種の仕様属性に割り当て、同一性キーを計算する | 品種、同一性キー |
| 5 | 重複の判定（3.6）。同じ同一性キーのレコードがあれば新しく作らず来歴を足す | `canonical_material`、`merge_event` |
| 6 | 配置。出典の見出しは手掛かりにするが、そのまま採用しない。決まらなければ未配置のままにする | `placement` |
| 7 | 類似関係の記録（3.4）。統合ではない | `similarity_link` |
| 8 | 不変条件（[taxonomy_schema.json](taxonomy_schema.json) の INV-01〜16）を全件検査し、合格したときだけ版を公開する | `release` |

品目側（手順4・5）を配置（手順6）より先に決めるのは、同じものかどうかは品目側だけで判定でき、部位の情報が欠けた出典でも重複の整理まで進められるためである。

### 3.3 名称ゆれ

| 段 | 名称欄の規則 | 注意 |
|---|---|---|
| N1 | Unicode の互換正規化（全角英数字→半角、半角カナ→全角カナ、組文字の単位記号→英数字） | 丸数字なども展開される。意図しない展開が無いかは実データで確認が要る |
| N2 | 制御文字を除き、空白を1個にまとめる | 空白は仕様トークンの区切りに使うので、この段では消さない |
| N3 | 括弧と区切り記号を統一し、自作の装飾語リストに載る注記を外へ移す | 括弧の中身を無条件に捨てない |
| N4 | ダッシュ類を統一する（カタカナの直後は長音記号、英数字の間はハイフン） | — |
| N5 | 英字を小文字にする | **名称キーだけ**。単位欄には適用しない |
| N6 | ひらがなをカタカナに畳む | 漢字をかなに開くことはしない（読みは一意に決まらない） |
| N7 | 仕様トークン（厚さ・径・区分などの表記）を取り出し、名称本体から除く | 単位の無い数値は「仮定した」ことを残す。どの属性か決まらなければ保留する |
| N8 | 空白を除いて名称キーにする。末尾の長音の有無・異体字は、名称キーを壊さず**派生キー**（照合用の索引）で吸収する | 畳みすぎによる衝突は別名表の一意性検査で表面化させ、人が判断する |
| N9 | どの規則でも解釈できずに残った文字列を出力する | 空でなければ未完了とし、黙って捨てない |

- **規則で吸収するもの**（別名の行を増やさない）：全角／半角、半角カナ、大文字／小文字、ひらがな／カタカナ、空白、括弧の種類。
- **人が別名表に登録するもの**：漢字とかなの読み替え・交ぜ書き、略称、同義語、現場用語、総称、外国語名、誤記、旧名。
- 総称のように複数の品種を指す語は、候補の一覧を持つ別名（`AMBIGUOUS`）として登録し、どれか1つに自動で寄せない。
- 別名表は、取込時の名称の解決と、指定時の名称検索の両方に同じものを使う（二重に持たない）。
- N5〜N8 の対象表と N7 の切り出しの型は、実データの表記を見てから定める。現時点では未定義である。

### 3.4 類似材料

| 場合 | 扱い |
|---|---|
| 同じ品種で仕様値だけが違う（厚さ違いなど） | 類似関係ではなく、同じ品種の仕様属性の値の違いとして表す |
| 別の品種だが近い | `similarity_link`（`SIMILAR`）に記録する。検索と提案にだけ使い、既定では計算に影響しない |
| 検討して別物と判断した | 同じ表に `DISTINCT_CONFIRMED` と理由を残し、同じ提案を繰り返さない |
| 一般品と特定製品 | `GENERIC_OF` |
| 係数の代用 | `PROXY_CANDIDATE`。代用は近似なので、研究プロトコル P7 に従って誤差（特に過小評価）を検証するまで有効にしない。有効にした場合も、置き換えた事実を計算行に残す |

類似度だけを根拠に自動で統合することはしない。類似度のしきい値は未設定である（正解付きの実データが無いと決められない）。

**仕様属性の役割**。3案の間で「厚さは同一性に含むか」が食い違っていたため、属性ごとに役割を持たせる。

| 役割 | 意味 | 例（架空） |
|---|---|---|
| `IDENTITY` | 値が違えば別の正規材料レコード。係数・質量換算・耐用年数・修繕率・廃棄経路のどれかを変える属性 | 面積で数える板の厚さ |
| `CONVERSION_PARAM` | 数量の換算にだけ使い、同一性に含めない。値は行ごとに与える | 体積で数える充填材を面積で拾うときの厚さ |
| `DESCRIPTIVE` | 説明のみ（色など） | — |

何を変える属性かが分からない間（現時点ではすべて）は `IDENTITY` として扱う。`CONVERSION_PARAM` への変更はレコードの統合を伴うので、データで確認してから行う。

### 3.5 単位違い

| 論点 | 扱い |
|---|---|
| 宣言単位 | 品種ごとに1つ。次元の違う単位を同じ品種の宣言単位にしない。係数が結び付いたら係数の分母に合わせる（現時点ではすべて暫定） |
| 同じものの単位表記・数え方の違い | 別の品種・別の材料にせず、単位換算として登録する |
| 同じ次元の換算（kg と t など） | 単位辞書の定義値だけで行う |
| 次元をまたぐ換算（面積→体積→質量など） | 品種または正規材料レコードごとに登録する。根拠の出所を必ず持つ：仕様値そのもの／行ごとの入力／自分で登録した等価関係／外部台帳 |
| 根拠の値 | 密度・単位質量などの値は表に持たず、外部のパラメータ台帳への参照と、その状態・許諾だけを持つ |
| 根拠が無い換算 | 「停止状態」のまま登録する（その単位が実際に現れるという事実を残す）。その単位で入力された数量は計算しない |
| 個数の単位 | 枚・本・台・基などは数え方ごとに別の単位コードとし、自動では換算しない。等価とみなす場合は、品種ごとに人が登録する |
| 一式 | 数量×係数の計算には使えない単位として扱う |
| 単位欄の解析 | 名称欄とは別の解析器を使う。大文字小文字を畳まない。同じ文字が欄によって別の意味を持ちうる（例：`t` は単位欄では質量、名称欄では厚さの接頭語でありうる） |
| 経路が複数ある | 両方で計算し、差が許容差を超えれば止める（許容差は未設定） |
| 質量への経路 | 輸送・廃棄段階に必要なので、有無を材料ごとに持つ。経路が無い材料は、その段階が「0」ではなく「計算できない」になる |
| 算定境界 | 単位が同じでも、係数の含む段階が違う参照を同一視しない。係数参照ごとに分母単位と含む段階を持ち、台帳の記載と一致しなければ計算しない |

機器の容量による按分のようなモデル計算は単位換算ではないので、換算表に入れない（計算式研究の対象）。

### 3.6 重複

| 水準 | 定義 | 扱い |
|---|---|---|
| `D0_RAW_EXACT` | 同じ出典の同じ内容の行 | 受領時に1件へ集約し、出現回数を数える |
| `D1_IDENTITY` | 正規化後に同一性キーが一致 | 作成時に防ぐ。後から一致した場合は**自動統合してよい唯一の場合** |
| `D2_UNIT_VARIANT` | 同一性は同じで単位だけが違う | レコードは1件にし、別の単位は換算として登録する。人の確認が要る |
| `D3_NEAR` | 名称や仕様が似ているが一致しない | 人が判断する。結果は「統合」「別物として維持」「類似関係」のいずれか |
| `D4_CROSS_SOURCE` | 別の出典が同じ材料を別の値で記述 | レコードは1件、係数参照と換算根拠は出典ごとに別の行。平均しない・選んで捨てない |

- 統合は `merge_event` に、根拠・残す側を決めた規則・項目ごとの決着・統合前後のライセンス状態を残す。退く側の行は消さず、名称は別名に移す。取り消し（分割）ができる。
- 統合後の実効ライセンスが悪化する統合は成立させない。D2〜D4 は判断者と確認者を別人にする。
- 同じ品目が部位別に別の値で提供されている出典は、勝手に統合しない。差の理由（算定境界など）が出典で確認できるときだけ、係数参照に配置の限定を付けて同じレコードの下に残す。

### 3.7 許諾のあるデータと無いデータを分ける仕組み

| 仕組み | 内容 |
|---|---|
| 取込前の関門 | 許可（証拠あり）でない出典は中身を保存しない |
| 状態の伝播 | レコードの実効ライセンス状態は来歴から計算し、手入力しない |
| 値を持たない | 係数・耐用年数・修繕率・密度・構成比の値を入れる項目を、カタログ側のどのレコードにも作らない。項目名で機械的に検査する |
| 別名の根拠 | 別名ごとに根拠の種類を必須にする。制限付きの出典に載っている名称を別名として登録することは、係数の転記と同じ扱いで禁止する |
| 区画 | 公開用の版には、許可状態のレコードしか入れない。非公開の区画は予約であり、現時点では使わない |
| 公開前 | 公開リポジトリに置いたものは履歴に残るので、関門は置く前に通す |

## 4. 少ない操作で指定するためのデータ構造

### 4.1 操作の数え方

画面の作りに左右されないよう、次の5種類を数える。案件ごとに一度だけ決める条件（主要構造、解決の厳しさなど）は、材料1件あたりの操作に数えない。

| 操作 | 定義 |
|---|---|
| `PICK` | 有限の候補から1つ選ぶ（候補数もあわせて記録する） |
| `ENTER` | 数値を1つ入れる（数量、厚さなど） |
| `SEARCH` | 名称を1回与える |
| `ACCEPT` | あらかじめ選ばれた既定を承認する |
| `OVERRIDE` | 既定や代表から得た値を別の値に置き換える（理由を記録する） |

補助指標として、選択情報量 Σlog2(候補数) を使う。9個から選ぶのと数百個から選ぶのとでは負担が違うためである。

### 4.2 操作を減らす構造

| 構造 | 何が要らなくなるか | 歯止め |
|---|---|---|
| 品種が宣言単位を、配置が入力単位を決める | 単位を選ぶ操作 | 許された単位以外は換算せずに止める |
| 名称から仕様トークンを切り出す | 名称入力とは別の、仕様値や厚さの入力 | 単位の無い数値は仮定した旨を残す |
| 別名表（1本） | 階層を辿る操作 | 複数を指す語は候補を返して止める |
| 既定の配置（品種ごとに1件） | 名称から入ったときの部位の選択 | 既定を使ったことを行に残す |
| 代表レコード（品種ごとに1件、決め方を記録） | 仕様が未定の段階での仕様値の指定 | 4.4 |
| アセンブリ（層構成・機器一式・出発点の一式） | 関連する材料を1件ずつ指定する操作 | 構成量が無い行は欠損のまま残す。二重計上を検査する |
| パラメータ束縛の継承 | 係数・耐用年数・修繕率・廃棄経路を行ごとに指定する操作 | どの水準から来たかを行に残す。どこにも無ければ欠損 |
| 取込時の自動対応付け | 一意に解決できた行の手作業 | 一意でないもの・未登録のものは人が判断する |

絞り込み（代表から個別仕様へ）は、同じ行の材料レコードと参照の**置き換え**であり、行を増やさない。

### 4.3 指定の経路と、構造上の最小操作数

| 経路 | 手順 | 最小操作数 | 増える場合 |
|---|---|---|---|
| 階層から | （部位グループ →）部位要素 → 品種 → 数量 | 部位グループが決まっていれば `PICK` 2 ＋ `ENTER` 1 | 仕様値を指定するたびに ＋1。換算に寸法が要れば ＋1 |
| 名称から | 名称 → 数量 | `SEARCH` 1 ＋ `ENTER` 1 | 語が複数を指せば `PICK` ＋1。既定以外の部位なら `PICK` ＋1 |
| アセンブリから | アセンブリ → 基準数量 | `PICK`（または `ACCEPT`）1 ＋ `ENTER` 1 で複数行 | 構成量が台帳に無い行は、数量を直接入れるたびに ＋1 |
| 取込から | 内訳の行を読み込む | 0 | 名称が未登録・複数候補、仕様値の不足、未配置のそれぞれで ＋1 |

いずれも部位グループが決まっている状態から数えた（[example_records.json](example_records.json) の行は、部位グループの選択も含めて数えている）。この表は、データ構造が許す最短の経路を数えたものであり、**操作が減ることの証拠ではない**。実際の回数は、候補数（部位要素ごとの品種の数）、別名の網羅度、既定が当たる割合で決まり、いずれも実データが無いと分からない。1回の `PICK` の候補数に上限を置く案はあるが、値は決めていない。なお、手間の大半は数量の拾い出しであり、指定の操作を減らしても数量を調べる手間は減らない。

### 4.4 仕様が足りないときの扱い（2つのモード）

3案の間で「仕様が欠けたら止める」と「代表で成立させる」が食い違っていたため、どちらで解決するかを案件ごとに明示し、行に写して残す。

| モード | 仕様値が足りないとき | 想定する使い方 |
|---|---|---|
| `STRICT` | 止める（`VARIANT_UNSPECIFIED`） | 取込、詳細な算定 |
| `COARSE_ALLOWED` | 品種の代表レコードで解決し、行に「代表」と記録する | 仕様が決まっていない段階の粗い算定 |

- 代表を使えるのは、その品種に代表レコードがあり、決め方が記録されている場合だけである。決め方が未定（`NOT_DECIDED`）の品種は、`COARSE_ALLOWED` でも止まる。現時点ではすべての品種がこの状態である。
- 品種内の係数のばらつきが大きい、または不明の品種の代表行は `REPRESENTATIVE_WIDE` と記録し、代表由来の行が全体に占める割合を結果とともに示せるようにする。
- **換算に使う寸法（厚さなど）は、どちらのモードでも既定値で補わない。** 名称にも入力にも無ければ止める。
- 代表の使用は近似である。研究プロトコル P7 に従って誤差（特に過小評価）を検証するまで、推奨としては扱わない。

## 5. 計算モデルとの接続（1行＝活動量・単位・係数参照・耐用年数・修繕率・廃棄経路）

材料の指定の結果は、計算研究へ渡す1行（`calc_row`）になる。カタログ側は値を持たず、外部のパラメータ台帳への参照と、その状態だけを行に渡す。項目名は仮であり、計算研究側の行の定義が確定したら合わせる。

| 行の項目 | どこから決まるか | 使う概念式（[第4章](../../04_FORMULAS/README.md) の ID） | 既存の入力項目（[第3章](../../03_INPUTS/README.md)） |
|---|---|---|---|
| 活動量（`activity`） | 入力数量 →（登録済みの換算）→ 宣言単位 | A13-01、A13-05 | `MATERIAL.quantity`、`EQUIPMENT.equipment_quantity` |
| 単位（`activity_unit`） | 品種の宣言単位 | SYS-02（係数の分母単位との一致） | `MATERIAL.quantity_unit`、`FACTOR.factor_unit` |
| 係数参照（`factor_ref`） | `param_binding`（`FACTOR`）。含む段階と分母単位を伴う | A13-01、製品固有の参照なら A13-03、SYS-03、QA-03 | `FACTOR.factor_id`、`EQUIPMENT.equipment_factor_id`、`MATERIAL.additional_epd_reference` |
| 質量換算（`mass_per_unit_ref`） | `param_binding`（`MASS_PER_UNIT`）または質量への換算経路 | A4-01、C2-01 | `TRANSPORT.transported_mass`、`END_OF_LIFE.waste_transport_mass` |
| 耐用年数（`service_life_ref`） | `param_binding`（`SERVICE_LIFE`） | B4-01、B4-02、B4-03 | `MATERIAL.material_life`、`MATERIAL.refresh_cycles`、`EQUIPMENT.equipment_service_life` |
| 修繕率（`repair_rate_ref`） | `param_binding`（`REPAIR_RATE`） | B3-01、B3-02 | `MATERIAL.repair_rate`、`EQUIPMENT.equipment_repair_rate` |
| 廃棄経路（`eol_route_ref`） | `param_binding`（`EOL_ROUTE`） | C3-01、C4-01、C-05 | `END_OF_LIFE.waste_treatment_route` ほか |
| 部位（`placement_id`） | 配置 → 部位要素 → 部位グループ | 部位別集計の鍵、QA-01 | `MATERIAL.construction_division`、`EQUIPMENT.equipment_trade` |
| 品目（`canonical_id`） | 正規材料レコード → 品種 → 素材・品目系統 | 品目別集計の鍵 | `MATERIAL.material_class`、`MATERIAL.material_specification`、`EQUIPMENT.equipment_model` |
| 状態（`param_states`、`representativeness`、`defaulted_fields`） | 解決の過程 | SYS-01 | `PROVENANCE.*` |
| 可否（`computable`、`blocking_reasons`） | 単位・権限・欠損の検査 | SYS-02、SYS-03、QA-03 | — |

- **束縛の探索順（暫定）**：行での置き換え → 製品 → 正規材料レコード → 配置 → 品種 → 部位ノード。係数と質量換算は品目側にだけ束縛できる。耐用年数・修繕率が品目で決まるのか部位で決まるのかは、実データが無いと決められない。同じ種別の参照が複数の水準にあるときは警告を出し、黙って片方を選んだことにしない。どこにも無ければ欠損のままにし、既定値を作り出さない。
- **アセンブリは行に展開する**。概念式 A13-02 は構成比から合成係数を作る形だが、構成要素ごとに耐用年数・修繕率・廃棄経路・係数の含む段階が違いうるので、合成係数1つにまとめず、構成要素ごとの行にする。複合品自身に係数の参照がある場合に限り、1行で計算する。同じ数量を両方で数えない。
- **2通りの集計**：部位グループ別の合計（未配置の別掲分を含む）、素材・品目系統別の合計、全体合計が一致することを不変条件にする。これは架空データでも試験できる。
- **計算構造としての位置**：分類表への結合は研究プロトコル P3 の `LOOKUP_JOIN`、アセンブリの展開は `MATRIX_EXPANSION` に当たると考えられる。分類体系は計算の入力の形を決めるだけで、計算式そのものは変えない。
- **近似・統合研究への接点**（いずれも置き場だけで、未定義・未検証）：品種の `calc_class`（材料をパラメータ化した共通モデル（P8 の M4）で使う区分キー）、仕様属性の `CONTINUOUS`（仕様値を連続パラメータとするモデル）、代表レコード（品種内を1件で近似する）。
- 既存の入力項目のうち、材料行 ID（`MATERIAL.material_id`）は案件内の行 ID であり、カタログ側の `canonical_id` とは別物である。既存の 01〜08 章のファイルは変更しない。

## 8. してはならないこと

1. J-CAT の分類表・コード表・名称一覧・原単位・更新周期・修繕率・漏洩率・工事分倍率などを、写すことも、記憶から書くことも、別名・対応表・階層・ID・アセンブリの根拠にすることもしない。分類表ワークブックのシート名から中身を推測して埋めない。
2. 規格・基準の本文を写さない。分類名は一般的な用語から自分で定める。
3. 許可（証拠あり）でない出典の中身を、表にも例にも記録にも保存しない。
4. カタログ側の表に、係数・耐用年数・修繕率・密度・構成比などの値を入れない。参照と状態だけを持つ。
5. 出典側のコードを ID にしない。出典のコード体系をそのまま階層として取り込まない。ID に意味を埋め込まない。ID を再利用しない。
6. 受領レコードを書き換えない。統合・廃止で行を消さない。
7. 部位が違うことを理由に、同じ品目を複製しない。
8. 名称が似ているだけの品目を自動で統合しない。類似品の係数を黙って代用しない。
9. 出典の違う係数参照や換算根拠を、平均・代表値の選択・上書きで1つにまとめない。
10. 欠けた数量・係数・換算根拠・構成量を、0・1・推測値で埋めない。単位が合わない数量を計算に通さない。算定境界（係数の含む段階）の違う参照を同一視しない。
11. 単位欄の大文字小文字を畳まない。名称欄と単位欄をまたいで文字の意味を解釈しない。
12. 既定・代表を黙って適用しない。代表による結果を、個別仕様による結果と同じ確からしさで示さない。
13. 分類できない行を、0 として扱ったり、近い部位に寄せたり、黙って除外したりしない。1行の数量を複数の部位へ自動で按分しない。
14. 架空の例で構造が組めたことを、実データへの適合や実用精度の根拠にしない。材料の件数、適合の程度、操作がどれだけ減るかについて、実データなしに数値を述べない。
15. 「J-CAT と同じ分類」「互換」「検証済み」と受け取られる表現を使わない。
16. この段階で UI・画面・アプリのコードを作らない。既存の 01〜08 章のファイルを書き換えない。
