# 独立した検査の指摘と対応

初版の結果（統合モデル、記録、報告書）に対して、3 つの検査を別々に行った。検査担当はいずれも自動の AI エージェントで、
互いの出力も、主担当の結論の根拠も見ずに、リポジトリの内容だけを読んで作業した（人による検査ではない）。
検査は読み取りだけで、リポジトリは書き換えていない。

この文書は、何が指摘され、どう対応したかの記録である。**対応後の版に対する独立した検査は、まだ行っていない**
（対応後の一致確認は、主担当が検証スクリプトを広げて行ったものである）。

## 1. 検査の観点

| 検査 | 観点 | 方法 |
|---|---|---|
| 数値の反例探し | 統合モデルと基準計算が食い違う入力はないか | 入力を壊したシナリオ、極端な値、冗長な入力の食い違いを作って両方を実行 |
| 定義からの再導出 | 基準計算は、台帳に書いた定義どおりか。定義そのものに穴はないか | 台帳の定義文だけから計算を書き直して基準計算と比べる。段階の境界、単位、端の規約を点検 |
| 記録の監査 | 記録・報告書の記述は、コードと測定結果に裏付けられているか | 成功とした記録の題名をコードと照合、演算の回数を計測、報告書の数字を JSON から再計算、指示書との適合を確認 |

## 2. 主な指摘と対応

### 2.1 一致が条件付きだった（重大）

| 指摘 | 対応 |
|---|---|
| 年次量と電力係数は、記述子（種類とパラメータ）と年次表の両方を入力に持つ。基準計算は年次表を、統合モデルは記述子を使っていたため、両者が食い違う入力では結果が分かれた（年次表の 1 年分を 3 倍にすると B6 が −1.15％）。この食い違いを検出する検査もなかった | どちらを正とするかを定義した（整った記述子を正とし、年次表は写し）。基準計算と統合モデルの両方をこの定義に合わせ、食い違いを報告する出力を加えた。食い違う入力を検証に加え、同じ値と同じ報告になることを確認した |
| 電力係数の記述子が整っていない場合（低下量が負など）の扱いが、2 つの計算で違った | 「整っている」条件を定義し、整っていなければどちらも年次表を使う |
| 基準案の結果を統合モデルが内部に保持していたため、基準案を書き換えると古い値を返した（基準案の合計が −22.9％）。しかも検証は保持していない状態でしか行っていなかった | 内部の保持をやめた。基準案の合計は、呼び出し側が渡した場合だけ使い回す。この使い方と、書き換え後の扱いを検証に加えた。使い回しの効果は成果の数字から外した |

### 2.2 定義の穴（基準計算の側）

| 指摘 | 対応 |
|---|---|
| B2 が対象段階の外にあるとき、施設管理分が B6 から引かれたまま、どの段階にも現れなかった（境界条件の例で運用エネルギー排出の 11.5％） | B2 が対象のときだけ B6 から引く。段階ベクトル、CO2 のみの結果、年次系列のすべてに同じ規則を適用 |
| 係数の単位と対象段階を確かめずに掛けている単位が 6 つあった。単位や段階の違う係数を指定しても、計算も検査も通った | 係数を使う条件を 1 つの規則にまとめ、すべての単位で適用。使えない行・経路・項目は合計に入れず、件数を報告し、合計に「不完全」の印を付ける |
| 処理経路の一部だけ係数が使えない行で、行全体を落とす単位と、その経路だけ落とす単位があった | 経路ごとに落とし、落とした経路の数を報告する |
| 小数の評価期間と周期の端（99.9 年と 33.3 年など）で、浮動小数点の誤差のために回数が 1 変わり得た | 「評価期間の内側」と「属する年」の判定に許容幅を定義し、両方の計算で同じ判定式を使う。該当する組を検証に加えた |
| 負の数量、範囲外の率、欠損を 0 とみなして黙って計算を続ける箇所があった | 除外して数える規則に統一 |
| 年次量の単位が「単位/year」であることを確かめていなかった | 条件として定義し、満たさなければ算出しない |
| 質量収支の検査が、廃棄質量を発注量と比べていた（据付量と比べるべき） | 据付量と比べる。架空データの生成器も合わせた |
| 評価期間が 0・負・非数・無限大のとき、2 つの計算の挙動が違った | どちらもエラーにする |
| 定義として残した選択（建替時に更新周期を初期化しない、設備の初期の搬入・据付を計上しない、エンボディドに B2 を含む）の影響の大きさが書かれていなかった | [06_OPEN_ISSUES](../06_OPEN_ISSUES/README.md) の B に、試算した大きさを付記 |

### 2.3 記録がコードより強いことを言っていた

| 指摘 | 対応 |
|---|---|
| 15 件の記録が「係数を掛ける前に活動量を合算する（乗算は係数の種類数）」と述べていたが、コードは行ごとに係数を掛けていた（係数 496 種に対して読み出し 21,559 回）。記録の裏付けが出力の一致だけだったため、仕組みの記述が誤っていても通っていた | 統合モデルを、合算（評価期間に依存しない）と乗数の適用の 2 段に作り直し、合計のみの出力では行ごとの乗算をしないようにした。記録が述べる仕組みを、統合モデル自身が数えた回数で確かめるようにした（成り立たなければ記録の生成が失敗する） |
| 「年ごとの繰り返しをしない」「更新年の一覧を作らない」は、合計のみの出力のときだけ正しかった | 記録の題名に条件を明記。全出力のときの回数も並べて示す |
| 「66 単位が 8 つのモデルに統合」の数え方に一貫した基準がなかった。「検査規則表」は表として実装されていなかった。基準案の再利用は式の統合ではない | 統合の基準を定義（値を共有の表から読むか、共有のパラメータ付き関数で求める）。モデルは 7 つに整理し、検査は実際に共有の関数にした 3 単位だけを統合に数える。基準案の再利用はモデルから外した |
| M6（厳密と近似の併用）の成功 14 件は、厳密な計算どうしの場合分けで、併用ではなかった | M1 に含め、M6 には実際の併用候補（年次表の系列だけ補間、上位行だけ詳細計算、上下限）だけを記録 |
| 3 単位が、測定した候補が 1 件もないまま「検証完了」になっていた。X-16 の保留は、データや権利の制約ではなく範囲の選択だった | 測定や導出の裏付けが 1 件もない単位は完了にしない規則を加えた。X-16 は架空の入力で基準計算に加え、統合を検証した |
| 不採用の記録に、その単位で測っていない誤差を引用しているものがあった（更新回数の近似を B5 や X-10 に付けていた） | B5 と X-10 でも測定した |
| 導出を示さずに「解析的に検証」と表示していた | 導出を [03_MODELS/DERIVATIONS.md](../03_MODELS/DERIVATIONS.md) にまとめ、導出のない記録は「架空データでの一致のみ」と表示 |
| 計算時間の削減率に、ごみ集めの影響が混ざっていた（基準計算の時間の約 37％）。規模 L は一致確認の対象に入っていなかった | 主な指標を命令数にし、時間はごみ集めを止めて測る。規模 L を一致確認に加えた |
| 直線的に変化する買電量にも厳密な閉形式があるのに、年ごとに計算していた。評価期間だけを変える再計算が、行の走査をやり直していた | どちらも実装し、基準計算と突き合わせた |
| 評価者（軸 B）が挙げた置き換え案のうち、記録に取り上げていないものがあった | 測定を追加し、対照表（[judge_proposal_trace.json](../03_MODELS/judge_proposal_trace.json)）を作った |
| 重視するとされた M4（共通の近似モデル）に、結論の出た候補がなく、候補も面積原単位の系統だけだった | 区分ごとの代表パラメータによる候補（AP-18 系）を加えて測定した。それでも結論は保留で、その旨を要約に明記した |
| 材料区分別の誤差が示されていなかった | 資材の行に作用する候補について追加 |
| シート族と評価単位の対応が、2 つのファイルで食い違っていた。「未調査」が 9 族だけのように読めた | 出所を 1 つにして機械的に同期。式の本文は全族で未調査であることを明記 |
| 「全体は 1 つの式で書ける」「材料・用途・構造の違いは式に現れない」が結果のように書かれていた | 独立概念モデルの設計によるものであることを明記 |
| 検査担当や評価者が人か自動かが書かれていなかった | 自動の AI エージェントであることを明記 |

## 3. 指摘のうち対応していないもの

- 出所レコードごとの入力状態の前計算、累積系列の閉形式、建替なしを範囲比 0 とする入力の整理は、実装していない（[06_OPEN_ISSUES](../06_OPEN_ISSUES/README.md) の G）。
- 評価軸 B の採点は初版の台帳に対するもので、やり直していない。採点は着手順序にだけ使っており、全単位を対象にしたので結論には影響しない。
- 基準計算そのものが現実の排出量を正しく表すかどうかは、この研究の対象外である。

## 4. 検査で問題が見つからなかった点

- 報告書の数字 54 個を JSON から再計算し、すべて一致した（初版）。
- 禁止された種類のファイル（原版の表計算ファイル、圧縮ファイル、PDF）、UI・Web・API のコード、実在の係数らしい値は、見つからなかった。
- 進捗台帳は、追加・変更指示の形式上の要件（全単位が 6 つの状態のいずれか、未実施の段階がある単位を完了にしない、理由の記載）を満たしていた。
- 統合モデルは、検査担当が独自に行った規模 L の比較でも基準計算と一致した（初版）。
