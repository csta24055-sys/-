## P2. 評価単位（計算式・式群）の定義

評価単位 = 独立概念モデルにおける固有の計算構造 1 件。次の 2 種類からなる。

1. **既存単位**：[formulas.json](../../04_FORMULAS/formulas.json) の 53 概念式。ID はそのまま使う（例 `A13-01`）。
2. **追加単位**：53 式に含まれないが、(a) シート族メタデータ、(b) 未接続の入力項目・出力項目、(c) 既存資料の記述から存在が読み取れる計算構造。ID は `X-01` から付番する。

追加単位には必ず根拠区分を付ける。

| 根拠区分 | 意味 |
|---|---|
| `EXISTING_CONCEPT` | 既存 53 式 |
| `INFERRED_FROM_SHEET_METADATA` | シート名・ノード数から存在を推定。原版の式本文は未確認 |
| `INFERRED_FROM_UNLINKED_INPUT` | 式に未接続の入力項目から、必要な計算構造を推定 |
| `INFERRED_FROM_EXISTING_DOCS` | 01〜08章の記述から推定 |

追加単位は「独立モデルに必要と考えられる計算構造の設計案」であって、原版の式の再現ではない。
シート族のうち計算構造を特定できないものは評価単位にせず、`NOT_INSPECTED`（未調査）として台帳に残す。

## P3. 分類台帳の様式（成果物1）

| 項目 | 内容 |

| `complexity` | 計算量（例 `O(N)`、`O(N·T)`） |

| `SUM_OF_STAGES` | 段階結果の合計 |
| `RATIO` | 比・原単位化・単位換算 |
| `MAX_CLAMP` | max/min による打ち切り |
| `PREDICATE_GATE` | 判定・検証（真偽を返す） |
| `MASS_BALANCE_CONSTRAINT` | 質量収支の制約 |
| `LOOKUP_JOIN` | コード・分類表の検索結合 |

## P4. 評価軸A：計算負荷・複雑性（成果物2）

**測定値を優先する。** 測定対象は「独立した基準計算」（P7）であり、J-CAT 原版ではない。原版は本環境に存在せず実行もしないため、原版側は数式ノード数を代理指標として併記するにとどめる。

| 指標 | 内容 | 取得方法 | 重み |
|---|---|---|---:|
| a1 | 実行時間シェア（基準計算の総時間に占める割合） | 実測。規模 S/M/L の中央値 | 0.35 |
| a2 | 基本演算回数（内側ループの反復回数） | 実測（計数） | 0.15 |
| a3 | ピークメモリ増分 | 実測（tracemalloc） | 0.10 |
| a4 | 入力変数数＋処理段数 | 台帳から算出 | 0.10 |
| a5 | 条件分岐・反復の複雑さ | 台帳から算出 | 0.10 |
| a6 | 他式との依存（入次数＋出次数） | 台帳の依存グラフ | 0.10 |
| a7 | 対応シート族の数式ノード占有率（原版側の代理指標、対応は推定） | sheet_families.json | 0.10 |

- 各指標を全単位内の百分位順位（0〜1）に直し、重み付き和を A スコアとする。
- モデル未定義で測定できない単位は a1〜a3 を欠測とし、残りの指標の重みを正規化して順位付けする（`measured=false` と明記）。
- **感度分析**：(i) 実行時間のみ、(ii) 全指標等重み、(iii) 代理指標 a7 を除外、の 3 通りでも順位を求め、重みの置き方で順位が大きく変わる単位を明示する。順位は着手順序の参考であり、研究対象を絞るためには使わない。

## P5. 評価軸B：簡略化・近似化・統合の余地（成果物3）

指示書の 8 観点を各 0〜3 点で採点する（合計 0〜24 点）。

| 観点 | 内容 |
|---|---|
| b1 | 数式が必要以上に複雑 |
| b2 | 本来まとめられる計算が別々に存在する |
| b3 | 入力条件が似ているのに異なる式を使っている |
| b4 | 複数の式を共通のパラメータモデルで表現できそう |
| b5 | 複雑な条件分岐を近似で置き換えられそう |
| b6 | 簡単な線形・多項式・補間モデルで代替できそう |
| b7 | 入力変数を減らせそう |
| b8 | 異なる式を共通の代理モデルへ統合できそう |

- 採点基準：0 = 該当しない、1 = わずかに該当、2 = 明確に該当、3 = 強く該当し具体的な置き換え案を示せる。
- 互いの採点を見ない 3 名の評価者（代数的統合／数値近似／入力・データモデル削減の各観点）が採点し、観点ごとの中央値の合計を B スコアとする。
- 評価者間の差が大きい単位（合計の最大差 6 点以上）は `B_DISPUTED` と表示し、理由を残す。

## P6. 研究対象と着手順序（成果物4）

追加・変更指示 第1号により、上位30％による選定は廃止した。

- **研究対象**：台帳に載った評価単位のすべて。順位が低いこと、計算負荷が小さいことを理由に除外しない。
- **着手順序**：2軸の結果から優先スコアを求め、高い順に着手する。異なる式を少数の共通モデルへ統合できる可能性を重視するため、軸Bのうち統合に関する観点（b2・b3・b4・b8）を独立の項として加える。

  `優先スコア = 0.35 × 軸Bの百分位順位 + 0.30 × 統合観点（b2+b3+b4+b8）の百分位順位 + 0.35 × 軸Aの百分位順位`

- 優先スコアの上位から 3 つの着手群（第1群・第2群・第3群）に分ける。群は着手の順番を示すだけで、第3群も必ず検証する。
- 旧方針の上位30％（`k = ceil(0.30 × N)`、境界同点は含む）は、軸ごとの参考表示として残す（`reference_top30`）。研究範囲の限定には使わない。
- 検証不能な対象は、理由と不足データを記録し、P10 の「未検証」または「保留」として扱う。完了扱いにしない。

## P7. 検証プロトコル（成果物5〜8）

### 基準計算
- 概念式の定義どおりに、行ごと・年ごとに逐次計算する実装（`research_code/refcalc/`）。簡略化を一切入れない。
- 候補モデル（`research_code/fastcalc/`）は、基準計算の関数を呼ばずに、入力シナリオだけから同じ結果を作る（共有するのは定数と比較の道具だけ）。
- 実施上の注記：基準計算と統合モデルはどちらも主担当が実装した。書き方が違う（逐次計算と、単一走査＋閉形式）ので互いの誤りは検出しやすいが、定義の読み違いは両方に入り得る。これを補うため、手計算との照合、意図的に入れた入力欠陥の検出試験、独立した担当による反証検査を行い、残る限界は [06_OPEN_ISSUES](../06_OPEN_ISSUES/README.md) D-3 に記載した。
- 入力検証（単位・境界・欠損）は基準計算でも候補でも同一規則で行い、近似の対象にしない。

### 架空データ
- 係数・数量・耐用年数・修繕率・漏洩率などはすべて乱数で生成した**架空値**（`SYNTHETIC_FICTIONAL`）。J-CAT その他の実データベースの値は使わない。
- 構造種別・用途・規模の違いは架空の生成パラメータで表す。したがって「構造別・用途別の誤差」は架空母集団上の値であり、実建物での精度を示すものではない。
- 乱数シードを固定し、再現可能にする。

### 誤差の評価
- 相対誤差 = (候補 − 基準) / 基準。符号を保持し、**過小評価（負の誤差）を別途集計**する。
- 集計：平均、95パーセンタイル、最大、最小（最大の過小評価）。建物全体、段階別、材料区分別、用途別、構造別。
- 暫定目標：建物全体 1％以内、主要段階 2％以内、重大な過小評価なし、適用範囲外では厳密計算へ戻せること。
- 厳密同値をうたう候補は、浮動小数点の丸め差（相対 1e-9 以内）を超える差が 1 件でもあれば不合格。

### 性能の評価
- 同一言語・同一実行方式どうしで比較する（ベクトル化の効果と数式置換の効果を混同しない）。
- 計算時間（反復の中央値）、ピークメモリ、基本演算回数、数式の種類数、必要入力項目数、共通化できた式群の数。

### 検証状態の語彙

| 状態 | 意味 |
|---|---|
| `VERIFIED_ANALYTIC_AND_SYNTHETIC` | 数学的導出があり、架空データでも基準計算と一致または誤差上界内 |
| `VERIFIED_SYNTHETIC_ONLY` | 架空データ上でのみ確認。実用精度は未検証 |
| `NOT_VERIFIED` | 検証不能または未実施（理由と不足データを記録） |

### 採否の語彙（候補モデルごと）

| 判定 | 意味 |
|---|---|
| `ADOPT_EXACT` | 厳密同値の簡略化・統合として採用候補 |
| `ADOPT_WITH_GUARD` | 適用範囲の条件付きで採用候補（範囲外は厳密計算へ戻す） |
| `KEEP_EXACT` | 近似しない（厳密計算を維持する理由を記録） |
| `REJECT` | 不採用（誤差・過小評価・物理的意味の喪失など） |
| `HOLD_DATA_NEEDED` | 検証保留（必要なデータを記録） |

## P8. 検討手順（追加・変更指示 第1号 3項）

全評価単位について、次の 6 段階を順に検討し、段階ごとの結論を記録する。

| 段階 | 内容 | 補足 |
|---|---|---|
| M1 | 数学的に完全に同じ結果になる簡略化 | 計算順序の変更、共通項の抽出、重複の削除、閉形式化、前計算の再利用 |
| M2 | 異なる式の共通化・統合（厳密） | 共通の関数と少数のパラメータで、結果を変えずに複数の式を 1 つにまとめる |
| M3 | 単純な近似式への置き換え | 線形、区分線形、多項式、補間 |
| M4 | 複数の異なる式を共通の近似モデルへ統合（重点） | 数学的構造が異なる式どうしも対象。材料・用途・構造・評価期間・修繕更新条件をパラメータ化 |
| M5 | 高度な代理モデルによる近似 | 回帰、応答曲面など。元の計算より重くなる・入力が増える場合は利点を再評価 |
| M6 | 厳密計算と近似計算の併用 | 適用範囲の判定と、範囲外で厳密計算へ戻す条件 |

- 段階ごとの結論は `SUCCESS`（検証済みで採用候補）、`REJECTED`（検証して不採用）、`NOT_APPLICABLE`（理由を明記。例：すでに厳密な閉形式があり近似の利点がない）、`HOLD`（データ・権利上の制約）、`NOT_DONE`（未実施）のいずれか。
- 「近似できない」という結論は、試した内容と理由を伴うものだけを認める。
- 精度・単位・算定境界が維持されない統合は採用しない。

## P10. 進捗台帳（追加・変更指示 第1号 5項）

`05_DECISIONS/progress_ledger.json` に、全評価単位の状態を 1 件ずつ記録する。

| 状態 | 表示 | 判定規則 |
|---|---|---|
| `DONE_SIMPLIFIED` | 検証完了・簡略化成功 | 6 段階すべてに結論があり、M1・M3・M5・M6 のいずれか（適用範囲の条件付きを含む）が `SUCCESS` で、統合（M2・M4）は成功していない |
| `DONE_UNIFIED` | 検証完了・統合成功 | 6 段階すべてに結論があり、M2 または M4 が `SUCCESS` |
| `DONE_APPROX_REJECTED` | 検証完了・近似不採用 | 6 段階すべてに結論があり、採用候補が 1 つもなく、保留中の段階もない（厳密計算を維持） |
| `IN_PROGRESS` | 検証中 | 一部の段階だけ結論がある |
| `NOT_VERIFIED` | 未検証 | どの段階にも検証結果がない |
| `HOLD_DATA_OR_RIGHTS` | データ・権利上の制約により保留 | 単位そのものが実データまたは権利の確認なしには検証できない。または、採用候補が 1 つもなく、いずれかの段階が保留中で結論を出せない |

- 単位が検証完了でも、個別の段階（例：M5 の代理モデル）が実データ待ちで `HOLD` のことがある。その場合は単位の状態に加えて `steps_on_hold` に段階と必要データを列挙する。保留中の段階を検証済みとして数えない。
- 「検証完了」は、架空データと数学的導出による確認が終わったことを意味する。実建物データでの実用精度の保証ではない（P7）。
- `NOT_DONE` の段階が 1 つでも残る単位を検証完了にしない。
- 状態は `research_code/tools/progress_ledger.py` が候補ごとの記録（`03_MODELS/records/*.json`）から機械的に求める。検証状態が `NOT_VERIFIED` の候補を `SUCCESS` として登録することはできない（`check` が不合格にする）。
