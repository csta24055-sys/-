## 2. 拾い方

Excel は開かず、ファイルの中の XML を直接読んだ（マクロも数式も実行しない）。表示シートだけでなく、非表示シート、入力規則、選択リスト、名前定義、フォーム部品、コメント、定数を対象にした。

1. **走査**：全シートの全セル（値・数式・書式）、入力規則、名前定義、結合、フォーム部品、コメントを読む。
2. **領域化**：セルを役割ごとの領域にまとめる。
   - 入力セル：セルの保護が外れているセル。入力シートでは、凡例が示す入力欄の色のセルも含む（簡易はピンク系、標準は水色系、詳細は緑系など）。値がなくても入力欄として数える。
   - 定数：保護されている数値。
   - 文字列の列：6 個以上つづく文字列（コード、品目名、単位など）。
   - 見出し・説明文：そのほかの文字列（シートごとに 1 行にまとめた）。
   - 数式：となり合う列で同じ範囲にあるものを 1 行にまとめ、式の型の数を添えた。
3. **台帳化**：領域 1 つを台帳の 1 行にする。入力シートの数量表は行区分（細目）ごとに、エネルギーや冷媒の表は行の見出しごとに分けた。データ表で同じ列に小さな領域が多いときは 1 行にまとめた。入力規則・名前定義・フォーム部品・コメント・参照切れは別の行として加えた。
4. **分類**：次の順に決める。入力規則の内容 → 見出し（列・行・左の見出し）→ 行区分 → シートの役割。どれにも当たらないものは「その他」か「不明」に置く。

## 3. 分類の考え方

- 受領した v0.1 の 5 大分類・小分類の ID はそのまま使った。小分類の下に詳細分類を 175 個置き（うち 139 個は v0.1 の項目名、36 個は今回の追加）、「結果表示・報告の設定」という小分類を 1 つ加えた。
- 全体共通の「要確認・未分類」を設け、不明・未分類／空欄・未入力／用途不明／参照不明・参照切れ／重複・統合候補に分けた。
- 各行の状態は「分類済み」「その他」「不明・未分類」「空欄等」のどれか 1 つ。値が 1 つもない入力欄だけの行は「空欄等」とし、見出しから分類できるものは分類 ID も付けた。
- 0・空欄・該当なし・不明は区別している。0 は値あり、空欄は「うち空欄」に数え、不明は状態で表す。
- 簡易・標準の GHG 版と CO2 版、簡易と標準のように、同じ位置に同じ内容がある行は「統合先（重複）」に元の行の ID を入れた。行は消していない。
- 資材や設備の個別コードは、分類の木には並べていない（v0.1 の取り決めどおり）。コード表やデータ表は表単位・列単位で分類した。

## 8. 調査できなかった範囲

1. VBA マクロ（詳細算定のブック）の中身。ボタン 3 個の動作も未確認。
2. チェックボックス 175 個のリンク先。部品の定義にリンク先セルがなく、どの値を切り替えるかは追えていない。
3. 数式から定数・入力セルへの参照の全件追跡。数式 3,818,483 セルの参照先を 1 つずつたどってはいない。シート単位で「どのシートが数式から参照されているか」は確かめた（簡易・標準では、文書と最終結果のシート以外は、数式か入力規則から参照されている。詳細算定のエネルギー統計値と、集計表の一部の参照表は、同じブックの数式から参照されていない。分類表には数式がない）。
4. 条件付き書式（294 組）の中身、グラフ、図形。
5. マニュアルの文字のないページ（15 ページ）と、図表の中の数値。
6. 簡易・標準・詳細で入力できる項目の差の、1 項目ごとの対応表。分類ごとにどのブックに現れるかは、完全分類ツリーの各節に記録した。
7. 詳細分類 175 個のうち 69 個には、台帳の行が 1 つも当たっていない（設備の品目、土工事・型枠など）。原版では個別コードや数式として現れ、今回の粒度では行を割り当てていない。一覧は `JCAT_input_classification_stats.json` の `details_without_rows`。
8. 書式だけがあって値のないセル（839,130 個）は、入力欄の印（保護解除・入力欄の色・入力規則）がないため対象外とした。

## 9. 実装時の注意

- 入力データ仕様の出発点は、完全分類ツリーの `input_entries`（表示されている入力シートの入力欄を行区分・見出しごとにまとめた 218 件）である。
- 必須・任意は、原版の凡例の色から判定した。任意の入力欄は地の色と同じで、保護も外れていないことがあるため、入力シートの保護された定数は「任意（既定値あり）」として扱った。
- 原版の標準値・係数・選択肢を新しいアプリへ持ち込まないこと。この台帳は「どこに何の種類の値があるか」を示すだけで、値は含まない。アプリの参照データは、許諾を確認した独立のデータで用意する。
- CO2 版の入力シートは非表示で、GHG 版の入力を数式で参照している。入力仕様は GHG 版を基準にすればよい。
- 分類は規則による。見出しの読み違いがありうるので、入力仕様にする前に `input_entries` を人の目で確かめること。
- アプリ（`12_APP_BASE`）は、この 5 大分類で入力文書を受け取れる。エンジンの入力項目と分類の対応は `binding_engine_model_v1.json` に置いた。

## 10. 再実行の方法

原版は各自が正規に入手したものを、Git の外のフォルダに置く。出力のうち `scan.sqlite3` には原版の値が入るので、リポジトリに入れない。

```bash
cd whole-life-carbon-jcat-study/13_INPUT_CLASSIFICATION/tools
W=<Git の外の作業フォルダ>
python3 -I unpack.py <ZIP> $W/originals            # 任意。読み取り専用で取り出す
python3 -I scan.py $W/originals $W/scan.sqlite3     # 走査
python3 -I regions.py $W/scan.sqlite3               # 領域化
python3 -I classify.py $W/scan.sqlite3 ../JCAT_入力分類ツリー_Claude引継ぎ.json   # 台帳化・分類・照合
python3 -I pdftext.py $W/originals/0_J-CAT_Manual_v2.3.pdf $W/manual.txt
python3 -I export.py $W/scan.sqlite3 ../JCAT_入力分類ツリー_Claude引継ぎ.json $W/manual.txt $W/out   # 成果物
```
