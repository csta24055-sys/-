# セキュリティ・個人情報・データの扱い

## いまの版の前提

- **1 台の端末で 1 人が使う、ローカル専用の試作。** 認証も利用者の区別も無い。だから外部に公開しない。
- サーバーはループバック（127.0.0.1／::1／localhost）以外では起動しない（`server.serve` が拒否）。

## 実装した防御（試験 `ServerTests` で確認）

| 対策 | 内容 |
|---|---|
| Host の確認 | `Host` が `127.0.0.1:<port>`・`localhost:<port>`・`[::1]:<port>` 以外なら 421（DNS リバインディング対策） |
| 書き込みの出所 | POST・PUT・DELETE に `Origin` があり別の出所なら 403。POST・PUT は `Content-Type: application/json` だけ（415） |
| 応答の見出し | CSP（スクリプトは同じ出所だけ、フレーム禁止）、X-Frame-Options DENY、nosniff、Referrer-Policy no-referrer、API は no-store |
| 静的ファイル | `web/` の外は出さない（パスの抜け出しは 404） |
| 大きさ | 本文は 40 MB まで |
| エラー | 内部エラーの詳細は端末のログだけ。応答には出さない |
| マクロ | マクロを含む Excel は読まない。数式は計算せず、保存された値だけを読む |
| 展開の上限 | Excel は宣言された大きさと実際に展開したバイト数の両方で部品 10 MB・合計 40 MB まで。XML は逐次の読み取り（iterparse）で、共有の文字列 30 万・セル 100 万・列は Excel の上限まで、読みながら確かめる。CSV は 10 MB・10 万行・100 万セルまで、壊れた CSV は 400。IFC の材料の参照は材料の型だけをたどり、参照ごとに結果を使い回し、ファイル全体の上限（50 万節点・試した数量の組 20 万）で止める |
| 接続 | 接続ごとにスレッドで読み、アプリの処理は 1 つの作業スレッドに渡す（遅い・止まった接続は自分のスレッドだけを止める）。接続の時間切れ 10 秒。不正・負の Content-Length は 400 |
| 削除 | プロジェクトの削除で、計算用に変換した入力・計算の記録とメモリの準備済みの計算も消す。SQLite は secure_delete で、消した部分を上書きする |

## 外部に送るもの

- 国土地理院：利用者が入れた住所の文字列（住所検索）と座標（逆ジオコーダ）。この 2 つの応答は端末のキャッシュに残さない。
- PLATEAU：その市区町村のタイルの URL（座標そのものは送らない。タイルの範囲の判定は端末で行う）。
- Zenodo・e-Stat：統計のファイルの取得だけ（建物の情報は送らない）。
- 送る見出しは一般的な `User-Agent: WLCStudio/0.1 (research prototype; +local)` だけ。メールアドレスなどは送らない。
- PLATEAU・統計のファイルの応答は `cache/` に保存する（Git には入れない。記録には問い合わせの文字列を書かない。起動時に、キャッシュの形の名前のファイルだけを対象に、400 日より古いものと、古い版が残した住所・座標の問い合わせを消し、記録に残った URL を消す）。`WLCSTUDIO_OFFLINE=1` で外部に一切出ない。

## 資料（図面・竣工図・BIM・数量表）

- 原本には個人情報や営業秘密が含まれうる。**既定では原本を保存しない**（SHA-256 と要約、候補だけ）。`--keep-uploads` のときだけ `var/uploads/` に権限 600 で保存し、プロジェクトの削除で消える。
- 公開の GitHub に入れない：`var/`、`cache/`、`*.sqlite3` は `.gitignore` にある。
- メーカーの BIM（例：パナソニック）は、同社の条件で「設計・設計検討の目的に限り、使用後は全て消去」。アプリは原本を残さず、製品のデータベースを作らない。製品の性能値（質量・冷媒量）は製造時の CO2 ではない。

## 外部に公開する前に要ること（未実装）

1. 認証と利用者・権限の管理（プロジェクトの持ち主、共有、管理者）。
2. 通信の暗号化（TLS）と、セッション・CSRF の対策（今の Origin の確認だけでは足りない）。
3. 利用者ごとのデータの分離と暗号化（保存時）、保存期間と削除の手続き、バックアップ。
4. 操作の記録（誰が・いつ・何を）と、記録に個人情報を書かない設計。
5. 外部 API の利用量の管理（PLATEAU・国土地理院は提供の保証が無い）と、止まったときの手入力への切り替え。
6. 依存するデータの利用条件の再確認（公開・商用利用の前に原文で）。
