# スキーマ（値・候補・プロジェクトの保存）

## 値（`wlcstudio/provenance.py` の `Value`）

| 項目 | 意味 |
|---|---|
| field_id | 入力欄の ID（`wlcstudio/fields.py`） |
| state | 7 つの状態：confirmed（取得・確認済み）／from_drawing（図面から計算）／statistical（統計推定）／assumption（仮定）／not_obtained（未取得）／not_applicable（適用外）／not_computable（計算不能） |
| value, unit | 値と単位（値のある状態だけが値を持つ。値の無い状態は値を持てない＝0 にできない） |
| method | 取り方（手入力、PLATEAU の属性、数量表の合計、RASMI × 延床面積 …） |
| source_id, source_detail | 出典の ID（`sources/registry.json` か資料の ID）と、その中の場所（シート・行・列、IFC の部材、ページ・行、建物 ID、表の行） |
| retrieved_at, factor_version, permission | 取得日、使ったデータ・原単位の版、利用許諾（例：CC-BY-4.0、政府標準利用規約2.0） |
| uncertainty | kind（none／interval／scenario／unknown＝根拠のある幅を付けられない推定）、low、high、level（信頼水準）、calibrated（独立のデータで当たり率を測ったか）、basis（範囲の作り方） |
| note, scope, depends, updated_at, updated_by | 説明、推定が欄の名前より広い範囲を含むこと（whole_building＝基礎を含む建物全体、all_steel＝鉄筋と鉄骨の全量。二重計上の防止に使う）、推定の前提（延床面積・構造・用途の区分。変わると結果に「概算し直す」）、保存の時刻、保存した人（候補を採用したときは「user（候補を採用: 出所）」） |

検査（`Value.check`）：値のある状態には値と取り方が要る；値の無い状態は値を持てない；統計推定には区間と出典が要る；図面からの計算には出典（資料）が要る；範囲は有限で下限 ≤ 上限。

## 入力欄（`wlcstudio/fields.py`）

4 画面に 75 項目（基本情報 19・材料 23・設備 20・運用 13）。各項目は、画面・グループ・5 大分類（building／construction／equipment／operation／assessment）・型・単位（受け付ける別の単位）・届くエンジンの入力・橋渡しでの使い方・必須か・「適用外」の意味（zero／absent／skip）・概算できるか・許す範囲・個人情報か、を持つ。既定値は持たない（係数を作らない）。

## プロジェクトの保存（`var/projects.sqlite3`、`wlcstudio/project.py`）

| 表 | 中身 |
|---|---|
| projects | id、名前、構造、data_kind（user／fictional_demo）、作成・更新時刻（作成時刻は画面へも送り、画面は id と作成時刻でプロジェクトを見分ける：削除したプロジェクトの id は再利用されることがある）、既存アプリのプロジェクト id、最後の評価期間、位置（座標・PLATEAU の建物 id） |
| field_values | 値の履歴（追記だけ。今の値は最後に保存したもの） |
| candidates | 候補（自動調査・資料・概算）。採用するまで計算に使わない。状態 open／accepted／dismissed。資料の候補は根拠（`rows`・`n_rows`・`excluded`・`n_excluded`・`n_maybe`）も持つ（採用した値には入らない） |
| later_flags | 「あとで確認」 |
| documents | 読み込んだ資料の名前・形式・SHA-256・大きさ・要約。原本は `--keep-uploads` のときだけ `var/uploads/`（権限 600） |
| research_log | 自動調査・概算の記録（出典 ID・件数。住所の文字列は残さない） |
| runs | 計算の結果の表示用の記録（入力の指紋・評価期間・状態） |

プロジェクトを削除すると、上の全部の行と保存した原本が消え、既存アプリの保存（`var/engine.sqlite3`）の変換した入力の版・条件・計算の記録と、メモリの準備済みの計算も消える（先に計算側を消すので、失敗してもやり直せる）。両方の保存は `secure_delete` で、消した部分を上書きする。

## エンジンへの文書（lca-input/1、`wlcstudio/bridge.py`）

既存アプリの入力形式そのもの（`12_APP_BASE/README.md`）。カテゴリーは 5 大分類、項目の ID はエンジンのモデルの名前。材料・設備・冷媒は表の行（`materials`・`equipment`・`refrigerants`）、燃料は `construction.fuels`、状態は `<所有者>.states` と `provenance` の表。参照セット（原単位）は `reference_set` で指定する。

## 計算の報告（`bridge.build` の report）

- `missing_inputs`：評価範囲の中で決まらない入力。各要素は field（入力欄、または入力欄の無い分の ID：解体工事・現場の廃棄物・代わりの配送原単位など）、label、stages、reason、`gap`、`screen_field`（画面の入力欄か）。
  - `gap = "omitted"`：合計に入っていない（その段階は不完全、合計は下限）。`omitted_inputs` に同じものを並べる。
  - `gap = "assumed"`：合計には入っているが、入力の代わりに仮定で計算した（例：運搬距離・手段の代わりに参照セットの数量あたりの配送原単位、更新周期が未取得のときの B3＝多めになりうる）。`assumed_stages` に段階を並べ、画面は「一部は仮定」と出す。下限にはしない。
  - `gap = "split"`：合計は正しいが、段階の間の内訳が決まらない（施設管理の割合が未取得：B2 の分は B6 に入っている）。`split_stages`、画面は「内訳が未定」。下限にはしない。
- `inconsistent_inputs`：互いに矛盾する入力（例：売電が自家発電より多い）。計算は止めず、画面に「入力の矛盾」として出す。
- `incomplete_stages`：入っていない分のある段階。`expand`：依存する段階へ広げる条件（b5、b4_material、b4_equipment、b4_equipment_gap＝交換が評価期間の中に来る設備に欠けがあるか、b1_replacement、b2_moot＝購入電力か運用の電力の排出係数が確かに 0、dist0・haul0＝運搬距離・解体材の運搬距離が確かに 0、mrep0・erep0＝材料・設備の修繕率が確かに 0、route_stages）。dist0・haul0・mrep0・erep0 は行の種類（材料・設備）ごとに A4・C2・B3 を「効かない」段階にし、欠けた入力の記録とエンジンの印の両方からその段階を外す。
- 電力：画面の「購入電力」は請求書の量（自家消費を含まない）。B6・B2 を決めるのは購入電力だけ。発電・売電が分かっていて矛盾しなければ、エンジンへは使用量＝購入電力＋max(0, 自家発電 − 売電) を導出の値として渡し、エンジンが買電量＝max(0, 使用量 − (発電 − 売電)) に戻す。発電・売電が分からない・矛盾するときは、使用量＝購入電力、発電・売電＝0（効かないので満たした値）として渡す。購入電力が未取得なら、それが欠けた入力（発電・売電は欠けた入力にしない）。ただし運用の電力の排出係数が確かに 0 なら、購入電力・発電・売電はどれも効かないので 0 で満たす。
- 数の読み方（`wlcstudio/numbers.py`、画面・サーバー・CSV・Excel・PDF で同じ）：全角は半角に、カンマは 3 桁の区切りだけ、数の中の空白は拒否、有限の数だけ。
- 「確かに 0」（`_surely_zero`）：適用外（0 の意味の項目）か、値 0 で範囲が 0 より上に及ばないもの。量や係数が確かに 0 なら、それに掛かる入力は効かないとして問わない（行を作らない・0 で満たす）。範囲が 0 より上に及ぶ 0 は「確かに 0」としない。
- 資料の読み込みの分類：名前（と規格）の**頭**で材料を決める。最初の区切り（括弧・読点・英語の前置詞）までのうち材料を名指す部分で、最後に来る材料の語（同じ位置で終わるなら長い語）。エポキシ樹脂塗装鉄筋は鉄筋、FRP防水は防水、ワイヤーメッシュ入りコンクリートはコンクリート、Supply and installation of plasterboard はボード、Reinforcement steel・High yield bars・主筋・帯筋は鉄筋。ただし次は頭にしない：ほかの材料の後の形の語（グラスウールボード・Insulation board は断熱材）、製品の前の「断熱」（アルミ断熱サッシはアルミ、断熱サッシはどの欄でもない）、下・上・裏・面が続く材料（砂利地業（土間コンクリート下）はどの欄でもない。鉄骨下地・鉄骨上屋・鉄筋上端筋はその材料）、どの欄でもない製品の前の「用」（鉄筋用スペーサー・コンクリート用混和剤・鉄骨用錆止め塗料はどの欄でもない。防水用シート・防水用塗膜は防水）、場所・用途の前置詞（under・beneath・between・for・to など）の後の部分（Hardcore under concrete slab、Sand for mortar はどの欄でもない）、どの欄でもない製品の後の in（Waterstop in concrete・Dowel bars in concrete はどの欄でもない。Foundations in concrete・Walls in brickwork はその材料）。場所だけの部分は飛ばして次の部分を見る。英語の block・blockwork はブロック類（Concrete blockwork もブロック類）、mesh・fabric reinforcement は鉄筋（mesh fence などは除く）。見るのは最初の 8 部分まで。
- 資料の読み込みで足さない行：合計・小計（括弧・句読点で区切った語が「計」で終わる。名前か規格）、再掲・内数（うち・内・内訳・別掲・上記に含む・(再)・included above など。字間が空いていても。名前・規格・区分のどれか）、控除（控除・差引・発生材・deduct・credit。発生材処分別途は値段の注記で控除ではない）、撤去・解体・処分（撤去・解体・はつり・殻・処分・demolition・removal・disposal・break out。名前か材料の部分にあれば撤去の行。材料の後の部分・規格だけにあれば「足すべきかもしれない」。端材処分共・殻処分費別途・別途処分・including disposal of surplus・disposal of offcuts by others は値段の注記で、材料の行）、見出し（数量も単位も無い行：コンクリート工事・鉄筋工事。材料の行の一覧には入れない）、作業の行（加工・組立・運搬・搬入・荷揚げ・打設・圧送・建方・手間など労務の語は名前でも規格でも。溶接・圧接・敷込・取付・試験・金ごて・打放しなど据え方の語は**名前にあるときだけ**（規格の「床下敷込」「溶接止め」「金ごて仕上」「打放し」「試験杭」は材料の行）。英語は材料より前の作業の語（Place concrete・Hoisting steelwork）と、材料より後の作業の名詞（Rebar fixing・Steel erection・Concrete pumping・Placing of concrete）。材料の後の過去分詞（poured against earth・cut, bent and fixed・laid in slabs・fabricated and erected・delivered to site）は材料の行。材工共・supply・including、作業の語の並び（処分・残材処分を含む）の後の共・込・とも（加工組立共・製作・運搬・建方・残材処分共・金ごて押え共・運搬費込）、別途・費別・excluding・by others の作業は材料の行。材料の前の作業の語・-ed の形容（加工鉄筋・Fabricated steelwork・Welded mesh）も材料の行）、負の数量、数量のセルの数式が**ほかの材料の行の数量**にたどり着くもの、参照先を確かめられない数式、非表示のシート・行・列の値。どれも理由つきで「使わなかった行」に出す（画面には 200 行まで全部）。
- 写しの判定：数量のセルの数式を、数式・名前（シートの名前を先に、なければブックの名前）・表（テーブル）の参照・別のシート・非表示のシート・行・列の数式・配列数式（スピル）の範囲までたどる。ほかの材料の行（欄の単位で数量のある行、またはそのシートの合計・再掲・作業・控除・撤去の行）の数量の列（数量・所要数量・体積・重量 など。単位質量・比重・率は除く）、またはその行の数量に**足し込まれる**セル（ROUND(F2)・SUM(B2:D2) の F2・B2〜D2）に届けば写し。その行のほかの数（階別の列 1F・2F・3F など）も、数量の式が**足し上げて**届くなら写し（集計!1F = 明細!C2、SUMPRODUCT、[@1F] などの表の参照）。ただし列の見出しが金額・係数（単価・金額・単位質量・比重・密度・係数・率・kg/m など）の列は除く。掛け合わせる・引くだけの数（長さ×単位質量の単位質量、表の横の早見表、比重）や、自分の行のほかの列は写しではない。名前の相対参照（明細!$C1・明細!A1）は、使ったセルから決める（Excel は A1 からの相対で持つ。LibreOffice で確かめた）。LET の値・LAMBDA の引数に書いた名前もたどる。確かめられないもの（INDIRECT・OFFSET、端が数式の範囲、シートの端を越える参照、定義の無い名前・表、自分自身にたどり着く名前、データテーブル、3D 参照、別のブック、元の無い共有の数式、循環する参照、途中から読んでいない非表示のシート、1 つの資料で 100 万歩を超えるたどり（名前が展開したセルも数える））は足さない。
- 単位の次元：同じ欄に m3 の行と t の行のように次元の違う行があれば、行の多い次元を候補にし、ほかは理由つきで足さない。同じ数なら、どちらが欄の量か決められないので候補を作らない。
- 候補の根拠：資料から作った候補は、足した行（名前・場所・数量）と、同じ材料を名指すのに足さなかった行（名前・場所・理由）を持つ（`rows`・`excluded`、それぞれ 200 行まで、数は `n_rows`・`n_excluded`）。足さなかった行には、あれば数量と単位（`quantity`・`unit`）と「足すべきかもしれないか」（`maybe`）を付ける。足さなかった理由が合計・再掲・控除・撤去・負の数量・見出しでないもの（作業・写し・確かめられない数式・単位・数値でない数量・材料の後の撤去の語）の数を `n_maybe` に持ち、画面は「足すべき行かもしれない。この候補は少なめのことがある」と出す。候補の注記も「足さなかった行 N 行。うち M 行は足すべき行かもしれない」と、一覧と同じ数を言う。どの行も足さなかったので候補ができなかった材料も、足すべきかもしれない行の数を読み込みの要約に出す（`left_out`）。採用した値には根拠の一覧は入らない（値の出所は source_detail に残る）。
- 入力の効く段階（`bridge.FIELD_REACH`。エンジンで 1 項目ずつ動かして測った上位集合）：評価範囲の段階のどれにも効かない入力は、渡しても「反映されない（効かない）」とし、推定の数・範囲の不明・範囲のある項目に数えない。設備は部分ごと：台数は A1-A3・B3・B4・B5・C3、耐用年数は B3・B4、1 台の質量は B4・B5・C3（設備の配送・施工の原単位は更新 B4 の中だけで効き、A4・A5 には効かない）。相方が確かに 0 か、相方が未取得で効かない値も同じ：割合 0 か割合が未取得の改修周期、周期が評価期間より長いか周期が未取得の改修の割合、B5 が 0 か計算できないとき（周期が評価期間より長い・割合が 0・周期か割合が未取得）の改修・建替えの想定（「想定しない」・適用外を含む）、損失 0 の冷媒の交換周期、交換の無い損失率、充填量・GWP・漏えい率のどれかが無いときの冷媒の入力すべて、漏えい 0 の補充の有無、漏えい 0 で交換の損失も回収の分も効かないときの充填量・GWP、購入電力が未取得の運用時の電力の排出係数、工事中の電力が未取得の工事中の係数、解体時の質量の分かる材料の行が無いときの解体材の運搬距離と処理シナリオ、廃棄率 0 の数量の基準、発注・竣工数量で質量の行か解体の段階が無いときの廃棄率の値（0・適用外を含む。この 2 つは別々の規則として両方当てる）、廃棄率が未取得のときの修繕率と、どの段階も計算できない材料の行の数量。B1 を確かに 0 にする理由（充填量 0、GWP 0、漏えい 0・損失 0（または交換なし）・回収率 100%）が 2 つ以上重なるときは、どの値も 1 つだけでは合計を変えないので、どれも数えない。材料の行ごとに、その数量が変えうる段階（廃棄率があれば A1-A3、トンキロか配送原単位で A4、施工後の質量があれば C2〜C4、それをくり返す B3・B4・B5）を求め、評価範囲の段階に効く行が 1 つも無ければ、共通の更新周期・修繕率・解体材の運搬距離・処理シナリオは効かない。数量の基準は、どの基準でも効く行が無いときだけ効かない。運搬距離 0 km は、0 以外の距離でも A4 を計算できる行が無ければ効かない。配送原単位（数量あたり）で運ぶ行だけのとき、距離の値は使わないが 0 km なら A4 は 0 なので、0 になりうる距離（範囲が無いか、範囲が 0 に及ぶ）は反映、範囲が 0 を含まなければ反映しない。更新周期が未取得の「修繕 B3 への影響」は、修繕を計算する行があるときだけ記録する。必須の係数でも、掛かる量が未取得なら効かないので 0 で満たして計算する（運用時の電力の排出係数は購入電力が未取得のとき、工事中の係数は工事中の電力が未取得のとき）。量と係数の両方を欠けた入力とし、その段階は不完全、合計は下限。解体後の処理シナリオも、解体時の質量が分かる材料の行が無ければ仮の処理で満たし、C3・C4 の欠けた入力とする。周期・寿命が評価期間より長いかどうかは、その入力の範囲の下端で決める（範囲が評価期間より短い側へ及べば相方は効くとし、範囲の計算でも動かし、欠けは不完全にする）。範囲の下端まで評価期間以上の寿命・周期そのものも、範囲のどの値でも合計を変えないので反映されないとし、範囲で動かさず数えない（範囲の無い値は数える）。どの項目も、反映の表にちょうど 1 行ある（材料の行が無いときの処理シナリオも理由つきで出す）。交換周期の適用外（交換しない）は「評価期間内に交換なし」。漏えい 0・損失 0（または評価期間内に交換なし）・回収率 100% なら B1 は確かに 0 で、冷媒の行を作らない。
- 合計を変えない入力（`bridge.TOTAL_NEUTRAL`）：施設管理の割合、購入電力が分かっているときの発電・売電、延床面積・階数・高さ・建築面積・竣工年、再使用材の割合、主な用途・構造・新築既存・基礎の形式・運用データの種類（エンジンへは渡すが合計を読む単位が無い。どの選択肢でも合計は同じと測った）。反映の表には渡したと出し、推定の数・範囲には数えない。
- 運搬（A4）：発注・竣工数量の質量の分かる行は発注量＝数量なので、運搬距離・手段がそろえばトンキロで決まる。距離・手段が未取得なら、それが A4 の欠けた入力（両方なら両方）で、手がかりに「廃棄率だけを入れると数量あたりの配送原単位で計算する（仮定）」も書く。設計数量では発注量 Q/(1−w) に廃棄率が要るので、廃棄率が A4 の欠けた入力。
- 合計の範囲：範囲のある値を、合計を小さくする端・大きくする端にそろえて 2 回計算する。寿命・周期・回収率と、数量の基準が設計数量でないとき（未取得を含む）の廃棄率（`bridge.decreasing`：エンジンは設計数量なら発注量 Q/(1−w)、それ以外なら施工後の質量 Q(1−w) に廃棄率を使う）は大きいほど合計が小さい。どの値を端へ動かすかは、相方の判定を範囲の端で行った反映による。範囲は必ず今の合計を含む（含まなければ広げて、そう書く）。
- 結果の古さ（GET /result）と台帳（GET /ledger）は、最後の計算（必須の入力が足りずに断ったものも含む）の評価期間で文書を作り直して比べる（文書は評価期間で変わる：期間内に交換が来るか）。入力の指紋には各項目の範囲も含める（範囲だけを変えても古いと出る。この版より前に保存した結果は、一度だけ古いと出る）。
