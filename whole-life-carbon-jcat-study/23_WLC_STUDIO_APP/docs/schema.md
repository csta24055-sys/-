# スキーマ（値・候補・プロジェクトの保存）

## 値（`wlcstudio/provenance.py` の `Value`）

| 項目 | 意味 |
|---|---|
| field_id | 入力欄の ID（`wlcstudio/fields.py`） |
| state | 7 つの状態：confirmed（取得・確認済み）／from_drawing（図面から計算）／statistical（統計推定）／assumption（仮定）／not_obtained（未取得）／not_applicable（適用外）／not_computable（計算不能） |
| value, unit | 値と単位（値のある状態だけが値を持つ。値の無い状態は値を持てない＝0 にできない） |
| method | 取り方（手入力、PLATEAU の属性、数量表の合計、RASMI × 延床面積 …） |
| source_id, source_detail | 出典の ID（`sources/registry.json` か資料の ID）と、その中の場所（シート・行・列、IFC の部材、ページ・行、建物 ID、表の行） |
| retrieved_at, factor_version, permission | 取得日、使ったデータ・原単位の版、利用許諾（例：CC-BY-4.0、政府標準利用規約2.0） |
| uncertainty | kind（none／interval／scenario／unknown＝根拠のある幅を付けられない推定）、low、high、level（信頼水準）、calibrated（独立のデータで当たり率を測ったか）、basis（範囲の作り方） |
| note, scope, depends, updated_at, updated_by | 説明、推定が欄の名前より広い範囲を含むこと（whole_building＝基礎を含む建物全体、all_steel＝鉄筋と鉄骨の全量。二重計上の防止に使う。全体の値が確かに 0（範囲が 0 より上に及ばない 0）なら何も含まないので、もう一方の欄の値を落とさず、もう一方の未取得も覆わない（欠けた入力のまま）。もう一方に「確かに 0」でない値（0 でない値か、範囲が 0 より上に及ぶ 0）があれば入力の矛盾として言う（14 回目））、推定の前提（延床面積・構造・用途の区分。変わると結果に「概算し直す」）、保存の時刻、保存した人（候補を採用したときは「user（候補を採用: 出所）」） |

検査（`Value.check`）：値のある状態には値と取り方が要る；値の無い状態は値を持てない；統計推定には区間と出典が要る；図面からの計算には出典（資料）が要る；範囲は有限で下限 ≤ 上限。

## 入力欄（`wlcstudio/fields.py`）

4 画面に 75 項目（基本情報 19・材料 23・設備 20・運用 13）。各項目は、画面・グループ・5 大分類（building／construction／equipment／operation／assessment）・型・単位（受け付ける別の単位）・届くエンジンの入力・橋渡しでの使い方・必須か・「適用外」の意味（zero／absent／skip）・概算できるか・許す範囲・個人情報か、を持つ。既定値は持たない（係数を作らない）。「適用外」にできない項目は `na_never`（保存で断る）。`na_context` の項目（運用時・工事中の電力の排出係数、解体後の処理シナリオ）は、値が効かないところでだけ「適用外」にできる。保存のとき、その適用外を入れた値で橋渡しを作り、計算が断るなら（報告の `na_refused`）理由つきで 400 にする。値が効かないところ（購入電力が 0、工事中の電力が 0・適用外、材料の行や解体後の段階が無いなど）では受けて 0 で満たす。評価範囲が未取得の間は、計算がその適用外を断るかが決まらない（計算は評価範囲が無いので止まる）ので、保存は受け、計算の理由は「適用外にはできない」と言わずに条件を書く：運用時の係数と、解体時の質量が分かる材料の行がある処理シナリオは「評価範囲が未取得なので、この適用外が使えるかは評価範囲で決まる（…）」、工事中の係数は画面のどの評価範囲にも A5 があるので「この適用外はまだ判定していない（工事中の電力があるので、評価範囲を入れると A5 の電力の分に係数が要る。A5 はどの評価範囲にもあるので、工事中の電力が 0・適用外・未取得のときだけ適用外にできる）」、質量の分かる行の無い処理シナリオは「まだ判定していない（いまは…評価範囲を入れても適用外のまま計算できる。…）」。計算に必須で足りない入力（`missing_required`）に挙げるのは、画面のどの評価範囲でも計算が断る適用外だけ（`bridge._open_without`）：処理シナリオ（建設時までなら使える）と運用時の係数（B6・B2 の無い評価範囲なら使える）は挙げず、結果の画面は「適用外にした必須の入力」に条件の文と出す。工事中の係数は、工事中の電力が 0・適用外・未取得でなければ（どの評価範囲でも断るので）挙げる。未取得は今までどおり挙げる。評価範囲を入れて使えなくなれば、その保存の `warnings` が言う。3 項目の説明文もそう言う（14 回目）。

## エンジンへの文書（lca-input/1、`wlcstudio/bridge.py`）

既存アプリの入力形式そのもの（`12_APP_BASE/README.md`）。カテゴリーは 5 大分類、項目の ID はエンジンのモデルの名前。材料・設備・冷媒は表の行（`materials`・`equipment`・`refrigerants`）、燃料は `construction.fuels`、状態は `<所有者>.states` と `provenance` の表。参照セット（原単位）は `reference_set` で指定する。

## 計算の報告（`bridge.build` の report）

- `missing_inputs`：評価範囲の中で決まらない入力。各要素は field（入力欄、または入力欄の無い分の ID：解体工事・現場の廃棄物・代わりの配送原単位など）、label、stages、reason、`gap`、`screen_field`（画面の入力欄か）。数量の基準・廃棄率・解体材の運搬距離の欠けた入力に C2〜C4（とそれをくり返す B4・B5）を付けるのは、質量の単位（t・kg）の材料の行があるときだけ（m3・m2 の行だけでは、これらを入れても C2〜C4 は計算できない。解体材の運搬距離は、C2 が付かなければ欠けた入力にしない）。
  - `gap = "omitted"`：合計に入っていない（その段階は不完全、合計は下限）。`omitted_inputs` に同じものを並べる。
  - `gap = "assumed"`：合計には入っているが、入力の代わりに仮定で計算した（例：運搬距離・手段の代わりに参照セットの数量あたりの配送原単位、更新周期が未取得のときの B3＝多めになりうる）。`assumed_stages` に段階を並べ、画面は「一部は仮定」と出す。下限にはしない。
  - `gap = "split"`：合計は正しいが、段階の間の内訳が決まらない（施設管理の割合が未取得：B2 の分は B6 に入っている）。`split_stages`、画面は「内訳が未定」。下限にはしない。
- `inconsistent_inputs`：互いに矛盾する入力（例：売電が自家発電より多い）。計算は止めず、画面に「入力の矛盾」として出す。
- `na_refused`：項目 → 今の入力ではその「適用外」を使えない理由（保存のときの判定に使う。画面の 400 の説明と計算の理由は同じ言葉）。
- 値を保存する応答（PUT と、候補の採用 `POST …/fields/<項目>/accept`）の `warnings`（そのまま見せる文の一覧）：前に受けた別の項目の「適用外」（`na_context` の 3 項目）が、**この保存で**使えなくなったとき（保存の前は計算が受け、後は断る。計算は止まる）だけ付く。前から使えない適用外は、使えなくした保存と計算が言っているので、関係の無い保存ではくり返さない。保存そのものは受ける。警告が無ければキーも無い。`warning_fields` は、各文がどの項目の「適用外」のことかを、`warnings` と同じ順に並べた項目 ID の一覧で、`warnings` があるときだけ付く（15 回目）。判定は、別の項目に適用外が保存されているときだけ値の一覧を 1 回読み、保存の前と後の値で橋渡しを作って `na_refused` を比べる（保存された適用外が無ければ橋渡しを作らない）。値を保存するサーバーの道は PUT（未取得に戻す・適用外・計算不能も同じ PUT）と採用だけ（13 回目。14 回目に採用にも付け、使えなくした保存だけにした）。画面は一度届けば伝わるように出す：警告を含む通知は「閉じる」（または通知の中で Esc）まで消えず、それを送った操作のプロジェクトのものとして、ほかのプロジェクトやプロジェクトの無い画面では「<プロジェクト名>」：を付けて読む（14 回目）。その項目に、あとで適用外でない状態（値・未取得・計算不能・候補の採用）を保存した答えが来れば、画面はその警告を取り下げる：同じ「保存して戻る」のあとの行がその項目に値を保存したときと、「保存して戻る」の最後の読み直しでその項目が適用外でないときは言わず、通知に残っている警告もその答えで消す。取り下げるのは、その答えの `updated_at`（サーバーがその書き込みを保存した時刻。書き込みは 1 つの作業で順に保存する）が、警告を言った答えの `updated_at` より前でないときだけ（同じ項目の前の保存の答えが遅れて来ても、その後に保存された適用外についての警告は残す）。見るのは警告の項目自身の状態だけで、ほかの入力で使えるようになった適用外の警告は言う（次の計算が本当のことを言う）（15 回目）。「保存して戻る」が保存していない行を名指す知らせ（止めた知らせ、戻らない知らせ）と、通知に収まらない文も「閉じる」まで残り、中で送れる（役割は警告だけが alert、ほかは status）。止めた知らせは「…は保存していません」を先に言う。一度収まらなかった文は、収まる画面に移っても「閉じる」まで残る。保存していない行を名指す知らせは、それより前の操作の遅い答え（「…を作りました」、概算の件数など）に置き換えられず、その答えは知らせの後ろに足す。別のプロジェクトの画面でも、警告と一緒に言ったその知らせは名前を付けて残す。残る通知は画面が変わっても読み上げ直さない（文字は変わるところ、プロジェクト名だけを書く）。候補の採用が断られた・失敗したときは、その行に打った値を消さない（行は操作で決まったことにならず、「保存して戻る」が保存するか、止めた知らせが「保存していません」と名指す）（15 回目）。
- `incomplete_stages`：入っていない分のある段階。`expand`：依存する段階へ広げる条件（b5、b4_material、b4_equipment、b4_equipment_gap＝交換が評価期間の中に来る設備に欠けがあるか、b1_replacement、b2_moot＝購入電力か運用の電力の排出係数が確かに 0、dist0・haul0＝運搬距離・解体材の運搬距離が確かに 0、mrep0・erep0＝材料・設備の修繕率が確かに 0、route_stages）。dist0・haul0・mrep0・erep0 は行の種類（材料・設備）ごとに A4・C2・B3 を「効かない」段階にし、欠けた入力の記録とエンジンの印の両方からその段階を外す。
- 電力：画面の「購入電力」は請求書の量（自家消費を含まない）。B6・B2 を決めるのは購入電力だけ。発電・売電が分かっていて矛盾しなければ、エンジンへは使用量＝購入電力＋max(0, 自家発電 − 売電) を導出の値として渡し、エンジンが買電量＝max(0, 使用量 − (発電 − 売電)) に戻す。発電・売電が分からない・矛盾するときは、使用量＝購入電力、発電・売電＝0（効かないので満たした値）として渡す。購入電力が未取得なら、それが欠けた入力（発電・売電は欠けた入力にしない）。ただし運用の電力の排出係数が確かに 0 なら、購入電力・発電・売電はどれも効かないので 0 で満たす。
- 数の読み方（`wlcstudio/numbers.py`、画面・サーバー・CSV・Excel・PDF で同じ）：全角は半角に、カンマは 3 桁の区切りだけ、数の中の空白は拒否、有限の数だけ。
- 「確かに 0」（`_surely_zero`）：適用外（0 の意味の項目）か、値 0 で範囲が 0 より上に及ばないもの。量や係数が確かに 0 なら、それに掛かる入力は効かないとして問わない（行を作らない・0 で満たす）。範囲が 0 より上に及ぶ 0 は「確かに 0」としない。運搬距離は、値が 0 なら範囲が 0 より上に及んでも A4 を 0 にする（範囲の上端は範囲の計算が別に計算する）。手段・質量の相方は「確かに 0」で判定する。ただし範囲の上端でもトンキロで運べる行（発注量の質量が分かる行）が無ければ、手段は効かない。
- 資料の読み込みの分類：名前（と規格）の**頭**で材料を決める。規格の列は見出しが規格・仕様・摘要・寸法・形状（形状・寸法、品質・規格）・spec・grade の列（内訳書の 名称・摘要・数量・単位・単価・金額・備考 - 運搬（A4）：発注・竣工数量の質量の分かる行は発注量＝数量なので、運搬距離・手段がそろえばトンキロで決まる。距離・手段が未取得なら、それが A4 の欠けた入力（両方なら両方）で、手がかりに「廃棄率だけを入れると数量あたりの配送原単位で計算する（仮定）」も書く。設計数量では発注量 Q/(1−w) に廃棄率が要るので、廃棄率が A4 の欠けた入力。
- 合計の範囲：範囲のある値を、合計を小さくする端・大きくする端にそろえて 2 回計算する。寿命・周期・回収率と、数量の基準が設計数量でないとき（未取得を含む）の廃棄率（`bridge.decreasing`：エンジンは設計数量なら発注量 Q/(1−w)、それ以外なら施工後の質量 Q(1−w) に廃棄率を使う）は大きいほど合計が小さい。どの値を端へ動かすかは、相方の判定を範囲の端で行った反映による。範囲は必ず今の合計を含む（含まなければ広げて、そう書く）。範囲が不明の項目に数えるのは統計推定と仮定だけ（要約の推定の数と同じ集まり）。推定を手で直して取得・確認済みにした値は、範囲が不明の記録を持っていても数えない。
- 範囲の端だけに現れる欠け（`end_gaps`。13 回目）：合計に入らないもの、仮定で計算したもの、段階の内訳が決まらないもののうち、基の計算に無いものは、端を名指して範囲の注記に言う。距離の値が 0 で範囲が 0 より上に及び、発注量の質量が分かる行があって手段が未取得なら、上端では手段も名指す（画面からは距離に範囲を付けられないので、今は潜在）。
- 結果の古さ（GET /result）と台帳（GET /ledger）は、最後の計算（必須の入力が足りずに断ったものも含む）の評価期間で文書を作り直して比べる（文書は評価期間で変わる：期間内に交換が来るか）。入力の指紋には各項目の範囲も含める（範囲だけを変えても古いと出る。この版より前に保存した結果は、一度だけ古いと出る）。入力の指紋は、記録のみの項目（建物名・所在地・ボーリングのメモ）の値を含まない（状態は含む）。それを直しても、結果は古いと出ない。計算していなければ GET /result は {} を返す。画面は、保存した結果の読み込みそのものの失敗（つながらない・500 など）を、結果の画面に「前の結果を読めませんでした：<理由>」と出す（つながらないときの理由は日本語の案内。その間に「計算する」を押していれば、計算の結果か理由が出るので言わない）（15 回目：何も出さず、計算していないように見えた）。
