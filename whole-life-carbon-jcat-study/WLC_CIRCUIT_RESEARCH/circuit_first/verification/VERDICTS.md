## Black-box audit of hidden computation (task 4)
* No reference/oracle code, no cycle-1 code, no numerical library in engine/adapter/model (import graph in `audit_static.json`).
* Adapter arithmetic is only W1 (primitive × building-independent constant). No event time, count, year, amplitude×count or
  year loop is computed in Python; the probe type logged zero arithmetic/comparison/conversion on raw scenario numbers.
  `.value` is read only inside `Tracked`, `w2_key`, `w3_*` and `Builder.val` (which counts a data element).
* Element values equal inputs × constants (packet C = amount, clock C = period, flow G = rate, explicit-reference source
  = given year); none equals an expected result. ρ and V_hi are convention/domain constants, not data.
* `model.py` reads capacitor states for the readout (allowed readout: γ·Σ C·u) and reads event/boolean logs only to
  *report* event times and years; nothing is fed back into the circuit.
* Data values do not pass through boolean logic: comparators compare analog ramps with V_th or with a DC reference; only
  booleans enter gates/latches/sequencers. The 8-bit year counter is not read by any data path in stage A.
* Engine: nothing WLC-specific in substance (generic MNA, impulsive re-initialisation, comparators, latches, counters,
  sequencers, priority classes). The priority-class scheduler and zero-length sequencer phases are, however, **free
  control in the simulator** that a physical realisation would need as arbiter/delay logic; they are not counted anywhere.
* Is `h` fair? It measures only adapter arithmetic; with W_out = 0 it is 0 whatever W_in is. It does not measure the
  control complexity moved into sequencer programs, priority classes and W2 wiring decisions. h = 0 is true but
  flatters the design as a summary of "nothing hidden"; report the control census next to it (below).
