## 2. 判断（a）〜（e）

**(a) D-9（オンラインリセットでの最小状態数）— まず1状態の構成を試み、その後に査読する。**
理由：D-9 は Gate 3 が PARTIAL である主因で、費用は小さい。査読より先に構成を試すのは、仮定の範囲を狭めそうな安い構成が少なくとも2つあるからである（再計画者の見立て、[H]）。
1. リセット時刻が格子（例：月単位）に限られるなら、時刻のずれを整数の計数器に保持できる。連続状態は1つで足りる可能性がある。
2. 時刻 t を外から無償で使える信号とみなすなら、リセット時刻を保持する実数1つで足りる可能性がある。D-9 の「2以上」は、時刻基準も状態に数える自律系を暗黙に仮定している。
3. 証明草稿は「有界時間内の内部事象は有限個」から「(s,t) の開集合で内部事象なし」を導いている。この一歩には、ガードが閉集合である、事象時刻が s に連続に依存する、といった追加の正則性が要る疑いがある。
どれも D-9 を反証するものではなく、成立範囲を確定するものである。構成が全て失敗した場合と、範囲を書き直した後の言明について、非著者が書面で査読する（EXP-2）。

**(b) C の MAPPING 行に基づく DIRECT 21 の単位別回路模擬 — 新しい模擬器は作らない。帳簿の照合だけ行う。**
理由：21 単位の値は、B の構成を使った統合と D の再検証で既に一致している（1,926 比較、標本外 EV0/EV7）。性能は否定的なので、同じ値をもう一度別の模擬器で出しても情報は増えない。未確認なのは C の表の「分類」と「4つ組」だけである。これは、統合が既に組んでいるネットリストの素子数を数えて表と突き合わせれば判定できる（EXP-4 の 4b）。

**(c) K26/K28/K30/K32/K33 — 3つは実行、1つは実行か再分類、1つは対象外のまま。**
- K26（T に依存する述語）、K30（節点形 L5 のネットリスト）、K32（M の掃引＋Z の加算）は、未使用シナリオで小さく実行する。K30 と K32 は基になる等式が既に確認済み（canon の節点形、X5）で、残るのは「ネットリストとして組んだ」という確認だけである。
- K28（max/min/abs）は、B 自身が「70単位モデルでは T に依存しない」と書いている。静的な試験を1つ行うか、「T 掃引回路の外の構成時の設定」と再分類する。どちらにしたかを記録する。
- K33（年別のベクトル出力）は B の分類が d（外部メモリ）である。ネットリストは作らない。NOT_RUN を PASS に変えず、「回路文法の対象外」として理由を付ける。
- これで H-B1 の PARTIAL を解消できるかどうかが決まる。新しい式の族には広げない（EXP-4 の 4a）。

**(d) 性能の線 — 一括評価と任意点評価については打ち切る。オンライン・逐次更新についてだけ、事前登録した試験を1回行い、そこで完全に閉じる。**
理由：
- 一括と任意点では、4つの独立測定が全て否定的で、D が再現した。これ以上の測定や調整は実装の巧拙を測るだけである。
- 未測定の条件は「予定の変更後の再評価」だけである。既存の数値では、変更直後の1点評価が、回路の新規構築＋掃引 444 ms/T に対し節点形の再構築 0.75 秒で、桁が同じである（`integration/benchmark.md`。別々の測定からの推定であり、利得の証拠ではない）。
- 再計画者の予測 [H]：利得は出ない。公平な基準（影響を受けた単位だけ節点を作り直す。単調な問合せでは二分探索をやめてポインタを進める）を取れば、どちらも1事象あたり償却 O(1) で、オンラインの自然なデジタル算法は回路の自動機と同型だからである。
- それでも1回だけ測るのは、この予測を数え上げた事実に変えるためである（EXP-5）。利得が出なければ、本研究の価値は**表現・教育上のもの**（境界規約とリセットの対応、A と E の違い、観測量ごとの状態数、反例集）と確定し、新しい機構の仮説なしに性能の線を再開しない。

**(e) Math7 の7エンジン実行 — 次サイクルでは依頼しないことを推奨する。決めるのはユーザーである。**
理由（`routes/F_math7_bridge/STATUS.md`、`claims.md`）：
- 制限付き Math IR が受け付けるのは、整数・有理数・記号・2項の加算と乗算・整数べき（0〜8）だけである。floor・frac・min・max・比較・区分・sqrt・sin・cos・π は拒否される。
- このため今の入力（34 件）は、事象回数や分岐を Python 側で計算して定数として渡した有理数の四則でしかない。SageMath と MATLAB で実行しても、既に2つの独立評価器で厳密に一致している算術に実装の多様性が加わるだけで、事象の数え方・核・三角関数の恒等式・回路の動作については何も増えない。
- 実行するには、入力を `main`（または `main` から切ったブランチ）の `math_tools_v2/examples/` に置き、ユーザーが手動でワークフローを起動する必要がある。どちらも研究領域の外である。
- 意味のある7エンジン検証には新しいアダプターが要る：floor・frac・min・max・abs・比較・区分の式、sqrt・sin・cos・π、区分多項式と三角関数の定積分、有界な漸化式のスキーマ。それに対応する SageMath と MATLAB の評価器。失敗時に閉じる検証器。直接オラクルとの試験。別途の査読。これは Math7 側（`main`）の独立した開発で、本研究の書込み範囲の外である。
選択肢は 7 節の質問1に示す。
