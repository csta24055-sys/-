# 08 One-message autonomous research start (Japanese)

【最優先：モデルと工程の切り替え】
まず `10_MODEL_ROUTING.md` を読み、全体計画は `wlc-architect`（Fable 5.2 High）、A/B/C/Eの実装・数値計算は各担当（Opus 5.5 Medium）、Dの独立検証は `wlc-verifier`（Opus 5.5 High）、成果の比較・統合は `wlc-integrator`（Opus 5.5 High）、最後の次期研究計画は `wlc-replanner`（Fable 5.2 High）に委任してください。各エージェントの `model` / `effort` を適用し、実際の起動モデルを記録してください。設定だけで実行済みと扱わず、モデルにアクセスできなければ代替使用と制約を明記してください。

GitHub リポジトリ `csta24055-sys/-` の `claude/wlc-equivalent-circuit-20261124` を出発点として、ホールライフカーボンの電気等価回路研究を**5本の独立ルートで並行**して進めてください。

最初に `CLAUDE.md`、`WLC_CIRCUIT_RESEARCH/06_PARALLEL_ORCHESTRATION.md`、`07_SHARED_CONTRACT.md`、`05_SOURCE_MAP.md` と既存理論 `WLC_THEORY_RESEARCH_BASE/00_README.md`・`13_別チャット引継ぎ文.md` を読み、元の理論と制約を確認してください。

A：初期値・連続的な直線増加・階段増加・周期ののこぎり残差から等価回路を作る。コンデンサに一定電流が入ると Q,V は直線的に増えるという基本式から始め、空調10年、配管20年の交換を別々のしきい値・リセットで発生させる。

B：既存の**方程式全体系**を出発点に、積和、条件分岐、時間核、交換、状態更新、集計などをどの回路構造（R/C、制御源、スイッチ、論理、外部状態等）へ変換できるか独自に研究する。コンデンサだけへ無理に押し込めない。

C：既存の**70評価単位そのもの**を起点として、全件の役割・入力・出力・時間依存・回路対応を列挙する。21直接寄与・49補助等の違いを保持し、実際に独立したテストを実施する。

E：**抵抗Rとジュール熱から独立してモデル化する研究**。抵抗に一定電流Iを流すと電力I²Rは一定で、累積発熱エネルギーI²Rtは時間の一次関数になる。これを空調の運転などの累積排出に対応させる方法を、コンデンサ充電から始めず独自に研究する。交流の抵抗でも瞬間電力は正で、累積エネルギーには線形増加＋2倍周波数の有界振動が現れる。抵抗の温度と累積熱量、蓄電エネルギー、CO₂を混同せず、排出係数による換算条件、実際に積算する方法、性能差、限界を検証する。詳細は `09_RESISTOR_ENERGY_ROUTE.md`。

D：A/B/C/Eとは独立した基準計算・反例・境界条件・効率比較をつくり、統合候補を厳密に検査する。

エージェントが使える場合は `.claude/agents/wlc-*.md` の担当エージェントへ同時委任してください。各担当の作業先は `routes/A_waveform/` 等の専用ディレクトリとし、共有ファイルへの並行書き込みは禁止。別セッションにする場合はそれぞれプロジェクトブランチ由来の独立したルートブランチを使い、開始コミットを必ず確かめること。

A、B、Eの検証済みの部分を比較して必要なら**回路統一モデル**を構築する。Cの70単位の研究で網羅性を検査し、Dが独立検証する。全件等価が成立しない場合は、条件付き・近似・ハイブリッド・不可能性のいずれかを根拠とともに記録する。

新しい研究だけを `WLC_CIRCUIT_RESEARCH/` の中に追加し、元の研究・J-CAT原資料・WLC Studioアプリを改変しない。根拠のない成功宣言や架空の結果を作らない。

**計画書だけで終わらず**、可能な範囲を実装・テスト・計測・保存し、GitHubコミットと再実行手順まで報告する。ツール・時間・権利上の制約があれば未達の範囲を明示する。細かな方針判断は自律的に進める。
