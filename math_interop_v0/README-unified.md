# 7数学エンジンの統合実証（Math IR Unified / Phase 5）

## 目的と独立性

この開発は建築LCAの**本業解析とは独立した数学計算基盤の検証**です。実データを含めず、第1〜4段階の完成コードを再利用します。研究リポジトリや既存のMATLAB・SageMath単体ワークフローの変更は行いません。

## 7エンジンをどう接続したか

**単一のGitHub Actionsワークフロー** `.github/workflows/math-ir-unified.yml` 内で、次の連鎖を強制します。

1. **Python 5エンジン**：`phase4.build` の27ノードDAGを再利用。SymPy（厳密値）、NumPy（binary64近似）、mpmath（高精度近似）、SciPy（独立数値積分）、DuckDB（厳密値の集計）を実行。元の式・単位ラベル・変数仮定を共通JSONで保持し、SHA-256とエンジンバージョンを記録。
2. **SageMath 10.10**：前段の共通Math IR JSONをActions成果物から受領し、合成5ケースをSageMath Docker内で独立に厳密計算。
3. **MATLAB + Symbolic Math Toolbox**：SageMathの結果JSONと元の数式JSONを受領。前者を実際に読み込み、MATLAB自身の記号計算と厳密に照合。
4. **統合照合**：Python 5エンジン側の27ノードキャッシュを*別ランナー／別プロセス*で再利用し、SageMath 5ノード、MATLAB 5ノード、ケース別の照合5ノード、全体集約1ノードを追加して**43ノードの依存グラフ**を構成。前段の全情報と計算結果を文章転記なしに引き継ぎ、型・数学的厳密値・仮定・単位・出力ハッシュを照合。

依存グラフ：`Python source -> SymPy exact -> NumPy/mpmath -> validated`、別系統で`source -> SageMath -> MATLAB`。これらをケースごとの`reconciled`に合流させ、SciPy・DuckDB結果も`unified_summary`で統合します。

## 試験対象

実建築データは使いません。`phase1.make_cases()`で定義された5ケースのみです。厳密有理数、負数、境界値、45桁超の整数を含みます。

- 5エンジンの実計算がない場合には27ノードグラフを構築できない。
- SageMath結果が欠落・改ざんされればMATLAB検証または統合処理で失敗する。
- MATLAB結果が不一致なら統合できない。
- 27ノードキャッシュのSHA-256、エンジン版、依存関係が合わなければ失敗する。
- 入力の仮定・単位を含む出力メタデータが失われれば失敗する。
- 別ランナーでキャッシュが27件再利用されることを実測する。
- 統合結果を別プロセスで再構築して照合する。
- 値・単位・エンジン・版・依存関係・グラフハッシュなど9種類の改ざんを拒否する。

## 検証コマンド

GitHub Actions（PR・手動実行）：`Math IR Unified Seven Engines - One Traceable DAG`。

ワークフロー内部では、`python math_interop_v0/phase5.py prepare math_ir_io` → SageMathの計算 → MATLABの計算 → `python math_interop_v0/phase5.py finalize math_ir_io` → `python math_interop_v0/phase5.py audit math_ir_io` を実行します。

## 利用枠と安全性

GitHub Actions成果物は3段階の小容量データ＋最後の統合グラフに限定し、保持期間を**1日**とする（既存の0.5 GBストレージ警告を考慮）。ワークフローは合成データ限定であり、秘密の研究式や個人情報を公開リポジトリへ送ってはいけません。

## ここまでの達成範囲・未実装

**達成できたこと**：7エンジンの実計算・構造化結果の連鎖・43ノードにまたがる依存関係の記録・厳密値比較・Python27ノードの別ジョブ再利用・改ざん検出。

**未達のこと**（完成と誤認しない）：

- 43ノードを任意の順序・任意の数式で動かす完全汎用スケジューラではない。**遠隔SageMath/MATLABの起動順はGitHub Actionsの`needs`で固定されている**。
- 7エンジンすべてのキャッシュを別ワークフロー実行間で永続共有するわけではない。今回は**単一のワークフロー実行の異なるランナー間**の受け渡しを検証する。
- MATLABランタイムの正確なバージョンは成果物に記録していない（setup-matlab@v3の設定のみ記録）。SageMathイメージもタグ指定であり、digest pinではない。
- 一般の数学式すべての損失なし変換、厳密な単位次元解析、普遍的な誤差保証、分散排他制御、ユーザー提供の任意コード処理は未実装。
- GitHub Actions成果物は永続保管ではない。重要データを1日保持のArtifactに任せない。
- エンジン間一致は今回の5合成ケースについての検証であり、あらゆる数学的等価性を保証する証明ではない。

**統合CIの4ジョブ成功・43ノード・全7エンジンが実行された証拠・改ざんテスト成功**を最小合格基準とする。さらに第1〜4段階の回帰CIも合格して初めて本ブランチを`main`へマージする。
