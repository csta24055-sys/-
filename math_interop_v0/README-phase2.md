# 第2段階：Python 5種類のライブラリ間の数学データ継承

この段階は第1段階の `math-ir/0.1` を変更せず、**SymPy・NumPy・SciPy・mpmath・DuckDB** の連携を合成データで検証する。建築LCAの研究データ、SageMath／MATLABワークフローには触れない。

## 重要な実装思想

- **厳密値を正本にする。** SymPyで求めた既約有理数の分子・分母は常に文字列で保持する。
- **近似値は別フィールドに保存。** NumPyのfloat64を16進浮動小数表記（`float.hex()`）で、mpmathの80有効桁出力は10進文字列で保持する。型を暗黙に置換しない。
- **数値の誤差を区別する。** NumPy/ mpmathの表示値と、既知の厳密値との差を正確な有理数として算出。SciPy QUADPACKが報告する誤差は推定値であって、数学的に保証された上界とは扱わない。
- **仮定・単位・由来を必ず維持。** 第1段階の変数仮定・単位ラベルと、元入力のSHA-256を引き継ぐ。単位の**次元整合性検査は未実装**。
- **DuckDBでは厳密値をVARCHARで保存。** 自動的にDOUBLE/DECIMALへ変換して桁落ちさせない。構造化JSONの完全な往復を検証し、単位別件数をSQLで集計する。
- **SHA-256は偶発的変更の検出目的。** 悪意ある人物が値とハッシュの両方を書き換える攻撃に対する認証ではない。

## 実行するテスト

- 第1段階の5ケース（1/3、負の有理数、境界0、代入1/7、大整数）についてSymPy厳密値を生成。
- NumPy float64への明示的変換、バイナリ表現の記録と**実際の丸め誤差の有理数表示**。
- mpmath 95桁で計算し80有効桁を記録。既知の厳密値との差を算出。誤差保証は主張しない。
- SciPyで区間[0,1]のx²を積分し、厳密な1/3との誤差を測定。
- NumPyの桁落ち例 `[1e20, 1, -1e20]` の和で、実際の誤差を明示し、数値誤差を隠蔽しない。
- DuckDBへの保存・読み出し・SQL集計とJSONの完全な往復。
- 単位・分子・仮定・NumPy丸め誤差・Infinity・mpmath精度・10進出力・精度ポリシー・ハッシュの**9種類の改ざん検出**。

## 合格ゲート

GitHub Actionsの`test-python-handoff`が成功し、上記のすべてが合格した場合のみ第2段階を完了とする。

**限界**：単位ラベルの保持は次元解析ではない。数値誤差が分かるのは今回の既知の厳密値に対してだけであり、未知の真値について一般的な保証はない。複雑な連続最適化、大規模配列、実データ、計算結果の永続的キャッシュ、SageMath/MATLABへの構造化受け渡しは次段階以降の対象とする。
