# career-master: 就活準備の運用

非公開ホーム: `$JUDGMENT_LOOP_HOME/career_master`（既定 `~/.judgment-loop/career_master`）。以下 `M`。
道具: `python3 .claude/skills/career-master/scripts/chat_index.py`（会話索引）、`build_trainer.py`（練習ページ生成）、`export_review_runs.py --out M/06_ai_review_runs`（レビュー記録の一覧と写し）。
反復とモデルの使い分けは `.claude/skills/judgment-loop` と `.claude/skills/career-model-router` を使う。

## 守ること

- 個人データ・応募先名・提出資料・会話の内容・評価結果は `M` と `~/.judgment-loop/workspaces` にだけ置く。**このリポジトリには汎用コードしか置かない。**
- 事実は必ず4つに分けて扱う: **実施済み・実測**／**文書上の主張**／**計画・仮説**／**未確認**。他人（研究室・先輩・AI）の成果を本人の成果として書かない。完了していないことを完了形で書かない。
- 提出済みの書類は正本。書き換えない。食い違いは追補として別に出す。
- 応募・提出・予約・送信・公開・main への変更はしない。未承認の有料 API 呼び出しと、個人データの外部送信の範囲拡大もしない。
- 合格確率のような根拠のない数値を作らない。優先度は「高・中・低＋根拠」で示す。
- 過去の会話には就活と無関係の私的な内容が含まれる。読まない・引用しない・記録しない。

## フォルダ（`M` の下）

| フォルダ | 中身 |
|---|---|
| `00_source_inventory` | 原資料の所在・ハッシュ・取得状況・未読範囲 |
| `01_candidate_facts_and_timeline` | 本人の事実と発言の証拠台帳、時系列、矛盾・撤回 |
| `02_research_and_code_evidence` | 研究資料とコードから検証した実績（主張と裏付けの対照） |
| `03_<面接名>_interview` | 面接専用: 最終パック、練習ページ、追補、面接後の記録 |
| `04_company_packets/<応募先>` | 応募先別: 公式資料、職種適合、ES・面接、弱点、次の行動 |
| `05_cross_target_strategy` | 応募先を横断した優先順位表（更新可能） |
| `06_ai_review_runs` | レビューの入出力と採否の記録（GPT 実通信／代替レビュー／模擬を区別） |
| `07_retrieval_index_and_replay` | 会話索引、原文位置への逆引き、処理の checkpoint |
| `raw/` | 取得した原本（変更しない） |

## 自然言語 → 操作

| ユーザーの言葉 | すること |
|---|---|
| 「面接対策を始めて／練習ページを作って」 | 最終パック（Markdown）を確認 → `build_trainer.py <pack.md> <out.html> --title "…"` → スマホ幅のブラウザで動作確認 → ファイルをユーザーへ送る |
| 「面接が終わった／聞かれたことを記録して」 | ユーザーの記録を `03_…/debrief_<日付>.md` に保存 → 事実は台帳へ → 次の面接用にパックと弱点表を更新 |
| 「（応募先）の資料を更新して」 | 公式ページを再取得（公式のみ、根拠台帳に URL・取得日・該当箇所）→ パケットを更新 → judgment-loop でレビュー → 採否を記録 |
| 「就活全体の優先順位を更新して」 | 締切・選考段階・本人の最新の意向・職種要件の一致・弱点・必要時間・情報の確かさで並べ直し、変更点と理由を残す（上書きせず版を足す） |
| 「過去の会話から〜を探して」 | `chat_index.py search … --role user` で本人発言を探し、`show` で前後を確認。引用は日付と位置つきで台帳へ。AI 側の発言は本人の事実として扱わない |
| 「停止」「再開」「状況は？」 | judgment-loop の pause / resume / status。`M/checkpoints/progress.jsonl` も見る |

## 会話索引（ChatGPT エクスポートの復旧テキスト）

1. 分割ファイル `recovered_NNN.txt` を `M/raw/chatgpt_recovered/` に置く（Dropbox からは一時リンク＋curl で直接ディスクへ。中身を画面に出さない。サイズと content_hash を照合し、`checkpoints/download_manifest.jsonl` に残す）。
2. `chat_index.py reassemble` — 連結して元ファイルに復元（欠番があれば止まる。目印の外に断片が残れば報告）。
3. `chat_index.py build` — 会話・発言単位の索引。chat.html は会話 JSON と同じ内容なので数えない。
4. `search` / `show` で原文へ。3文字未満の語は部分一致で補う。

## 面接練習ページ

- パックの書式: `## 1. 柱` / `## 2. プレゼン`（`【0 導入】` などの段、`**時間**`、``` の手持ちメモ）/ `## 3. 質問`（`**Q1 質問**（根拠）` → `**「最初の1文」** 続き` → `→「追質問」：答え`、`**専門の確認…**`、`**短く答える…**`）/ `## 4.` 言い直す語 / `## 5.` グループワーク / `## 6.` 逆質問 / `## 7.` 持ち物 / `## 8.` 練習。
- 生成されるページは単一 HTML で外部通信をしない。記録は端末内にだけ残る。文面はパックのまま変えない。
- 公開 URL にはしない（個人の内容のため）。ファイルとしてユーザーへ渡す。

## レビューの扱い

- GPT が使えるとき: judgment-loop の承認予算の範囲で `review --send`。
- レビューのたびに `export_review_runs.py --out M/06_ai_review_runs` で一覧を更新する（GPT 実送信・送信失敗・代替レビュー・模擬を区別して出る）。
- 使えないとき（残高切れなど）: 作成担当とは別の独立したエージェントにパケット全文を渡し、同じ JSON 形式の判定を `review --mock <file> --mock-source claude-independent` で取り込む。報告では必ず「GPT 未レビュー」と書く。模擬の成功を本番通信の成功と書かない。
