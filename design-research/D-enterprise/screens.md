# EnviroOps Federated Shell — 画面一覧と操作説明

プロトタイプ: `prototype.html`（単一 HTML、外部依存なし、ハッシュルーティング）。題材は架空の共同利用基盤『（仮称）EnviroOps Platform』で、組織・人名・IP・数値はすべてダミー（IP は文書用アドレス 192.0.2.0/24 などを使用）。

## 共通シェル（全画面）

| 要素 | 内容 | デスクトップ（1440px） | スマートフォン（375〜390px） |
|---|---|---|---|
| スキップリンク | 「本文へスキップ」 | Tab 1 回目で表示 | 同じ |
| スコープバー（banner） | 組織 › プロジェクト › 環境（本番 / 検証）、現在のロール、コマンド、テーマ、ヘルプ | 選択欄を横並び | 1 行の要約ボタン。タップで「スコープとロールの切替」シート |
| 左レール（navigation） | ホーム / センサー / LCA 結果 / 管理 / 部品。「展開」で 232px に | 常設 | 非表示 → 下部ナビ（ホーム / センサー / 承認 / 管理 / その他） |
| ロール切替（デモ用） | 組織管理者 / プロジェクト責任者 / 解析者（既定） / 閲覧者 / 監査担当 | スコープバー右 | スコープ切替シート内 |
| テーマ | 自動（OS 設定） → ライト → ダーク の順に切替。設定は端末に保存 | ボタン | アイコンボタン |
| コマンドパレット | 画面移動、監査ログ・権限マトリクスへの直接移動、組織切替、ロール切替、テーマ、密度、ヘルプ | `Ctrl/⌘+K` または `/` | 「その他」→ コマンドパレット |
| トースト | 軽微な結果だけ。7 秒で消える（ホバー・フォーカス中は止まる）、閉じるボタンあり | 右下 | 下部ナビの上 |

組織を切り替えるとアクセント色（主ボタン・選択ナビ・リンク）だけが変わり、状態色は変わらない。北陵大学=青、湊川市=緑、東和建設=茶。

### キーボード操作（共通）

| キー | 操作 |
|---|---|
| `Ctrl` / `⌘` + `K` | コマンドパレットの開閉 |
| `/` | コマンドパレット |
| `g` → `h` / `w` / `d` / `s` / `c` | ホーム / センサー / LCA 結果 / 管理 / 部品 へ移動 |
| `?` | ヘルプとショートカット一覧 |
| `F6` / `Shift+F6` | スコープバー → レール → 本文の各列 の順に領域移動 |
| `Esc` | ダイアログを閉じる（フォーカスは開いたボタンに戻る） |

1 文字ショートカット（`g`、`/`、`?`）は「管理 › 外観と操作」で無効にできる。入力欄にいるときは働かない。

## 1. ホーム `#dashboard`（スコープのホーム）

**目的**: 選んだスコープの状況を固定レイアウトで把握する（案B から取り込んだ概要表示。自由配置はしない）。

**構成**
- KPI カード 4 枚: 稼働中のセンサー（欠測台数）、警戒台数（注意台数）、あなたの承認待ち（権限がなければ「承認権限なし」と表示）、LCA ジョブ 24 時間の成功 / 失敗
- PM2.5 の 24 時間推移: 線グラフ、基準 25 µg/m³ の帯と破線、欠測区間のハッチ、ホバーで値、要約文、「表で見る」
- 計算エンジンの状態: SymPy / SageMath は正常、MATLAB は縮退（部分障害）。画面全体は落とさず、影響するジョブだけを案内
- センサー配置（模式図）: 状態を形（円・三角・四角・中抜き）でも区別、「表で見る」
- 承認の受信箱: 現在の組織の承認待ちだけ。リンクで該当の対象へ

**主要操作**: 再読み込み（スケルトン表示を確認できる）、報告用に出力（印刷用 CSS でナビ類を除いて PDF 化）。

**空状態**: プロジェクト「共同研究 2027 準備」を選ぶと「まだデータがありません」（登録・複製の導線）。閲覧者では登録ボタンが無効になり、理由を表示。

**モバイル**: KPI は 2×2、カードは 1 列。

## 2. センサー運用 `#workspace`（主要機能・3 列ドリルダウン）

**目的**: 約 414 台（全組織で 1,240 台）のセンサーを一次切り分けし、校正値の変更を申請する。

**列 1: センサー一覧（大規模データテーブル）**
- 検索（ID・名称）、状態、保存ビュー（すべて / 要対応 / 校正期限 30 日以内）、表示密度（詰める 24px / 標準 32px / 広げる 40px）
- 列の設定: 表示の切替と ↑↓ ボタンでの並び替え（ドラッグ不要）。設定は端末に保存
- 固定列（選択・ID）、固定ヘッダー、3 状態ソート（昇順 → 降順 → 解除）
- 行を選ぶと一括操作バー（校正を一括申請 / 選択分を CSV 出力 / 選択を解除）。閲覧者では一括申請が無効になり、理由を表示
- ページング（25 / 50 / 100 件）、件数表示「全 414 件中 1–25 件」
- 絞り込みに一致しないときは「条件に一致しない」空状態と「絞り込みを解除」

**列 2: 詳細**: 状態、値の出所ラベル（計測値 / 手入力・承認済み）、PM2.5 24 時間グラフ＋要約＋表、「校正値の変更を申請」。

**列 3: 証跡**: 承認の経過、変更履歴、監査イベント、値の出所。「証跡を表示 / 閉じる」で開閉。

**申請ダイアログ**
- 申請先スコープとロールを濃色帯で再掲（別組織への誤申請を防ぐ）
- 差分（変更前 / 変更後）を入力に合わせてその場で更新
- 申請者・承認者は自動入力（再入力させない）
- エラーは項目直下に原因と修正例、上部に件数つきの要約（各項目へのリンク）
- ±5.0 を超える変更と一括申請は高リスクとして、対象 ID（または「n件」）の入力を求める
- 申請後は列 2 に「申請中」、列 3 に承認の経過が残り、監査ログに記録される

**キーボード（表にフォーカスがあるとき）**: `j` / `k`（または ↑↓）で行移動、`x` / `Space` で選択、`Enter` で詳細を開き列 2 にフォーカス。

**URL 共有**: 行を開くと `#workspace?sel=AQ-0142` になる。別組織のセンサーへのリンクを開くと、スコープをその組織に切り替えたうえで通知する。

**幅による違い**: 1280px 以上は 3 列、768〜1279px は 2 列（証跡は詳細の下）、767px 以下は 1 列ずつ（一覧 → 詳細 → 証跡を「戻る」で移動）。スマートフォンでは表がカードリスト（ID・名称・PM2.5・状態・最終受信）になり、一括操作バーは出さない。

**LCA プロジェクトを選んだ場合**: 「このプロジェクトにはセンサーがありません」と、同じ組織のセンサーのプロジェクトへ切り替える導線を表示。

## 3. LCA 結果 `#detail`（詳細・結果表示）

**目的**: LCA ジョブ「LCA-2026-0918 研究棟B 改修シナリオ v3」の結果を確認し、公開を承認または差戻す。

**タブ（ARIA tablist、← → / Home / End）**
1. 結果: KPI 4 枚（合計、基準比、v2 からの変化、床面積あたり）、段階別（製造・輸送・施工・運用・解体）の積み上げ横棒（凡例・ホバー・要約・表）
2. 承認フロー: 申請 → レビュー → 承認 / 差戻し のステップ、変更の差分（v2 → v3）、経過とコメント
3. 値の出所: 値ごとに 計算値 / 手入力 / 推定値 の区別、エンジン（SymPy / SageMath / MATLAB）、係数 DB と版
4. シナリオ改訂: 対象 → 材料 → 係数 → 確認 の 4 段ウィザード。前回値を引き継ぎ、確認画面で再入力させない。範囲外の値は項目直下にエラー

**承認 / 差戻し**
- 承認権限（組織管理者・プロジェクト責任者）がないと両ボタンが無効になり、理由を表示
- 現在のスコープが別組織（湊川市・東和建設）のときは、警告と「北陵大学に切り替える」ボタンを出し、承認操作を無効にする
- 差戻しは理由が必須（5 文字以上）。処理後はステップと経過が画面内で更新され、トーストでも通知、監査ログに記録

**部分障害**: MATLAB 停止で感度分析ジョブが保留中であることを示し、本結果には影響しないことを明記。

**モバイル**: KPI は 2×2、ステップは縦積み、値の出所の表はカードリスト。差分を確認したうえで承認できる（スマートフォンは確認と承認に絞る方針）。

## 4. 組織の管理 `#settings`（設定・管理）

**アクセス**: 組織管理者は全項目を編集できる。監査担当は読み取り専用（監査ログの検索と出力は可）。それ以外のロールは **ページ単位の「権限がありません」** を表示し、「権限を申請」ボタンを出す（ナビから項目は消さない）。この表示も監査ログに「拒否」として記録する。

**タブ**
1. メンバー: 氏名（ダミー）、ロール（変更すると監査ログに記録）、2 要素認証の状態、最終ログイン
2. 権限マトリクス: 9 機能 × 4 権限レベル（閲覧 / 編集 / 承認 / 管理者）。可・不可を色＋アイコン＋文言で表示
3. セキュリティ: SSO（SAML 2.0 / OIDC、IdP メタデータ URL の検証、接続テスト）、2 要素認証の方針（パスキー推奨、SMS 不使用、コードの貼り付け許可）、無操作時のセッション失効、管理操作の IP 制限、アクティブなセッションの一覧と「失効させる」（確認ダイアログあり）
4. 監査ログ: 誰が（実行者）・いつ（日時 JST）・何を（操作・対象）・どこから（IP とクライアント）・結果、組織。検索、種類・結果・期間で絞り込み、25 件ずつ追加表示、CSV 出力（出力した事実も記録）。この画面で行った操作は即座に先頭に追記される
5. 組織テーマ: ライト用・ダーク用アクセントの HEX を入力すると、背景とのコントラスト比をその場で計算。4.5:1 未満ならエラーと候補色を表示。変更は申請として承認フローへ
6. 外観と操作: テーマ（OS / ライト / ダーク）、表の密度、1 文字ショートカットの有効・無効

**モバイル**: タブ列は横スクロール（タブ列の内部だけ）、表はすべてカードリスト。

## 5. 共通部品とトークン `#components`

実際に操作できる部品の一覧。部品の成熟度（stable / beta）、ボタン 5 種、フォーム（検証つき）、確認ダイアログ、タブ、並べ替えできる表、チャート（棒＋表＋要約）、カード、成功・注意・エラー・承認待ちのメッセージ、エラーの 4 階層（トーストの実演、存在しない画面へのリンク）、空状態 2 種、スケルトン、カラートークン（現在のテーマと組織で計算した値とコントラスト比）、文字サイズ、余白・角丸・影。

## 6. 例外画面

- 存在しない画面（例 `#no-such-page`）: 「ページが見つかりません」とアドレス、ホームへの導線
- 権限なし: 「組織の管理」を解析者・閲覧者・プロジェクト責任者で開いたとき

## 試し方（推奨シナリオ）

1. ロール「解析者」のまま `#workspace` で AQ-0142 を開き、オフセットに「7」と入力 → 高リスク確認が出ることを確認して申請
2. ロールを「プロジェクト責任者」に切り替えて `#detail` で承認 → ステップと監査ログ（`#settings` は組織管理者で）を確認
3. 組織を「湊川市」に切り替えて `#detail` を開き、別組織のため承認できないことを確認
4. ロールを「閲覧者」にして `#settings` を開き、権限なし画面を確認
5. 幅 375px で `#workspace` を開き、カードリスト → 詳細 → 証跡の移動を確認

## 確認レベル

ヘッドレス Chromium（Playwright）で 1440×900 と 375×812 の両方について全 7 ルートを表示し、スクリプトエラーがないこと、375px でページの横スクロールが出ないこと（`scrollWidth` = 375）を確認した。目視したスクリーンショットは デスクトップのセンサー運用（3 列）とモバイルのホームの 2 枚だけ。スクリーンリーダー、実機スマートフォン、Safari / Firefox は未確認。
