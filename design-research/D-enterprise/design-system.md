# EnviroOps DS v2.4.0 — D 分類（大企業品質）の推奨デザインシステム

対象: 採用案C「Federated Shell」（プラットフォーム統合型＋トークン駆動マルチテナント）。実装例は `prototype.html`。
根拠の記号（P1〜P12 / X1〜X8）は `principles.md` を参照。データ・組織名・人名はすべてダミー。

## 1. 設計思想

1. **誰が・どの範囲で見ているかを常に示す。** 全画面の上部にスコープバー（組織 › プロジェクト › 環境）と現在のロールを出す。承認・申請のダイアログにも同じスコープを再掲し、別組織への誤操作を構造的に防ぐ。
2. **画面骨格を先に決め、機能はその上に載せる（P3）。** 骨格は「スコープのホーム（固定配置の概要）」「3 列ドリルダウン（一覧 → 詳細 → 証跡）」「タブ付き詳細」「管理（タブ）」「例外（権限なし・404）」の 5 種類だけにする。
3. **値は役割名のトークンで参照する（P1, P2）。** 組織ごとに差し替えるのはアクセント系トークンだけにする。状態色・余白・文字は全組織で固定する（X3 の回避）。
4. **変更は「下書き → 申請 → レビュー → 承認 / 差戻し」で行い、差分と出所を必ず示す（P6, P12）。**
5. **高級感ではなく成熟度を目指す。** 装飾を足さず、状態・空・読み込み・失敗・権限なしの各状態を一級の画面として設計する（P5, P7）。

## 2. トークンの層

| 層 | 例 | 役割 | 画面コードからの参照 |
|---|---|---|---|
| global（値） | `--space-400: 16px`、`--fs-300: 14px`、`--radius-200: 6px` | 物理値の唯一の定義 | 余白・文字・角丸だけ可 |
| semantic（役割） | `--color-text-subtle`、`--status-danger`、`--brand-accent` | 意味と用途 | **原則こちらを参照** |
| component | `--row-h`、`--ctl-h`、`--scopebar-h`、`--rail-w` | 部品の寸法。密度設定と連動 | 部品の CSS 内だけ |

運用ルール:
- 新しいトークンには接頭辞（`--color-` / `--status-` / `--brand-` / `--series-` / `--space-` / `--fs-`）を付ける。HEX 値を直接書いたらリンタで検出する（P2）。
- ダークは「自動反転」にしない。同じ役割に別の値を選び、暗い面に対して検査する（`prefers-color-scheme` と `data-theme` 手動切替の両方で定義）。
- 組織テーマは JSON で配布する。登録時にコントラストを自動検査し、管理者の承認を経て反映する（プロトタイプの「管理 › 組織テーマ」）。

## 4. タイポグラフィ

フォント: `system-ui, -apple-system, "Hiragino Sans", "Noto Sans JP", "Yu Gothic UI", "Meiryo", sans-serif`。ID・IP・コードは等幅（`ui-monospace` 系）。数値は `font-variant-numeric: tabular-nums`。

| トークン | サイズ / 行送り | 用途 |
|---|---|---|
| `--fs-100` | 12 / 16 px | 注記、凡例、ナビのラベル |
| `--fs-200` | 13 / 20 px | 表、補助文、ヘルプ |
| `--fs-300` | 14 / 20 px | 本文、ボタン、入力 |
| `--fs-400` | 16 / 24 px | 見出し 3、カード見出し |
| `--fs-500` | 20 / 28 px | 見出し 2、ダイアログ見出し、モバイルの見出し 1 |
| `--fs-600` | 24 / 32 px | 見出し 1（ページに 1 つ） |
| `--fs-kpi` | 28 / 36 px | KPI の数値だけ |

規則: 見出しは 3 段まで（h1 → h2 → h3 を飛ばさない）。太さは 400 / 600 / 650 の 3 種。字間の調整はしない。表記規則（P12）: 単位は数値の後に半角スペース（`28.4 µg/m³`、`3,945 t-CO₂e`）、日時は `YYYY-MM-DD HH:mm`（JST）、相対時刻は「5 分前」を 1 時間未満だけに使う、欠測は「—」または「欠測」で 0 と区別する。

## 5. 余白・グリッド・寸法

- 基本単位 4px。段階: `--space-050` 2 / `-100` 4 / `-150` 6 / `-200` 8 / `-300` 12 / `-400` 16 / `-500` 24 / `-600` 32 px。
- ページの内余白: デスクトップ 24px、スマートフォン 16px（左右のガター）。
- カード内余白 16px（モバイル 12px）、カード間 16px。3 列の列間は 1px の境界線＋列内 16px。
- グリッド: KPI は 4 列（1279px 以下で 2 列）。概要は 2:1、1023px 以下で 1 列。
- 部品の高さ（密度と連動、P4）

| 密度 | 表の行高 `--row-h` | 操作部品 `--ctl-h` |
|---|---|---|
| 詰める | 24px | 28px |
| 標準（既定） | 32px | 32px |
| 広げる | 40px | 36px |
| スマートフォン（固定） | カード表示 | 40px（下部ナビ・スコープ要約は 44px 以上） |

- シェル: スコープバー 48px（モバイル 52px）、左レール 76px（展開時 232px）、下部ナビ 60px。

| トークン | 値 | 用途 |
|---|---|---|
| `--radius-100` | 4px | タグ、キーボード表記 |
| `--radius-200` | 6px | ボタン、入力、ステップ |
| `--radius-300` | 8px | カード、表の外枠、ダイアログ、メッセージ |

| `--shadow-300` | `0 8px 28px` 22% | ダイアログ、トースト、ツールチップだけ |

## 7. コンポーネントの使用ルール（Do / Don't）

| 部品 | Do | Don't |
|---|---|---|
| スコープバー | 組織 › プロジェクト › 環境とロールを全画面に出す。検証環境は「検証環境」バッジを併記。リンクにスコープを含める（`#workspace?sel=AQ-0142`） | 画面ごとに位置や表記を変える。スコープを設定画面の奥に隠す |
| ナビ（レール / 下部ナビ） | 現在地は `aria-current="page"`＋帯＋太字。権限がない項目も消さず、例外画面で申請方法を出す | 権限で項目を消して利用者を迷わせる。選択状態を色だけで示す |
| ボタン | 主ボタンは 1 画面 1 つ（P7）。主 / 副 / 控えめ / 危険 / 無効の 5 種。無効にするときは近くに理由を書き、`aria-describedby` で結ぶ | 主ボタンを並べる。理由のない無効ボタン。危険操作を主ボタンの色で出す |
| フォーム | ラベルは常時表示。必須は「必須」と文言で示す。ヘルプは入力前に読める位置。エラーは項目の直下に「原因＋修正例」、複数ならダイアログ上部に要約とリンク。既知の値は自動入力（申請者・承認者・前回値。WCAG 3.3.7） | プレースホルダーだけのラベル。「入力が不正です」だけのエラー。同じ情報の再入力 |
| ダイアログ | `<dialog>` の `showModal()`。開いたら最初の入力へ、閉じたら開いたボタンへフォーカスを戻す。高リスク確認・申請・承認に限る。高リスクは対象 ID の入力で確認（P6） | 低リスク操作に毎回「よろしいですか」。ダイアログの中で別のダイアログを開く |
| タブ | `role="tablist"`、矢印・Home・End で移動、選択タブだけ `tabindex=0` | タブをページ遷移の代わりに使う（URL が変わる移動はナビで） |
| データテーブル | 3 状態ソート（昇順 → 降順 → 解除、`aria-sort`）、固定列（選択・ID）、列の表示切替と並び替え（↑↓ ボタン。ドラッグ不要: WCAG 2.5.7）、選択時の一括操作バー（最大 5 操作）、ページング 25 / 50 / 100、保存ビュー、密度 3 段階。行は `j` / `k` で移動 | 表計算の代わりにする、入れ子にする、狭い枠に押し込む（X4）。一括操作をスマートフォンで許す |
| 3 列ドリルダウン | 列 1 一覧、列 2 詳細、列 3 証跡（承認の経過・変更履歴・監査イベント・値の出所）。列 3 は必要なときだけ開く。1279px 以下は 2 列（証跡は詳細の下）、767px 以下は 1 列ずつ「戻る」で移動 | 3 列を常時出す（X6）。狭い画面で横に詰める |
| チャート | インライン SVG、線 2px、閾値は帯＋破線＋文言、欠測はハッチで区別（0 と混同させない）。ホバーで値を表示。**全グラフに「表で見る」と要約文** | 二重軸。系列色を数値の文字に使う。凡例なしの多系列 |
| カード | 固定配置。見出し＋内容＋操作 1 つ | 利用者の自由配置（多組織で一貫性が崩れる） |
| メッセージ | 成功・注意・エラー・承認待ち・情報を 色＋アイコン＋太字の見出し文で | 色だけ、アイコンだけ |
| エラーの階層 | トースト（軽微・7 秒・ホバーで停止・閉じるボタン）→ インライン（項目）→ セクション（部分障害、画面は落とさない）→ ページ（権限なし・404） | 重要な結果をトーストだけで伝える（X5）。部分障害で画面全体をエラーにする |
| 空状態 | 「まだデータがない」（作成の導線）と「条件に一致しない」（絞り込み解除）を区別 | 「データがありません」だけ |
| 読み込み | 最終配置と同じ形のスケルトン＋`role="status"` の「読み込み中」 | 長いスピナー、配置がずれる読み込み |
| コマンドパレット | `Ctrl/⌘+K`。画面移動・スコープ切替・テーマ・密度・ヘルプに到達。combobox＋listbox | パレットにしかない機能を作る |

部品の成熟度（P11）: Button / Field / Dialog / Tabs / Table / ScopeBar / ColumnLayout / CommandPalette は stable、MapView は beta（基幹画面では使わず概要表示だけ）。

## 8. レスポンシブ規則（P10）

| 幅 | ナビ | スコープ | 本文 | 表 |
|---|---|---|---|---|
| 1280px 以上 | 左レール（76px、展開 232px） | 横並びの選択欄＋ロール | 3 列ドリルダウン | 表（固定列・表内スクロール） |
| 768〜1279px | 左レール | 同上 | 2 列（証跡は詳細の下） | 表 |
| 767px 以下（375〜390px を想定） | 下部ナビ 5 項目（ホーム / センサー / 承認 / 管理 / その他） | 1 行の要約ボタン → シートで切替 | 1 列ずつ（一覧 → 詳細 → 証跡、戻るボタン） | カードリスト（主要列だけ）。一括操作バーは出さない |

スマートフォンは「確認と承認」に絞る（案A から）。375px でページ全体の横スクロールを出さない（ヘッドレス Chromium で `scrollWidth = 375` を確認済み）。

## 9. アクセシビリティ規則（WCAG 2.2 AA を基本目標）

- コントラスト: 文字 4.5:1 以上、UI 部品とフォーカスリング 3:1 以上（3 章の表）。組織アクセントは登録時に自動検査し、不足なら候補色を提示する。
- フォーカス: 2px のリング＋2px オフセット（2.4.7）。固定ヘッダーと下部ナビに隠れないよう `scroll-padding` を設定（2.4.11）。
- ターゲット: 最小 24×24px（2.5.8）、モバイルは 40〜44px。
- 構造: スキップリンク、`banner` / `navigation` / `main` / 各列 `region`（見出し付き）。見出しは h1 → h2 → h3。
- キーボード: すべての操作をキーボードで完結。`F6` で領域移動。1 文字ショートカットは設定で無効化できる（2.1.4）。
- フォーム: 常時表示のラベル、`aria-invalid` と `aria-describedby` でエラーを結ぶ、原因と修正例を書く（3.3.1, 3.3.3）。
- ヘルプ: 全画面の右上同じ位置（3.2.6）。
- 冗長な入力の回避: 申請者・承認者・前回値を自動入力（3.3.7）。
- 認証: パスキーまたは認証アプリ、コード欄の貼り付けと自動入力を許可、パズル型 CAPTCHA は使わない（3.3.8）。
- ドラッグ代替: 列の並び替えは ↑↓ ボタン（2.5.7）。
- 動き: `prefers-reduced-motion` に対応。強制カラーモードでは境界線を `CanvasText` で描く。
- グラフ: 代替テキスト＋要約文＋データ表。状態は色＋形＋文言。

## 10. D 分類（大企業品質）の基準との組み合わせ方

| D 分類の基準 | このデザインシステムでの担保 |
|---|---|
| 一貫したデザインシステム | 3 層トークン＋5 種類の画面骨格。組織差し替えはアクセントだけ |
| 情報階層 | h1 1 つ・主ボタン 1 つ・見出し 3 段。スコープ → 機能 → 対象の 3 段ナビ |
| 操作へのフィードバック | エラー 4 階層、トーストは軽微な結果だけ、重要な結果は画面内に残す |
| 読み込み・エラー・空状態 | スケルトン、部分障害の縮退表示、空状態 2 種、権限なし・404 のページ |
