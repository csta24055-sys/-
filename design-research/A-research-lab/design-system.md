# 分類A 研究支援アプリ 推奨デザインシステム「Pipeline Ledger DS」

対象: 大学・研究室内部の研究支援アプリ（採用案C「Pipeline Ledger」）
実装例: `prototype.html`（単一 HTML、外部依存なし、データは全てダミー）
前提文書: `principles.md`（P1〜P11、X1〜X7）、`concepts.md`（案C の仕様と評価）

## 確認レベル

- トークンの主要な文字・背景の組み合わせは、ライトとダークの両方で WCAG のコントラスト比をスクリプトで計算した（最低値はライト 4.74、ダーク 5.24。いずれも `--border-strong` 対 `--surface`）。
- `prototype.html` は、ヘッドレスの Chrome（Playwright）で 1440px と 375px の幅で読み込んだ。5画面とも JavaScript のエラーがなく、375px で横スクロールが出ないことを確認した。主な操作（段の実行、台帳のキーボード操作、ダイアログのフォーカスの戻り、学部生の入力エラー）も確かめた。
- スクリーンリーダーでの読み上げと実機のスマートフォンでの確認はしていない。

## 1. 設計思想

1. **作業の単位は「処理の段」とする。** 画面の骨格は、取り込み → 検証 → Math IR 変換 → ソルバー実行 → LCA 演算 → 図表・レポートの段である。表（台帳）と根拠ページは、段の「表示」の1つとして扱う（P1, P2）。
2. **状態の語彙を固定する。** 状態は「○ 未設定・◐ 準備完了・● 成功・✕ 失敗・↻ 要再計算」の5つだけで、色・記号・文字の3つで示す。利用者は色の意味を変えられない（P3, X4）。
3. **重い計算は利用者が実行を決める。** 条件の変更はすぐには計算しない。「未適用 n 項目 ▶ 実行」で実行し、下流の段は ↻ にする。軽い試算（感度分析のスライダー）だけは即時に反映するが、「試算」と明示し、台帳には記録しない（P4, X3）。
4. **全ての値に来歴を付ける。** 図と出力の下には、入力のジョブ・条件の版・データのハッシュを必ず表示する。右の根拠パネルは常に置いておく（P2, P5, P10）。
5. **装飾よりも情報の密度・速さ・正確さを優先する。** 本文は 13px、表は 12.5px、行の高さは 26px（詰めた表示では 22px）。読み物（根拠ページ）だけは 15px に広げる。
6. **段階的に開示する。** 根拠パネルは既定で「入力の来歴」だけを開き、学部生には取り込みと検証の段だけを見せる（X1, X6）。

フォント: `"BIZ UDPGothic", "Noto Sans JP", "Hiragino Sans", "Yu Gothic UI", system-ui, sans-serif`。数値は全て `font-variant-numeric: tabular-nums` にする。ID・ハッシュ・コマンドは `ui-monospace, "BIZ UDGothic", monospace` にする。

| トークン | サイズ | 用途 |
|---|---|---|
| `--fs-2xl` | 22px | 指標カードの数値 |
| `--fs-xl` | 18px | 画面の見出し（h1） |
| `--fs-lg` | 15px | 節の見出し、根拠ページ（レポート）の本文（行間 1.8） |
| `--fs-md` | 13px | 本文、フォーム（行間 1.55） |

## 4. 余白・グリッド

- 余白は 4px の倍数にする: `--sp-1` 4 / `--sp-2` 8 / `--sp-3` 12 / `--sp-4` 16 / `--sp-5` 20 / `--sp-6` 24 / `--sp-8` 32。
- パネルの内側は 12px、カードは 12px×16px、表の行は 26px（`--row-h`。詰めた表示では 22px）。
- 作業画面（1440px）は4つの領域に分ける: 段のリスト 232px、作業 可変、根拠 300px、ジョブモニターは下部の全幅。
- ダッシュボードと詳細は 12 列のグリッドにし、カードは `span-4 / 6 / 8 / 12` で配置する。

## 5. 角丸・影・モーション

- 角丸: `--r-sm` 4px（入力欄、kbd）、`--r-md` 6px（ボタン、通知）、`--r-lg` 10px（カード、パネル、ダイアログ）。
- 影: `--shadow-1`（カード、ごく薄く）、`--shadow-2`（ダイアログ、トースト）。それ以外の装飾の影は使わない。
- モーション: `--dur` 120ms の色の変化と、スケルトンの光の移動だけにする。`prefers-reduced-motion: reduce` では全てのアニメーションと遷移を止め、スケルトンは静止した面にする。

## 6. コンポーネントの使用ルール

### ボタン
- 種類は主・副・危険・無効・文字の5つ。1つの領域に主ボタンは1つまでにする。
- 高さは 32px 以上（小は 28px）、幅は 32px 以上にする（2.5.8 の 24px を満たす）。
- Do: 「▶ 実行」「↻ 同条件で再実行」のように、記号と動詞の文字を併記する。
- Don't: アイコンだけのボタンを作る（X1）。危険な操作を確認なしで実行する。危険ボタンは必ず確認ダイアログを経由し、何が残るか（変更履歴に残る等）を書く。

### 実行ボタン（未適用の表示）
- 常に作業画面の右上の同じ位置に置く。表示は「未適用 n 項目 ▶ 実行」。n が 1 以上なら紫（`--st-stale`）の二重の輪で強調する。
- 変更した欄の行には、左に紫の縦線と「未適用」の文字を付け、適用済みの値を併記する。

### フォーム
- ラベルは必ず `<label for>` で付け、ヘルプとエラーは `aria-describedby` でつなぐ。
- 単位・許容範囲・既定値・出典を1行にまとめた「条件の表」を基本にする（P6）。
- エラーは、入力欄の赤枠と赤背景、`✕` 付きの文で示す。文には「何が違うか」と「どう直すか」を書く（例: 「異常の閾値は注意（35）より大きくしてください」）。送信時は、先頭にエラーの要約を出してフォーカスを移し、各項目へのリンクを付ける。
- 前回の値（部屋・装置）は引き継ぎ、同じ内容を二度入力させない（3.3.7）。
- Don't: 単位違い（mg/m³ と µg/m³）を黙って受け付ける。単位を選ばせて換算し、換算後の値で範囲を確かめる。

### データテーブル・台帳グリッド
- 数千行は仮想スクロールにする（表示範囲の前後 10 行だけを描画する）。スマートフォンでは 20 件ずつのページングとカードにする。
- 見出しはボタンにして並べ替えられるようにし、`aria-sort` を付ける。下部には集計行（n、平均、最大）を固定する。
- 異常値はセルの背景色＋記号（⚠ / △）＋判定列の文字で示し、選択行の判定理由（どの閾値を超えたか）と来歴（元ファイルの何行目か）を表示する。
- キーボード: ↑↓ PageUp PageDown Home End で移動、1〜3 でタグ、0 でタグを消す。保存検索をボタンで置く。
- Don't: 数値を自由記述欄や添付ファイルに入れる（X5）。色の意味を利用者に設定させる。

### 段のリスト（ステッパー）
- 順序付きリストにし、現在の段に `aria-current="step"` を付ける。各段は「記号の丸＋段の名前＋状態の文字」で表示する。
- 権限のない段は消さずに「（院生以上）」と表示し、選べないことを示す。
- Don't: ノードを自由に配置するエディタだけで操作させる（KNIME の注記）。依存関係は自動で整列した表示に限る。

### 根拠パネル
- 折りたたみ（`<details>`）にし、既定では「入力の来歴」だけを開く。ほかに、使った式（Math IR）、エンジンと版、係数の出典、変更履歴、コメントがある。
- 図と出力の下には「この出力の入力: ジョブ・条件の版・データのハッシュ」の1行を必ず付ける。

### タブ
- `role="tablist"`、`tab`、`tabpanel` を使う。←→ で移動して選び、Home と End で端へ移る。選ばれていないタブは `tabindex="-1"` にする。

### ダイアログ
- `<dialog>` の `showModal()` を使う。開いたら最初の操作対象へフォーカスを移し、閉じたら開いたボタンへ戻す。Esc で閉じる。
- 再実行のダイアログには、条件の版・入力のハッシュ・エンジンの版・乱数シードを表示する。

### 通知（成功・注意・エラー・情報）
- 色・記号・ラベル文字の3つで示す: ● 成功、△ 注意、✕ エラー、ⓘ 情報。トーストは `role="status"` にし、失敗は `aria-live="assertive"` で読み上げる。
- 過去版の表示中は、全幅の状態バナー（`--info-bg`）を上部に固定し、「最新版に戻る」ボタンを付ける（P5）。

### チャート
- インラインの SVG に `role="img"` と、要点を書いた `aria-label` を付ける。同じ内容のデータ表を `<details>` で添える。
- 閾値は線種（破線・点線）と文字ラベル（△注意 35 / ⚠異常 55）で示し、異常点は ✕ の印で示す。系列は1色（`--chart-1`）を基本にする。
- 初期表示で大量のグラフを自動生成しない（X6）。

### 空状態・読み込み中
- 空状態には、理由と次の操作（「絞り込みを解除」）を必ず書く。
- 計算中は、出力の領域にスケルトンを出し、`role="status"` と「計算中」のラベルを付ける。

### ナビゲーション
- 主要5画面のナビゲーションは、デスクトップでは左の固定サイドバーにし、スマートフォンでは下部のナビゲーションにする。現在地は `aria-current="page"` で示し、太字・背景・線の3つで見せる。
- ヘルプは全ての画面で右上の同じ位置に置く（3.2.6）。

## 7. レスポンシブの規則

| 幅 | レイアウト |
|---|---|
| 1181px 以上 | サイドバー 196px＋作業画面の4領域（段・作業・根拠・ジョブ） |
| 761〜1180px | 根拠パネルを作業の下に回す。ダッシュボードのカードを全幅にする |
| 760px 以下 | 下部のナビゲーション（5項目、高さ 52px）。表はカード一覧にし、台帳は 20 件ずつのページングのカードにする。条件の編集は読み取り専用にする（学部生の測定入力だけはホームで行える） |

- 375px で横スクロールを出さない。長い文字列（ハッシュ・コマンド）は折り返し、`pre` は `white-space: pre-wrap` にする。
- 固定ヘッダーと下部ナビゲーションにフォーカスが隠れないよう、`scroll-padding-top` と `scroll-padding-bottom` を付ける（2.4.11）。

## 8. アクセシビリティの規則（WCAG 2.2 AA）

- コントラスト: 文字は 4.5:1 以上、UI 部品は 3:1 以上（2章の表を参照）。
- フォーカス: 全ての操作対象に、2px の `--focus` のリングを表示する（2.4.7）。
- スキップリンク、ランドマーク（header、nav、main、aside）、見出しの階層を付ける。F6 でパネルの間を移動できる。
- ターゲットの大きさは 24×24px 以上（2.5.8）。チェックボックスは 18px にし、ラベル込みで 28px の高さにする。
- ドラッグには代替手段を付ける（2.5.7）。列の並べ替えには ↑↓ ボタン、スライダーには数値の入力欄を付ける。
- エラーは特定して、直し方を提案する（3.3.1, 3.3.3）。冗長な入力は避ける（3.3.7）。
- 認証は学内のシングルサインオンかパスキーにし、パスワード欄への貼り付けを許可する。認知機能のテスト（画像の文字入力など）は使わない（3.3.8）。
- 状態変化は `aria-live` で読み上げる（成功は polite、失敗は assertive）。

## 9. D分類（大企業品質）との組み合わせ方

分類A の設計思想（密度・速さ・再現性）は保ったまま、D の品質基準を「仕組み」として重ねる。

| D の基準 | 分類A での取り入れ方 |
|---|---|
| トークンを一元管理する | 本書のトークンを JSON（Style Dictionary 等）に移し、CSS とグラフのライブラリへ自動で配る。状態色はロックし、研究室ごとに変えられるのはアクセントだけにする |
| コンポーネントを文書化する | 共通部品の画面（`#components`）を Storybook 相当に育てる。各部品に Do/Don't とアクセシビリティの確認項目を付ける |
| 自動テスト | axe によるアクセシビリティの検査、375px・1440px のスクリーンショットの差分、コントラストを計算するスクリプトを CI に入れる |
| 監査ログ・権限 | 版の履歴とハッシュを「監査ログ」として扱う。ただし承認は任意の機能にし、学内保存を既定にする（X7）。重い署名フローは必須にしない |
| 国際化 | 文言を辞書に分け、英語版の論文用書き出しに対応する。単位・数値の書式は locale で切り替える |
| 性能の予算 | 台帳は 10 万行まで仮想スクロールで 60fps を目標にし、初期表示の JS を 200KB 以下にする |

組み合わせるときの注意: D の「余白の大きいエンタープライズ調」を、そのまま入力画面に持ち込まない。行の高さ 24〜28px と本文 13〜14px は保つ。
