## 3. 実施した修正

### 修正1（prototype.html）: 「本文へスキップ」で別の画面に飛ばされていた（重大）

- 症状: スキップリンクは `href="#main"` だったが、このアプリは画面の切り替えをハッシュ（`#detail` など）で行っている。Enter を押すとハッシュが `#main` になり、ルーターがそれを知らない画面として扱ってダッシュボードに戻していた。修正前は、`#workspace` `#detail` `#settings` `#components` のどこで使っても `hash:"#main"`、フォーカスは `h-dashboard` になった。キーボード利用者が「本文へ行こう」とした結果、作業中の画面を失っていた。axe では見つからない。
- 修正: スキップリンクにクリック処理を追加した（ルーターの直後）。ハッシュは変えずに、今の画面の見出し（`#h-<route>`）へフォーカスを移してスクロールする。
- 再検査: dashboard → `#dashboard / h-dashboard`、workspace → `#workspace / h-workspace`、detail → `#detail / h-detail`、settings → `#settings / h-settings`、components → `#components / h-components`。全ルートで、画面はそのままでフォーカスだけが本文の見出しに移ることを確認した。

### 修正2（concepts.html）: スキップしてもフォーカスが本文に入らなかった

- 症状: `<main>` にフォーカスを受ける属性（`tabindex`）がなく、スキップ後のフォーカス先が `BODY` になっていた。ブラウザによっては次の Tab が先頭からやり直しになる。
- 修正: `<main id="main" role="main" tabindex="-1">` とし、`main:focus{outline:none}` を追加した。main は操作する部品ではないので、枠線は出さない。
- 再検査: スキップ後のフォーカス先が `main` になることを確認した。

## 5. 残っている課題（未解決・要手動確認）

1. 1.4.11（文字以外のコントラスト）を測色ツールで確認する。特にダーク配色での入力欄の枠線と、グラフの系列の線。
2. スクリーンリーダー（NVDA + Chrome、VoiceOver + Safari）での確認。画面切り替え時に見出しへフォーカスが移ったことが読み上げられるか、`aria-live` のトースト通知が重複して読まれないか。
3. 表（データグリッド）のセル単位のキーボード操作と、Excel 風の貼り付けが、キーボードだけで完結するかを手動で確認する。
4. モバイル実機で、下部固定ナビがフォーカス中の要素を隠さないか（2.4.11）。
5. concepts.html の縮小模型は、文字間隔を広げると文字が切れる。図であることを優先して `aria-hidden` のままとし、内容は figcaption の本文で補っている。厳密に対応するなら、模型を画像化するか、`role="img"` と要約ラベルを付ける。
6. 200% 拡大（1.4.4）と、ブラウザの文字サイズ設定を変えたときの表示は未検証。
