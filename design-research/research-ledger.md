### A-1-1 MATLAB（MathWorks。デスクトップ版 / MATLAB Online）

- **公式URL**: https://www.mathworks.com/products/matlab.html
- **何をするアプリか**: 数値計算・行列演算・可視化・アルゴリズム開発の統合環境。MATLAB Online はブラウザで動き、インストール不要。MATLAB Drive（無料5GB、ライセンス付きなら20GB）にファイルを保存し、GitHub・File Exchange・OneDrive・Amazon S3 と連携する。
- **主な利用者**: 工学系・理学系の教員、大学院生、学部生（授業・演習）、企業の研究開発エンジニア。
- **画面構成とナビゲーション**: 上部のツールストリップ（Home / Plots / Apps などのタブ）、Files パネル（ファイル操作）、Workspace パネル（作った変数や読み込んだデータの一覧）、Command Window（>> プロンプト）、サイドバー（ドッキングしたツールや追加パネル）からなる多ペイン構成。Live Script と Apps には、ほかのデスクトップ要素を隠して全画面で表示する Focused View がある。
- **配色・文字・余白・アイコン**: （公式ドキュメントの文章で確認した範囲）タブ式ツールストリップでコマンドを機能グループにまとめ、ペインを並べて情報を詰め込む。配色・フォント・アイコンの細部はこのセッションで画面画像を見ておらず、ここに書くのは事前知識による推測：白〜淡いグレー地に青系のアクセント、等幅フォントのコード領域、小型のモノクロ寄りアイコン。
- **優れている操作体験**: 変数をすぐに確認できる（Workspace パネル）。コマンド入力と GUI 操作を併用できる。Live Script でコード・出力・説明文を1つの文書にまとめられ、計算の根拠が残る。Focused View で作業内容に集中できる。ブラウザ版は環境構築が不要で、授業や学生の導入コストが低い。
- **使いにくい点・制約**: パネルとツールストリップのボタンが多く、初学者の学習負荷が大きい（一般的な評価で、本セッションでは未検証）。ライセンス費用と Toolbox ごとの機能差がある。MATLAB Online は計算資源（vCPU 数、16GB メモリ）とストレージの上限に制約される。
- **採用できる要素**: (1) 現在の変数・入力パラメータを常に見られる「ワークスペース」型サイドパネル（Math IR の中間変数・LCA 係数の一覧表示に応用）。(2) コマンド入力と GUI フォームの二重入力経路（上級者は式を直接入力、学部生はフォーム入力）。(3) コード・数式・結果・説明を1文書にまとめる Live Script 型のレポート（計算根拠の追跡と再現性）。(4) 作業内容だけを全画面表示する集中モード。(5) Git 連携とファイルストレージ連携。
- **採用すべきでない要素**: 機能を大量に詰め込んだ多段タブ式ツールストリップをそのまま採ること（研究室内部アプリでは操作を絞るべき）。Toolbox の有無で機能が出たり消えたりして、利用者が混乱する構成。商用製品固有の配色・アイコン・レイアウトの複製。
- **参考資料**: https://www.mathworks.com/products/matlab-online.html / https://www.mathworks.com/help/matlab/learn_matlab/desktop.html

### A-1-2 JupyterLab（Project Jupyter）

- **公式URL**: https://jupyter.org/
- **何をするアプリか**: ブラウザで動くオープンソースの対話型計算環境。ノートブック（コード・出力・Markdown）、テキストエディタ、ターミナル、コンソールをタブとパネルで並べて使える。拡張機能で機能を追加できる。
- **主な利用者**: データ解析を行う大学院生、研究者、学部生（授業）、データサイエンティスト。Python（SymPy 等）利用者との相性が良い。
- **画面構成とナビゲーション**: 中央のメイン作業領域にドキュメントやアクティビティをタブで開き、タブを中央や端へドラッグすると、サイズ変更できるパネルに分割できる。作業中のタブは上辺の色付きボーダーで示される。左サイドバー（折りたたみ可）には、ファイルブラウザ、開いているタブと稼働中のカーネル・ターミナルの一覧、コマンドパレット、目次、拡張機能マネージャーがある。右サイドバー（折りたたみ可）には、プロパティインスペクターとデバッガーがある。上部メニューは File / Edit / View / Run / Kernel / Tabs / Settings / Help。コマンドパレットは v3.0 以降モーダル表示。Simple Interface モードでは、ほかを閉じずに1つのドキュメントだけを表示できる。
- **配色・文字・余白・アイコン**: （ドキュメント本文で確認した範囲）作業中のタブは上辺の色付きボーダーで示される。それ以外の配色・フォント・余白・アイコンは画面画像を見ておらず、事前知識による推測：明るい背景と細い区切り線、控えめな青系アクセント、ダークテーマあり、セル左側の実行番号表示。
- **優れている操作体験**: 自由にパネルを分割して、データ・コード・グラフを並べて比較できる。コマンドパレットで全コマンドをキーボードから呼び出せる。目次パネルで長いノートブックを移動できる。Simple Interface で集中モードに切り替えられる。拡張機能で研究室固有の機能を追加できる。
- **使いにくい点・制約**: セルの実行順序が自由なため、隠れた状態が生じて再現性が損なわれやすい（一般的に知られた課題で、本セッションでは未検証）。カーネル管理や環境構築の概念が学部生には難しい。大量の表データを閲覧・編集する UI は標準では弱い。
- **採用できる要素**: (1) 分割可能な多パネル作業領域（入力条件・計算結果・グラフを並べて比較）。(2) キーボード中心のコマンドパレット（少ない操作で全機能を呼び出せる）。(3) 左に資源（ファイル・目次・実行中ジョブ）、右に選択対象のプロパティ、という役割の明確なサイドバー分担。(4) 作業中タブの明確な強調表示。(5) 単一ドキュメントの集中表示モード。
- **採用すべきでない要素**: 実行順序を自由にしすぎて、計算の依存関係が不透明になる設計（Math IR パイプラインでは依存グラフと実行履歴を明示すべき）。カーネルなどの実装概念を利用者にそのまま見せる UI。

### A-1-3 Origin / OriginPro（OriginLab Corporation）

- **公式URL**: https://www.originlab.com/
- **何をするアプリか**: 科学技術向けのデータ解析・グラフ作成ソフト（Windows デスクトップ）。ワークブック / ワークシートにデータを保持し、グラフウィンドウで出版品質の図を作る。OriginPro では高度な解析（ピークフィット・信号処理・統計など）が追加される。
- **主な利用者**: 物理・化学・材料・工学系の研究者、大学院生（論文図の作成）、企業の研究開発部門。
- **画面構成とナビゲーション**: Project Explorer（プロジェクトをフォルダ構造で表示）で、ワークブック・グラフ・マトリクスなどの子ウィンドウを管理する。各フローティングウィンドウには Object Manager パネルがある。選択した対象（グラフ・ワークシート・マトリクス）に応じて変わるミニツールバーを表示する。解析ダイアログは後から開き直して設定を変え、再計算できる。GUI モードは4種類、ダークモードあり。
- **配色・文字・余白・アイコン**: （公式ページ本文で確認した範囲）ダークモード、4種類の GUI モード、フローティングウィンドウ、文脈依存のミニツールバー。配色・アイコン・余白の具体的な見た目は画面画像を見ておらず、事前知識による推測：Windows 伝統型の多数ツールバーと MDI 風の子ウィンドウで、情報密度は高い。
- **優れている操作体験**: 入力データが変わると（再インポート時など）結果・グラフ・レポートが自動更新される（再計算・自動更新）。解析ダイアログを開き直してパラメータを変えられ、解析をやり直さずに済む。30以上の形式（CSV / Excel / HDF5 / NetCDF / DB）をインポートでき、ドラッグ＆ドロップで取り込み、元ファイルから再インポートできる。データコネクタは接続設定をワークシートに保存する。Excel がなくても Excel ファイルを取り込める。グラフ画像からデータを抽出する Digitizer。ミニツールバーで、ダイアログを開かずに主要な設定を変えられる。
- **使いにくい点・制約**: 機能が非常に多く、メニューやダイアログが深い階層になる（一般的な評価で、本セッションでは未検証）。Windows 中心で macOS 対応は限定的（事前知識）。有償ライセンス。
- **採用できる要素**: (1) 入力データ → 解析 → グラフ・レポートの依存関係を保持し、元データが変わると自動で再計算する仕組みと、「再計算が必要」を示す状態表示。(2) 解析条件を後から開き直して編集できる（計算条件の追跡と再利用）。(3) 元ファイルへのリンクを保持した再インポート（CSV / Excel 連携）。(4) 選択対象に応じた文脈依存ツールバー（少ない操作）。(5) 多形式インポートと Excel なしでの取り込み。
- **採用すべきでない要素**: 多数の固定ツールバーと深いダイアログ階層。子ウィンドウが散らばるウィンドウ管理（ブラウザアプリではタブやパネルで代替する）。製品固有の UI の複製。
- **参考資料**: https://www.originlab.com/ / https://www.originlab.com/index.aspx?go=Products/Origin

### A-1-4 LabArchives（電子実験ノート ELN。Dotmatics 傘下）

- **公式URL**: https://www.labarchives.com/
- **何をするアプリか**: クラウド型の電子実験ノート（ELN）。研究データを記録・整理・検索・共有する。ノートブックはページ単位で、カスタムテンプレート、化学構造の描画、画像注釈、DNA ファイルの閲覧（SnapGene 連携）を備える。関連製品に Inventory（試料・資源の管理）と Scheduler（機器・部屋の予約）がある。
- **主な利用者**: 大学・研究機関（中核市場）の PI・研究員・大学院生。授業向けの ELN for Education。企業や政府機関（FedRAMP 認証版）も対象。
- **画面構成とナビゲーション**: ノートブック → フォルダ → ページ → エントリーの階層構造で、フォルダツリーでナビゲーションする。ページ上部に New Entry ツールバーと Page Tools がある（Page Tools → View revisions でページの全変更履歴を開く）。各エントリーのツールバーのメニューから、そのエントリーの履歴表示・復元ができる。ウィジェットもエントリーの一種。

- **画面構成とナビゲーション**: 【公式で確認】グローバルルールに Navigation、Feedback、Data Entry、Data Display、Copywriting、Data Format、Buttons、Data List がある。テンプレートとして Visualization Page と Detail Page、リサーチテンプレートとして Form、Workbench、List、Result、Exception の各ページがある。【事前知識・未確認】ヘッダー＋サイドメニュー＋コンテンツのレイアウトと、パンくずリストによる階層ナビゲーション。
- **配色・文字・余白・アイコン**: 【公式で確認】Colors、Layout、Font、Icons、Dark Mode、Shadow、Visualization、Motion、Illustrations の各仕様ページがある。Certain の価値として、色値の変換やスペーシングの組版といったデザインルールを「オブジェクト」として扱い、主観的な判断を減らすとしている。【事前知識・未確認】8px グリッド、青系のプライマリカラー、14px の基本文字サイズ、アルゴリズムで派生させるトークン体系。
- **優れている操作体験**: 【公式で確認】Meaningful の価値として、明確な目標をサブ目標に分解し、すべての操作に即時フィードバックを返して結果を見えるようにする。難易度を利用者の習熟に合わせ、不要な要素を取り除いて作業に集中させる。原則として Stay on the Page（ページ内で完結させる）、React Immediately、Make it Direct、Keep it Lightweight、Provide an Invitation、Use Transition を掲げる。Result / Exception ページのテンプレートで、完了・失敗・権限なしの状態まで設計範囲に含めている。
- **使いにくい点・制約**: 価値（特に Natural や Growing）の記述は抽象度が高く、実装上の判断基準にそのまま落としにくい。導入ページは索引中心で、詳細は個別ページを読む必要がある。【事前知識・未確認】既定テーマのまま使うと、どの管理画面も同じに見える「Ant らしさ」が強く出る。コンポーネントが多く、依存とバンドルサイズが重くなりやすい。
- **採用できる要素**: Data Format ルール（数値・日付・単位の表記統一。LCA の CO2 換算値や単位表記に必須）。Result / Exception ページの標準化（計算完了・失敗・権限不足）。Stay on the Page に基づくインライン編集。すべての操作への即時フィードバック。色やスペーシングをルール（関数）として定義し、主観を減らすこと。
- **採用すべきでない要素**: 既定テーマをそのまま使った没個性な管理画面。トースト通知やモーダルの多用。抽象的な価値の文言だけを掲げて、具体的な判断基準に落とさないこと。

### D-2-6 AWS Cloudscape Design System

- **公式URL**: https://cloudscape.design/
- **何をするアプリか**: AWS が 2016 年に作ったオープンソースのデザインシステム。UI ガイドライン、React コンポーネント（122 個）、パターン（59 件）、デモ（33 件）、デザインリソース、開発ツールを提供し、Gen AI のセクションもある。
- **主な利用者**: AWS の各サービスチーム、および Cloudscape で業務・運用系の Web アプリを作る外部の開発者・デザイナー。最終利用者はクラウドエンジニアや運用管理者。
- **画面構成とナビゲーション**: 【公式で確認】Service navigation として、構造的なナビゲーションを担うサイドナビゲーションと、グローバルな操作を分けて置くトップナビゲーションがある。一覧と詳細の表示には Table view、Card view、Split view（一覧と分割パネル）、入れ子やグループ化された表がある。詳細ページには Details page、タブ付き、関連リソースのプレビューを並べるハブ型がある。ほかに Secondary panels、Service dashboard（固定型と、利用者が項目の表示・移動・サイズ変更をできる設定型）がある。
- **配色・文字・余白・アイコン**: 【公式で確認】Foundation に Colors、Spacing、Iconography、Visual modes（ライト／ダーク）、Theming、Accessibility、Responsive design がある。パターンに Density settings（利用者が表示密度を選べる）がある。【事前知識・未確認】具体的な書体、配色、visual refresh 後の角丸や余白の値。
- **優れている操作体験**: 削除をリスクに応じて3段階に分けている（低リスクは1クリック、作り直しにくいものは簡易確認、重大なものは追加確認）。未保存変更の警告、フィルタを URL に保持してビューを共有できること、保存済みフィルタセット、タイムスタンプ（相対／絶対）の指針、読み込みと再読み込み、空状態（リソースが無い場合と、フィルタに一致しない場合）、エラーメッセージと入力検証、作業中に開ける文脈ヘルプ、ベータ／プレビュー機能の告知、無効状態と読み取り専用状態の区別まで、パターンとして体系化している。「ブラウザ・画面サイズ・能力に関わらずすべての顧客のために設計」と明言している。
- **使いにくい点・制約**: AWS コンソールの外観と強く結びついていて、そのまま使うと AWS 製品に見えやすい。実装は React 中心。表やパネルが多い高密度の画面は、初めての利用者には負担が大きい。【事前知識・未確認】テーマのカスタマイズ範囲には制約がある。
- **採用できる要素**: リスク段階に応じた削除確認（LCA のプロジェクト、データセット、排出係数ライブラリの削除）。フィルタ状態の URL 保持と共有。表示密度の設定。Split view による一覧＋詳細。無効状態と読み取り専用状態の区別（権限・承認フローとの整合）。監査ログ向けのタイムスタンプ表記指針。設定型ダッシュボード。ベータ機能の明示。空状態を「データ無し」と「該当無し」で分けること。
- **採用すべきでない要素**: AWS コンソール特有のヘッダー配色や画面のつくりの模倣。すべての画面を表中心にすること。補助パネルを多用して主作業の領域を圧迫すること。
