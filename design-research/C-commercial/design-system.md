# C 分類（収益・利益追求型の商用アプリ）推奨デザインシステム

対象: （仮称）AirLCA Cloud — 採用案「案C アウトカム・ハブ」。実装見本は `prototype.html`（`#components` 画面にトークンと部品を表示）。料金・数値はすべてダミー。

> 確認レベル: 本書の原則は `principles.md`（台帳 12 件。料金ページ・公式文書は取得確認、画面構成の多くは事前知識による推測）に基づく。コントラスト比は WCAG 2.x の相対輝度式で計算した値。実ユーザーでの検証は未実施で、評価は専門家によるヒューリスティック評価の段階。

---

## 1. 設計思想

1. **成果物から始める**: ホームは機能一覧ではなく「今月作るもの」を出し、各成果物の完成度と次の 1 手を示す（原則 1・6）。
2. **課金理由が見える**: 数えられる量（センサー台数・レポート件数）を、ヘッダーの使用量メーターで常に見せる。上位プランへの移行は「成長したから必要になった」と感じられる形にする（原則 2）。
3. **誠実な収益化**: 料金・試用・解約は「設定 → プランと請求」の 1 か所に集める。表示は税込で、月額と年額を並べる。試用はカード不要で自動課金なし。解約は 2 操作で済み、上限を超えてもデータは消さない。ダークパターンは使わない（避けるべき設計 1〜7）。
4. **初心者のボタン、熟練者のキーボード**: 主要操作は常に見えるボタンで出す。同じ操作を Ctrl+K のコマンドパレットからも呼べるようにする（原則 7）。
5. **言葉を先に決める**: 「センサー」「レポート」「閲覧者」「編集者」「CO2e」などの用語を、画面・料金表・計測イベントで同じ意味で使う（原則 8）。
6. **独自ブランド**: 深いティールと琥珀の組み合わせ、葉と空気の流れを描いたマークを使う。他社の色やモチーフは真似しない（避けるべき設計 7）。

## 2. カラートークン

コントラスト比は白（#FFFFFF）に対する値。（ ）内はページ背景 #FAFAF7 に対する値。

| トークン | HEX | 用途 | コントラスト比 |
|---|---|---|---|
| `--color-bg` | #FAFAF7 | ページ背景（body に明示） | — |
| `--color-surface` | #FFFFFF | カード・ダイアログ・表 | — |
| `--color-surface-2` | #F1F3EE | 表見出し、沈んだ面 | 補助文字との比 6.78 |
| `--color-text` | #1C2430 | 本文・見出し | 15.62（14.94） |

| `--color-border` | #D9DDD6 | 装飾の区切り線。意味を持たせない | 1.38（装飾のため基準の対象外） |

| `--color-primary` | #0F6B5C | 主ボタン、リンク、選択状態 | 6.41（6.13）。白文字を載せた場合も 6.41 |

| `--color-focus` | #1D4ED8 | フォーカスリング（3px、2px 離す） | 6.70。淡色の面の上で 5.73 |

状態の淡色背景（`--color-good-soft` #E6F3EB、`--color-warn-soft` #FBF1DC、`--color-bad-soft` #FCE9E7）の上では、本文に `--color-text` を使う（13.4〜13.7）。状態色の文字を淡色背景に載せた場合も 4.6〜5.6 で、4.5:1 を満たす。

**ルール**
- 状態は色だけで伝えない。必ず「文言（良好／注意／要換気）」と「アイコンの形（丸／三角／八角形）」を併記する。
- 琥珀（accent）は「有料要素の事前表示」専用にする。警告には使わない（注意は `--color-warn`）。
- チャートの系列は、主色・補助文字色・良好色の 3 色までにする。それ以上は直接ラベルで区別する。
- ダークテーマは次の段階で用意する。同じトークン名のまま値を差し替える前提で、ここに挙げたトークン名は固定する。

## 3. タイポグラフィ

書体: `system-ui, -apple-system, "Hiragino Sans", "Noto Sans JP", "Yu Gothic UI", sans-serif`。数値は等幅 `ui-monospace`（`font-variant-numeric: tabular-nums`）。

| トークン | サイズ | 行高 | 用途 |
|---|---|---|---|
| `--fs-2xl` | 28px（スマホ見出し1は 22px） | 1.35 | 画面見出し（h1）、KPI 数値 |
| `--fs-xl` | 22px | 1.35 | 節見出し（h2） |
| `--fs-lg` | 18px | 1.35 | カード見出し（h3） |
| `--fs-md` | 16px | 1.7 | 本文（日本語は行高を広めにとる） |
| `--fs-sm` | 14px | 1.7 | 補助文、表、ボタン |
| `--fs-xs` | 13px | 1.5 | 注記・タグ（最小サイズ。これより小さくしない） |

見出し階層は h1 → h2 → h3 の順に飛ばさず使い、1 画面の h1 は 1 つにする。

## 4. 余白・グリッド

- 8px を基準にする（例外として 4px と 12px を使う）: `--space-1` 4 / `-2` 8 / `-3` 12 / `-4` 16 / `-5` 24 / `-6` 32 / `-7` 48。
- カード内の余白はデスクトップ 24px、スマホ 16px。カード同士の間隔は 16px、節同士の間隔は 32px。
- デスクトップ: 左レール 208px ＋ 本文（最大 1240px）。作成画面は「本文＋右の文脈パネル 380px」の 2 列にする。
- カードの並びは 3 列 → 2 列（1100px 以下）→ 1 列（768px 以下）と減らす。

## 5. 角丸・影・モーション

| トークン | 値 | 用途 |
|---|---|---|
| `--radius-sm` | 6px | 入力欄、小部品 |
| `--radius-md` | 10px | ボタン、通知 |
| `--radius-lg` | 16px | カード、ダイアログ |
| `--radius-pill` | 999px | タグ、使用量メーター、切替 |
| `--shadow-1` | 弱 | カード |
| `--shadow-2` | 強 | ダイアログ、トーストのみ |
| `--dur-fast` / `--dur-base` | 120ms / 200ms | ホバー、表示切替 |

`prefers-reduced-motion: reduce` のときは、すべてのアニメーションとトランジションを止める（スケルトンの光沢も静止させる）。祝福アニメーションや紙吹雪は使わない（原則 11: 達成表示は控えめにする）。

## 6. コンポーネント使用ルール（Do / Don't）

| 部品 | Do | Don't |
|---|---|---|
| ボタン（主・副・危険・無効・文字） | 主ボタンは 1 画面（または 1 カード）に 1 つ。高さ 44px 以上。危険ボタンは不可逆な操作（解約の確定など）だけに使う | 無効ボタンを理由なしに置く（隣に理由の文を添える）。「閉じる」を小さな文字リンクにする |
| アップグレード提案 | 提案と「閉じる」を同じ大きさ・同じ見た目（副ボタン）で並べる。価格（税込）と試用条件を文中に書く。閉じたら 30 日間は出さない | カウントダウン、「残りわずか」の表示、閉じるボタンを隠す、作業の途中に割り込むモーダル |
| 使用量メーター | 数字と単位をバーと一緒に出す（「2/3台」）。上限に達したら注意色にし、文言で状況を説明する | バーだけで見せる。上限に達したとき赤で煽る |
| 料金表 | 推奨プランを 1 つだけ示し、推奨の理由を書く。セルは「含む／制限付き（数値）／—」の語彙で書く。税込で、月額と年額を並べ、差額を金額で示す | ○×だけの表。年払い前提の金額を月額のように見せる。重要な条件を脚注に置く |
| フォーム | ラベルを常に表示する。ヘルプ文を `aria-describedby` で関連づける。エラーは「どこが・なぜ・どう直すか」を書き、最初のエラー欄にフォーカスを移す。前回値を初期値にし、登録済みの情報は再入力させない | プレースホルダーをラベルの代わりにする。色だけでエラーを示す |
| ダイアログ | `<dialog>` の `showModal()` で開き、最初の操作要素にフォーカスを移す。閉じたら開いた要素にフォーカスを戻す。Esc で閉じられるようにする | 解約の確認ダイアログで引き止めの割引を出す |
| タブ | `role=tablist/tab/tabpanel`。←→・Home・End で移動し、選ばれていないタブは `tabindex=-1` にする | 画面遷移の代わりにタブを使う |
| テーブル | `<th scope>` と `aria-sort` を使う。並べ替えボタンは見出しの中に置き、結果を `role=status` で読み上げる。スマホではカードリストに切り替え、並べ替えはセレクトで代替する | 初回から 10 列以上を出す（主要 5 列＋「詳細表示」にする） |
| チャート | インライン SVG に `role=img` と要約（title / desc / aria-label）を付け、同じ内容のデータ表を `<details>` で添える。点の形でも強調する | 色だけで系列や閾値を区別する |
| 平面図 | 部屋ごとに状態を「色＋アイコン形状＋文言＋数値」で示し、表の代替を付ける | ヒートマップの色だけで状態を示す |
| 通知（成功・警告・エラー・情報） | 左の太線、アイコン、「成功:」などの見出し語の 3 つを併用する | 色だけで区別する。自動で消えるトーストに重要な情報を載せる |
| 空状態 | 「何がないか」「次に何をするか」を書き、操作を 2 つまで置く（サンプルで試す／テンプレートから作る） | 白紙のまま出す |
| 読み込み中 | 2 秒以内に終わる処理はスケルトンで示す。読み上げ用に「読み込み中」を `role=status` で伝える | 画面全体のスピナーで操作を止める |
| コマンドパレット | Ctrl/⌘+K で開く。ヘッダーに常設ボタンを置き、↑↓・Enter・Esc で操作できるようにする | パレットからしか呼べない機能を作る |

## 7. レスポンシブ規則

| 幅 | ナビゲーション | レイアウト |
|---|---|---|
| 1101px 以上（基準 1440px） | 左レール（ピン留め・最近）＋上部ヘッダー | 3 列カード、作成画面は文脈パネル付きの 2 列 |
| 769〜1100px | 同上 | 2 列カード、文脈パネルは本文の下へ。料金表は 1 列 |
| 768px 以下（基準 375〜390px） | 下部タブ 4 つ（ホーム／データ／レポート／設定）＋全画面共通のヘッダー | 1 列。表はカードリストに切り替える。ヘッダーの使用量は数字だけにする。ホームは「要対応」と「完成度」を優先する（原則 10） |

- 375px で横スクロールを出さない（`overflow-wrap:anywhere`、`min-width:0`、SVG は `max-width:100%`）。試作は 375px 幅の iframe で全 5 画面を検査し、`scrollWidth ≤ viewport` を確認済み。
- 固定ヘッダーと下部ナビにフォーカスが隠れないよう、`scroll-padding-top` と `scroll-padding-bottom` を設定する。

## 8. アクセシビリティ規則（WCAG 2.2 AA）

- コントラスト: 文字 4.5:1 以上、UI 部品の境界とフォーカスリングは 3:1 以上（§2 の表を参照）。
- 2.4.7 / 2.4.11: フォーカスリングは 3px で、`:focus-visible` で表示する。固定要素の下にフォーカスが隠れないよう scroll-padding を設定する。
- 2.5.8: 操作対象は 44×44px を標準にする（最小 24px を大きく上回る）。表内の小ボタンも 36px 以上にする。
- 2.4.1: 最初のフォーカスで「本文へスキップ」を出す。ランドマークは banner / nav（2 つ。それぞれ名前を付ける）/ main / contentinfo。
- 画面を切り替えたら h1 にフォーカスを移し、`document.title` を更新する。
- 2.5.7: CSV のドラッグ＆ドロップには「ファイルを選ぶ」ボタンを必ず並べる。並べ替えはボタンとセレクトで行う（ドラッグ不要）。
- 3.2.6: ヘルプはすべての画面で、ヘッダー右端の同じ位置に置く。
- 3.3.1 / 3.3.3: エラーは欄を特定し、修正例を示す（例:「AQ- と 4 桁の数字にしてください（例: AQ-1003）」）。全角数字やカンマは受け付けて変換する。
- 3.3.7: 登録時に入力した事務所名や前回の部屋名を初期値にし、同じ情報を再入力させない。
- 3.3.8: ログインはパスキーまたはメールのワンタイムリンクにする。パスワード管理ツールの自動入力と貼り付けを妨げない。画像パズルや文字の書き写しは使わない。
- 2.3.3 / 2.2.2: `prefers-reduced-motion` に対応する。自動で動き続ける表示は置かない。
- 1.3.1: 表はすべて `<table>`、見出しセル、`<caption>` で組む。カードリスト表示でも `data-label` で列名を出す。
- `forced-colors`（Windows のハイコントラスト）でもボタン・カードの枠が見えるようにする。

## 9. 商用分類固有の規則（収益化と誠実さの両立）

1. **価格は触る前に見せる**: Pro の要素には、押す前に「Pro・税込 ¥4,980/月」のラベルを付ける（避けるべき設計 1）。
2. **試用条件は CTA の隣に書く**: 「カード不要」「自動課金なし」「データは残る」を、試用ボタンの直下に書く（原則 3）。
3. **契約状態を 1 枚のカードで示す**: プラン名、試用終了日、通知日、自動更新の有無、次回更新日をまとめて表示する。
4. **解約は 2 操作で完了させる**: 解約ボタンを押し、確認ダイアログで確定する。理由の入力は任意で、確定ボタンは理由を選ばなくても押せる。
5. **閲覧者は無料にする**: 共有ダイアログに「受け取る人は無料・登録不要」と書く。公開範囲の既定は「招待した人だけ」にする（避けるべき設計 3）。
6. **計測を設計に含める**: 操作要素に `data-analytics-event` を付け、`settings → 計測とプライバシー` に指標・定義・イベントの対応表を置く。計測はオフにでき、オフにしても機能は変わらない。「押しつけ度」（提案の閉じる率と、提案表示後の解約率）も監視対象にする。

## 10. D 分類（大企業品質）との組み合わせ方

C の誠実な収益化の仕組みは残したまま、D の品質基準を重ねる。

| 観点 | C 単独（本書） | C × D で追加すること |
|---|---|---|
| トークン | CSS 変数で約 25 個 | 3 層構造（基本値 → 意味 → 部品）にし、トークンをバージョン管理する。Figma 変数とコードを同期する |
| テーマ | ライトのみ（ダークは予定） | ダーク・ハイコントラスト・企業ブランドの差し替え（ホワイトラベル）を、トークンの差し替えで実現する |
| 権限 | Team の権限管理・監査ログ | SSO（SAML / OIDC）、SCIM、役割ごとの画面差分、監査ログの UI 規約を加える |
| 料金 | 3 プラン・セルフサーブ | Enterprise を「要相談」として 4 段目に置く。ただしセルフサーブの 3 段は変えない（段階を増やしすぎない） |
| 品質保証 | 手動の確認と iframe 幅検査 | ビジュアル回帰テスト、axe などによる自動 a11y 検査を CI に入れる。コンポーネントごとに a11y の受け入れ基準を書く |
| 国際化 | 日本語のみ | 文言を外部化する。文字数が 1.5 倍になっても崩れないレイアウトにする。通貨・税表示をロケール別にする |
| 計測 | 画面内ログ（外部送信なし） | 同意管理、イベントのスキーマ管理、データ保持期間の明示を加える |

どの組み合わせでも、ダークパターン禁止（§9）と WCAG 2.2 AA（§8）は譲らない。
