# C 分類 試作 `prototype.html` — 画面一覧と操作説明

対象: （仮称）AirLCA Cloud（採用案「案C アウトカム・ハブ」）。単一の HTML ファイルで、外部依存はない。ハッシュで画面を切り替える。データ・料金・事業所名はすべてダミーで、計測イベントは外部に送信しない（画面内のログに表示するだけ）。

> 確認レベル: 試作はヘッドレス Chrome で動作を確認した（JS エラーなし、375px 幅で全 5 画面の横スクロールなし、1440px で表示確認）。スクリーンリーダーの実機確認と、実ユーザーによるテストは未実施。料金や試用条件の設計は、台帳で取得確認した料金ページの原則に基づく。画面構成は事前知識による推測を含む原則から独自に設計したもので、既存製品の画面は複製していない。

## 全画面共通

| 要素 | デスクトップ（1440px） | スマートフォン（375〜390px） |
|---|---|---|
| ヘッダー | ロゴ、使用量メーター（センサー n/3 台・レポート n/1 件・プラン名、バー付き）、検索・操作（Ctrl+K）、ヘルプ | ロゴマークのみ、使用量は数字だけ、検索アイコン、ヘルプアイコン |
| ナビゲーション | 左レール（ホーム／作成／レポート／設定・プラン／部品とトークン）、ピン留め、最近 | 下部タブ 4 つ（ホーム／データ／レポート／設定）。部品一覧はフッターのリンクから開く |
| ヘルプ | ヘッダー右端の同じ位置（全画面共通） | 同左 |

**キーボード操作**
- `Tab` で移動し、最初の `Tab` で「本文へスキップ」が出る。
- `Ctrl+K`（Mac は `⌘+K`）でコマンドパレットを開く。`↑↓` で選び、`Enter` で実行、`Esc` で閉じる。
- `?` でヘルプを開く（入力欄にいるときは無効）。
- タブは `←→` で移動する。`Home` で最初、`End` で最後へ。
- 画面を切り替えると h1 にフォーカスが移り、ページタイトルも変わる。ダイアログを閉じると、開いたボタンにフォーカスが戻る。

## 1. `#dashboard` ホーム（今月つくるもの）

- **目的**: 初回は 3 ステップで最初のレポートを作る体験をしてもらう。継続利用時は「成果物の完成度」と「要対応」を一目で把握できるようにする。
- **主要操作**
  1. **初回オンボーディング（3 ステップ）**: ①作りたいもの（空気質の月次レポート／建材 LCA 比較／施主向けサマリー）を選ぶ → ②「サンプルデータで試す」（登録やセンサー設置の前に、架空の事務所のデータで仕上がりを確認できる） → ③結果を見る（完成度 80% のレポートが完成し、`activation` が記録される）。「あとで」で閉じても、ヘルプから再開できる。
  2. **空状態からの誘導**: レポートがないときは「サンプルで試す／テンプレートから作る」を表示する。
  3. **成果物カード**: 完成度のバー、未入力の項目、次の 1 手のボタンを並べる。Pro の要素には、押す前に価格ラベル（税込 ¥4,980/月）を付ける。
  4. **要対応**: 会議室B の CO2 が 1,240ppm で、改善案も示す。「対応済みにする」を押すと成功表示に変わる。
  5. **週推移チャート**: SVG の折れ線グラフ。第 3 週は四角い点で、基準超過を形でも示す。「データ表で見る」で同じ内容の表を開ける。
  6. **押しつけないアップグレード提案**: 「プランを比べる」と「閉じる（30 日間表示しない）」を同じ大きさで並べる。
- **デスクトップとモバイルの違い**: モバイルでは週推移チャートを隠し、要対応と完成度を優先する（チャートはレポート画面で見られる）。オンボーディングのステップは縦に並べる。

## 2. `#workspace` 作成（データをつなぐ・確認する）

- **目的**: 成果物に必要なデータを接続・確認する。上部に 3 段階の進み具合（データをつなぐ → 確認する → 共有する）を表示し、右の文脈パネルに「このレポートに必要なもの」を出す。
- **主要操作**
  - **タブ（センサー／建材 LCA／平面図）**: ARIA tablist で、矢印キーでも操作できる。
  - **センサー表**: 名前・CO2・PM2.5 の見出しボタンで並べ替える（`aria-sort` を更新し、結果を読み上げる）。「詳細表示」で温度・湿度の列を追加する（案A から取り込んだ要素）。「最新値を取得」でスケルトンを 1.2 秒表示する。「ピン留め」を押すと左レールに追加される。
  - **センサー追加フォーム**: ラベル、ヘルプ、エラーを常に関連づける。エラーは原因と修正例を示し、最初のエラー欄にフォーカスを移す。部屋と通知基準には前回値と推奨値を初期値として入れる。**4 台目を追加しようとすると**、Free の上限を説明する（追加はできないが、データは消えず、閲覧と書き出しは続けられる）。そのうえで「プランを比べる」と「閉じる」を同じ大きさで出す。
  - **CSV/Excel 取り込み**: ドラッグ＆ドロップに加え、「ファイルを選ぶ」ボタンでも同じ結果になる（2.5.7）。形式が違うときは、その旨と対処を示す。
  - **建材 LCA**: 表の中で数量を編集すると、CO2e、横棒グラフ、レポートの KPI がすぐに更新される。
  - **平面図**: SVG で描き、色・アイコンの形・文言・数値で部屋ごとの状態を示す。同じ内容の表も付ける（案B から取り込んだ要素）。
- **デスクトップとモバイルの違い**: デスクトップは本文と文脈パネルの 2 列。モバイルでは 1 列にし、表をカードリストに変え、並べ替えは「並べ替え」セレクトで行う。

## 3. `#detail` レポート（詳細・結果表示）

- **目的**: 完成したレポートの確認と共有。施主向けサマリーを兼ねる。
- **主要操作**
  - KPI カード 3 つ（CO2 の月平均、基準を超えた時間、建材案C の削減率）。状態はアイコンと文言を併記する。
  - 施主向けサマリーの平面図（SVG）と、代替の表。
  - 「PDF で書き出す（Free でも可）」。自社ロゴ入りは Pro で、価格を事前に表示する。
  - 「共有する」を押すとダイアログが開く。公開範囲の既定は「招待した人だけ」。閲覧者は無料で登録も不要と明記し、「AirLCA で作成」の表示は外せる。共有すると `share_link_created` が記録される。
- **デスクトップとモバイルの違い**: KPI は 3 列から 1 列に変わる。ダイアログのボタンはモバイルでは幅いっぱいに広がる。

## 4. `#settings` 設定（プランと請求／アカウント／計測とプライバシー）

- **目的**: 料金・試用・解約を 1 か所に集める。アカウント管理と計測の透明性も担う。
- **主要操作**
  - **試作用の切替**: 契約状態（Free／Pro 試用中／Pro 契約中）を切り替えて、各状態の表示を確認できる（実製品にはない）。
  - **現在のプラン**: Free は期限なし・自動で有料にならないことを示す。試用中は**試用終了日（2026年11月29日、ダミー）**、3 日前の通知日、**自動更新・自動課金なし**を示す。契約中は**自動更新あり**、次回更新日、7 日前の通知を示す。
  - **料金プランの比較**: 月払い／年払いの切替（年払いは差額を金額で表示）。Free ¥0／**Pro ¥4,980/月（おすすめは 1 つだけ。理由も表示）**／Team ¥3,480/編集者/月（3 名から、閲覧者は無料）。すべて税込のダミー価格。比較表は「含む／制限付き（数値）／—」の語彙で書く。
  - **解約**: 「プランを解約する」を押し、確認ダイアログで「解約を確定する」を押す、の **2 操作**で完了する。理由の入力は任意。「解約しない」と「解約を確定する」は同じ大きさ。ダイアログには、データは削除されないこと、更新日までは使えることを書く。コマンドパレットの「プランを解約する」からも直接ここへ来られる。
  - **アカウント**: メールアドレス（形式エラーには修正例を示す）、事務所名（登録時の値を再利用）。ログインはパスキーかワンタイムリンクで、認知機能テストは使わない（3.3.8）。
  - **計測とプライバシー**: 指標・定義・イベントの対応表、計測ログ（画面内のみ）、計測をオフにする切替、ダークパターンを使わないという約束。
- **デスクトップとモバイルの違い**: 料金カードは 3 列から 1 列（1100px 以下）。比較表と計測表はカードリストになる。タブ列は、要素の中だけで横スクロールする。

## 5. `#components` 部品とトークン

- **目的**: 共通部品とデザイントークンの一覧（`design-system.md` と対応）。
- **内容**: ボタン（主・副・危険・無効・文字）、成功・警告・エラー表示、フォームのエラー例（初期値 80 で「検証する」を押すとエラーが出る）、ダイアログ（フォーカス管理の例）、スケルトン、空状態、カラートークン表（HEX・用途・コントラスト比）、文字サイズ、余白、角丸・影。タブ・並べ替え表・チャート・サイドバー・下部ナビは、実際の画面で動作する。
