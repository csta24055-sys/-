# C 分類 — （仮称）AirLCA Cloud の UI コンセプト 3 案と評価

前提: `principles.md` の原則 1〜11 と避けるべき設計 1〜7 に基づく。料金・数値・事業所名はすべてダミー。視覚比較は `concepts.html` を参照。

## 比較軸の決め方

基本の 3 軸（実用性・効率／先進性・視覚的完成度／統合型）は維持する。ただし商用アプリでは「どの経路で売上が立つか」で UI の重心が変わるため、各案に**成長モデル**を対応づけた。

| 案 | 基本軸 | 成長モデル | 根拠 |
|---|---|---|---|
| 案A ワークベンチ | 実用性・効率 | 業務定着・席拡大型（使い込んだ担当者が社内に席を広げる） | Linear・Stripe・Airtable の「速さ／ピン留め／ビュー切替が継続価値」 |
| 案B ショーケース | 先進性・視覚的完成度 | ブランド・獲得型（見た目と共有物の美しさで新規を呼ぶ） | Canva・Miro・Duolingo の「テンプレートと視覚表現で初見の価値を伝える」 |
| 案C アウトカム・ハブ | 統合型 | プロダクト主導成長型（成果物の共有と量の上限で自然に有料化） | freee・Airtable・Figma・Notion の「透明な無料体験＋役割課金＋推奨 1 プラン」 |

3 案は色違いではなく、**ホームの起点**（A=データ一覧／B=建物ビジュアル／C=作る成果物）と**ナビゲーションの型**（A=左サイドバー＋コマンド／B=全画面キャンバス＋フローティングドック／C=上部ステップ＋文脈サイドパネル、スマホは下部タブ）が異なる。

---

## 案A ワークベンチ（実用性・効率重視）

- **基本思想**: 「毎日開く業務ツール」。センサーと建材データを高密度の表で扱い、熟練者の操作回数を最小にする。
- **想定利用者と主要タスク**: 設備・オフィス管理者、設計事務所の環境担当。①全拠点のセンサー異常を一覧で確認 ②建材データベースを検索して LCA 表を編集 ③月次レポートの一括出力。
- **代表的な画面構成**: 左サイドバー（ホーム／センサー／建物／建材 DB／レポート／ピン留め／最近）＋上部フィルタバー＋中央の表（行＝センサーまたは建材）＋右の詳細パネル。ホームは KPI 4 つ（平均 CO2、要換気の部屋数、今月の CO2e 削減量、未生成レポート）と要対応リスト。
- **ナビゲーション**: 2 段サイドバー（日常業務／製品別）、Ctrl+K コマンドパレット、`?` でショートカット一覧。すべての操作にボタンも用意。
- **配色・フォント・余白**: 背景 `#FFFFFF`、面 `#F4F6F8`、文字 `#1F2933`、補助文字 `#4B5563`、主色 `#0B5F8A`（白背景で約 6.9:1）、境界 `#D4D9DF`、状態 良好 `#1E7B4C`／注意 `#8A5A00`／要換気 `#B42318`（いずれも文言併記）。書体 system-ui＋Noto Sans JP、数値は等幅（ui-monospace）。余白 4px 基準、行高 32px のコンパクト表。
- **情報表示の密度**: 高（1 画面 25〜40 行）。初回のみ「おすすめビュー」で列を 5 列に絞る。
- **グラフ・表・入力フォーム**: 表が主役。行内スパークライン、列ごとの並べ替え・固定。グラフは詳細パネルで折れ線（CO2・PM2.5・温湿度）。フォームはインライン編集、前回値を初期値にする賢いデフォルト。
- **デスクトップとスマホ**: デスクトップは 3 ペイン。スマホは表をカードリストに変換し、閲覧とアラート対応のみ（編集はデスクトップ誘導）。
- **アクセシビリティ**: 全操作キーボード可、表は `<table>` と見出しセル、フォーカスリング 2px、状態は色＋文言＋アイコン形状。課題は高密度による文字の小ささ（最小 13px）。
- **採用技術と実装難易度**: React＋TanStack Table（仮想スクロール）、uPlot 等の軽量グラフ、Python バックエンド（既存 LCA 演算子・Math IR を API 化）。難易度: 中。
- **料金導線**: プラン上限は設定画面と右上の使用量メーターで常時表示。席追加は管理画面から。
- **メリット**: 継続利用者の作業時間が最短。拡張（列・ビュー追加）しやすい。B2B の席拡大と相性がよい。
- **デメリット**: 初見で価値が伝わりにくく、無料登録直後の離脱が多くなりやすい。ブランドの独自性が出にくい。

## 案B ショーケース（先進性・視覚的完成度重視）

- **基本思想**: 「建物が呼吸しているのが見える」。建物の平面図・断面図の上に空気質と CO2e を重ね、施主に見せたくなる表現で差別化する。
- **想定利用者と主要タスク**: 設計事務所の代表・営業担当、工務店。①施主向けプレゼンで建物の空気質と環境性能を見せる ②テンプレートから美しい LCA レポートを作る ③共有リンクで送る。
- **代表的な画面構成**: 全画面の建物キャンバス（部屋ごとに状態を色＋ラベル表示）、下部フローティングドック（ビュー／時間スライダー／共有）、右上に「ストーリー」（自動生成された説明カード）を順にめくる。レポートは雑誌風レイアウト。
- **ナビゲーション**: プロジェクトギャラリー（大サムネイル）→ 建物キャンバス → ストーリー。階層は浅いが、機能はドックとコンテキストメニューに隠れる。
- **配色・フォント・余白**: 背景 `#0E1A2B`（濃紺）、面 `#16263D`、文字 `#E8EEF6`、補助文字 `#A9B8CC`（背景で約 8.7:1）、主色 ミント `#5EEAD4`、強調 `#FBBF77`、状態 良好 `#6EE7A8`／注意 `#FCD34D`／要換気 `#FCA5A5`（暗背景で文言併記）。見出しは太めの system-ui（700）、本文 16px、余白 8px 基準で広め（セクション間 48px）。
- **情報表示の密度**: 低（1 画面に主要メッセージ 1 つ）。
- **グラフ・表・入力フォーム**: 平面図ヒートマップ、時間アニメーション、CO2e の積み上げを建物シルエットで表現。表は折りたたみ。フォームは会話型ウィザード（1 画面 1 質問）。
- **デスクトップとスマホ**: デスクトップは大画面キャンバス。スマホは縦スワイプのストーリー表示で、施主がリンクから閲覧する体験を重視。
- **アクセシビリティ**: アニメーションは `prefers-reduced-motion` で停止、キャンバスには同内容の表を代替提供（必須）。課題: ヒートマップは色覚多様性への配慮が難しく、キャンバス操作はスクリーンリーダーで再現しにくい。
- **採用技術と実装難易度**: WebGL/Canvas（three.js 等）、SVG 平面図、IFC 等の建物データ読込、動画書き出し。難易度: 高。
- **料金導線**: 高品質テンプレートと書き出しを Pro に。共有リンクの閲覧は無料で、閲覧画面に控えめな「AirLCA で作成」表示。
- **メリット**: 第一印象と差別化が最も強い。共有物が広告になる。
- **デメリット**: 日常の監視・編集が遅い。実装・保守コストが高く、性能問題が出やすい。視覚に頼るため情報の正確な読み取りとアクセシビリティに弱い。

## 案C アウトカム・ハブ（統合型／プロダクト主導成長）— 採用案

- **基本思想**: 「作りたい成果物から始める」。ホームは機能一覧ではなく「今月作るもの」（空気質月次レポート／建材 LCA 比較／施主向けサマリー）で、各成果物の完成度と次の 1 手を示す。データ画面（案A の表）とビジュアル（案B の平面図）は成果物を作る途中で必要な分だけ開く。
- **想定利用者と主要タスク**: 小規模設計事務所・工務店の実務者（1〜10 名）、オフィス管理者。①テンプレートを選んでセンサーと建材データを流し込み、10 分で最初のレポートを作る ②アラート（CO2 1,000ppm 超など）に対応 ③施主・テナントに共有。
- **代表的な画面構成**: 上部に 3 ステップのプログレス（データをつなぐ → 確認する → 共有する）、中央に成果物カード（完成度バー・未入力項目・次の操作ボタン）、右に文脈サイドパネル（いま必要なデータ表または平面図）。右上に使用量メーター（例: 「センサー 2/3 台・レポート 0/1 件（Free）」）と「プランを見る」。
- **ナビゲーション**: デスクトップは細いアイコン＋ラベルの左レール（ホーム／モニター／LCA／レポート／設定）＋上部ステップ。スマホは下部タブ 4 つ（ホーム／アラート／レポート／アカウント）と、全タブ共通のヘッダー。Ctrl+K も用意。
- **配色・フォント・余白**: 背景 `#FAFAF7`、面 `#FFFFFF`、文字 `#1C2430`、補助文字 `#4A5563`、主色 `#0F6B5C`（深いティール。白背景で約 6.4:1）、強調 `#B45309`（琥珀。白背景で約 5.0:1、Pro ラベル用）、境界 `#D9DDD6`、状態 良好 `#1E7B4C`／注意 `#8A5A00`／要換気 `#B42318`（文言＋アイコン形状を併記）。書体 system-ui＋Hiragino Sans／Noto Sans JP、数値は等幅。余白 8px 基準、カード内 16〜24px、本文 15〜16px。
- **情報表示の密度**: 中。ホームは低〜中、文脈サイドパネルと LCA 編集画面は中〜高（利用者が「詳細表示」に切替可能）。
- **グラフ・表・入力フォーム**: 成果物カードに小さな要約グラフ（CO2 の週推移、建材別 CO2e の横棒）。表は「主要 5 列＋列追加」。入力は段階的フォーム（必要な項目だけ）、CSV/Excel のドラッグ＆ドロップ取り込み、前回値を初期値に。
- **デスクトップとスマホ**: デスクトップで作成・分析、スマホで確認・即応・共有（原則 10）。スマホのホームは「要対応 1 件」と「今月のレポートの完成度」のみ。
- **アクセシビリティ**: WCAG 2.2 AA 目標。コントラスト 4.5:1 以上、タップ領域 44px 以上、状態は色＋文言＋形状、平面図には表の代替、ランドマークと見出し階層、キーボード操作、`prefers-reduced-motion` 対応。
- **採用技術と実装難易度**: React（または Svelte）＋デザイントークン（CSS 変数、用途つき段階スケール）、軽量グラフ、SVG 平面図（WebGL は使わない）、決済・試用・解約は Stripe Checkout／顧客ポータル相当のホスト型を採用（原則・避けるべき設計 7）。計測は自前イベント（`principles.md` の指標表）。難易度: 中〜やや高（成果物モデルの設計が肝）。
- **料金導線（ダミー価格・税込）**: Free ¥0（センサー 3 台・LCA レポート月 1 件・閲覧者無制限・データ保持無期限）／**Pro ¥4,980/月**（推奨: センサー 20 台・レポート無制限・自社ロゴ）／Team ¥3,480/編集者/月（3 名から・閲覧者無料・権限管理）。年払いは 2 か月分割引を金額で併記。試用: Pro 14 日、カード不要、終了 3 日前に通知、自動課金なし、データは引き継ぐ。上限到達時は「追加できません／既存データは閲覧・書き出し可」と表示し、アップグレードと「閉じる」を同じ大きさで並べる。解約は 設定 → プラン → 解約 の 2 操作。
- **メリット**: 初回体験・継続・収益化の 3 つを 1 つの情報構造（成果物）でつなげられる。料金上限が使用量メーターとして常に見え、課金理由が明確。
- **デメリット**: 「成果物」という概念設計を誤ると自由度が下がる（テンプレート外の使い方に弱い）。A の高速性・B の華やかさはそれぞれの単独案に及ばない。

## 評価

### 評価基準と重み（C 分類向け、合計 100%）

商用アプリでは「初回利用体験」と「収益化への貢献」が事業の成否を直接左右するため重くし、実装保守コストと拡張性はやや軽くした。

| 評価基準 | 重み |
|---|---|
| 操作効率 | 8% |
| 学習の容易さ | 10% |
| 情報の理解しやすさ | 10% |
| 視覚的完成度 | 7% |
| アクセシビリティ | 8% |
| 拡張性 | 6% |
| 実装保守コスト（高得点＝低コスト） | 6% |
| 目的への適合性 | 10% |
| 収益化への貢献可能性（分類固有） | 13% |
| 初回利用体験（分類固有） | 12% |
| 継続利用のしやすさ（分類固有） | 10% |
| **合計** | **100%** |

### 採点（1〜5 点）と加重合計

加重合計 = Σ(点数 × 重み) ÷ 100（5 点満点）。

| 評価基準（重み） | 案A ワークベンチ | 案B ショーケース | 案C アウトカム・ハブ |
|---|---|---|---|
| 操作効率（8） | 5 | 2 | 4 |
| 学習の容易さ（10） | 3 | 4 | 4 |
| 情報の理解しやすさ（10） | 3 | 4 | 5 |
| 視覚的完成度（7） | 3 | 5 | 4 |
| アクセシビリティ（8） | 4 | 3 | 4 |
| 拡張性（6） | 4 | 3 | 4 |
| 実装保守コスト（6） | 4 | 2 | 3 |
| 目的への適合性（10） | 3 | 3 | 5 |
| 収益化への貢献可能性（13） | 3 | 3 | 5 |
| 初回利用体験（12） | 2 | 5 | 4 |
| 継続利用のしやすさ（10） | 4 | 3 | 5 |
| **加重合計（5 点満点）** | **3.34** | **3.44** | **4.37** |

計算: 案A = (40+30+30+21+32+24+24+30+39+24+40)/100 = 3.34、案B = (16+40+40+35+24+18+12+30+39+60+30)/100 = 3.44、案C = (32+40+50+28+32+24+18+50+65+48+50)/100 = 4.37。

### 採用案: 案C アウトカム・ハブ

理由:
1. **課金理由が UI の構造そのものに埋め込まれている**: 成果物（レポート）の件数とセンサー台数という「数えられる量」が使用量メーターとして常に見え、上位移行が「成長の結果」になる（原則 2・5）。閲覧者無料の共有で獲得経路も持つ。
2. **初回体験と継続を同じ情報構造で扱える**: 初回はテンプレートで 1 件目のレポート、2 回目以降は「今月のレポート」の更新という同じ動線で、継続理由が蓄積価値になる（原則 1・11）。
3. **ダークパターンを構造的に避けやすい**: 料金・試用条件・解約導線を 1 か所（設定 → プラン）に集約し、上限到達時もデータを消さない方針を UI 文言で約束できる（避けるべき設計 1〜4・7）。
4. 初回利用体験の単独点は案B が上回るが、案B は実装コストとアクセシビリティの弱さ、日常業務の遅さが継続率・解約率に響くと判断した。

### 不採用案から取り込む要素

- **案A から**: コマンドパレット（Ctrl+K）とショートカット、ピン留め・最近の履歴、文脈サイドパネル内の高密度表（「詳細表示」切替）、インライン編集と賢いデフォルト値、等幅数値。→ 熟練者の継続と Team 席拡大を支える。
- **案B から**: 共有リンクで開く施主向けサマリーの視覚表現（SVG 平面図の部屋別状態表示、建物シルエットの CO2e 積み上げ）をレポートテンプレートの 1 種として採用。ただし WebGL は使わず、必ず表の代替を付ける。公開ページの控えめな「AirLCA で作成」表示（閉じられる・誤認させない）。
- **共通の受け入れ基準**: 試用はカード不要・自動課金なし・終了 3 日前通知、解約 2 操作以内、アップセルの「閉じる」は同じ大きさ、料金は税込・月額と年額を併記、上限超過でもデータは閲覧・書き出し可。

### 確認レベルの注記
本評価は台帳 12 件の記述（料金ページ等は取得確認、画面構成の多くは事前知識による推測）と、本チームの設計判断に基づく。実ユーザーによる検証は未実施で、採点は専門家評価（ヒューリスティック）の段階である。次段階で 5 名程度の想定利用者によるタスクテスト（最初のレポート作成までの時間、料金プランの理解度テスト）を推奨する。
