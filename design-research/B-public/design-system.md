# B分類 推奨デザインシステム「公開データ 3層」（試作 v0.1）

対象: 国家規模・公共性の高いプロジェクト向けアプリ（B分類）。採用案C「段階的開示・3層レイヤー型」を実装した `prototype.html` から抽出した。原則番号（P1〜P11）と避けるべき設計（X1〜X7）は `principles.md` を参照。データ・地名・数値はすべて架空で、出典は『環境データ公開基盤（ダミー）』。

確認レベル: コントラスト比は Python で計算し（下表）、画面上でも同じ計算式で実測値を表示している（`#components`）。ヘッドレス Chrome で 1440px と 375px（iframe 内）を描画し、全6画面で横スクロールが無いこと（scrollWidth = clientWidth）と JS エラーが無いことを確認した。スクリーンリーダー・実機・利用者による試験は**未実施**。

---

## 1. 設計思想

1. **同じページ・同じ URL・同じ根拠**: 一般市民と専門家を別サイトに分けない（X5）。第1層「いまの状況」（結論と行動）→ 第2層「くらべる」（図表と比較）→ 第3層「根拠とデータ」（方法・出典・取得）の順に深くなる（P7）。
2. **運営主体を最初の1行で示す**: 公的に見える画面ほど、政府サービスではないことを識別帯で明示する（P1・X1）。
3. **色は意味の一部でしかない**: 区分は「色＋記号＋区分名＋数値範囲＋意味＋行動」で伝える（P2・X3）。
4. **欠損・速報・推計も正式な値として扱う**: 欠損をゼロや良好として表示しない（P4・X7）。
5. **JS は拡張として載せる**: JS が無くても全画面・全層が展開された状態で読める（P8・X2）。
6. **表が正、図は表から作る**: チャートは同じ画面の表データから描画する。図・地図・表・CSV・API は同じ条件を共有し、URL で再現できる（P5）。

## 3. タイポグラフィ

書体は端末内の UD 系を優先する（`BIZ UDPGothic` → ヒラギノ → Noto Sans JP → 游ゴシック → メイリオ）。Web フォントは読み込まない（低帯域・長期維持のため）。

| トークン | サイズ | 用途 |
|---|---|---|
| `--fs-xxl` | 36px | 第1層の主要数値（23 µg/m³） |
| `--fs-xl` | 28px | 画面見出し h1 |
| `--fs-l` | 22px | 層見出し h2・第1層の結論文 |
| `--fs-m` | 18px | 第1層の本文（案Aから取り込み） |
| `--fs-s` | 16px | 標準本文 |
| `--fs-xs` | 14px | 第3層の表・注記（これより小さくしない） |

行間は本文 1.75、見出し 1.35。単位は rem で指定し、文字サイズ切替（標準 100%／大 112.5%／特大 137.5%）でページ全体が拡大する。日付は ISO 8601（2026-11-15）、単位は SI 記法（µg/m³、ppm、kg-CO2e/m²）（P9）。

## 4. 余白・グリッド

- 8px グリッド: `--space-1` 4px、`-2` 8、`-3` 12、`-4` 16、`-5` 24、`-6` 32、`-7` 40（層の間）、`-8` 48、`-9` 64。
- 最大幅 1360px。デスクトップは「サイドバー 264px＋本文」の 2 カラム。地域画面は第1層 5：第2層 7 の 2 カラムで、第3層は全幅。
- 操作領域: 主要操作 48px（`--target-min`）、絶対下限 24px（`--target-floor`、WCAG 2.5.8）。

## 5. 角丸・影・モーション

- 角丸: `--radius-s` 4px（タグ・状態ラベル）、`-m` 8px（ボタン・入力欄）、`-l` 12px（カード・層・ダイアログ）、`-pill`（区分バッジ）。
- 影: `--shadow-1`（カード）、`--shadow-2`（ダイアログ・ドロワー）。軽量表示では影を消し、代わりに 2px の黒枠にする。
- 動き: `--dur-fast` 120ms、`--dur` 200ms。`prefers-reduced-motion` または「動きを減らす」設定で 0ms にし、スケルトンのきらめきも止める。動きで情報を伝えない。

## 6. コンポーネント使用ルール（Do / Don't）

| 部品 | Do | Don't |
|---|---|---|
| 識別帯 | 全画面の最上部に固定。運営主体・非公式であること・出典を書く | 操作ボタン・広告・外部企業リンクを入れる。政府ロゴや公式バナーを模倣する（X1） |
| 緊急帯 | 識別帯と別部品にする。対象地域・発表時刻・行動・**対象外の地域**を書く。訓練時は「訓練用」と明記 | 色だけで深刻度を示す。識別帯と同じ見た目にする |
| 区分バッジ | 色＋記号（●▲◆■／）＋区分名＋範囲を一体で表示 | 色の丸だけを置く（X3） |
| 状態ラベル | 速報値（破線枠）・確定値（実線枠）・推計値（斜体）を文字で書く | 速報値を確定値と同じ見た目で出す（X7） |
| 層（details） | 第1層は常に開く。第2層は初期で開き、第3層は一般向けでは閉じ、専門家向けでは開く。JS 無しでは全層が開く | 層の順番を画面によって入れ替える |
| 層ナビ | 3 つの層を番号付きで常に表示し、現在の層を `aria-current` と塗りで示す。第1層へ 1 操作で戻れる | ハッシュを書き換えて URL の条件を壊す（ジャンプは JS で行い、URL は変えない） |
| ボタン | 主ボタンは 1 画面に原則 1 つ。無効ボタンには理由を併記。危険な操作は確認ダイアログを通す | 理由の無いグレーアウト |
| フォーム | ラベル・ヒント・エラーを `aria-describedby` でつなぐ。エラーは要約（リンク付き）＋欄ごとの文言で、**直し方の例**を書く。全角数字も受け付ける | プレースホルダーだけでラベルを代用する。エラー時に入力を消す |
| 1画面1問 | 市民の手続き（通知登録）で使う。前の画面で選んだ地域を初期値にする（3.3.7） | 専門家の比較画面に適用する（X6） |
| タブ | ARIA tablist、←→ / Home / End、選択中だけ Tab 順に入る。表示切替（グラフ／地図／表）は同じ条件を共有 | タブごとに別の条件を持たせる |
| テーブル | 見出しのボタンで並べ替え、`aria-sort` で状態を伝える。データなしは常に最後 | 欠損を 0 として並べる |
| チャート | 「この図が言っていること」1 文、凡例（線種・記号）、基準線にラベル、欠測は線を途切れさせて「欠測」と書く。同じ内容の表と代替テキストを必ず持つ | 色だけで系列を区別する。画像だけで出典を落とす |
| 根拠ブロック | 定義・単位・期間・出典・状態・次回更新・ライセンス・処理方法を同じ順番で図の直下に置く（P3） | 出典をページ末尾にまとめて図から切り離す |
| ダイアログ | `<dialog>`＋`showModal()`。開くと中の最初の操作（危険操作では「やめる」）にフォーカス、閉じると開いたボタンに戻す。Esc で閉じる | 重要な判断を時間制限付きで迫る |
| 空状態 | 何が無いか・なぜか・次の一手（例・ボタン）を書く | 「該当なし」だけを出す |
| スケルトン | 読み込み中は `role="status"` で文字でも伝える。動きを減らす設定では静止 | スピナーだけで終わりを示さない |
| ダウンロード | 「表示中のデータ」と「全データ」の 2 段階。CSV に出典・ライセンスを書き込む。欠測は `NA` | 表示中の部分だけを全データのように見せる |

## 7. レスポンシブ規則

| 幅 | ナビゲーション | レイアウト | 表 |
|---|---|---|---|
| 1024px 以上 | 上部主要メニュー＋左サイドバー（固定） | 2 カラム。第1層と第2層を横並び | 表 |
| 640〜1023px | 上部主要メニュー＋「メニュー」ボタンでドロワー（Esc・背景タップで閉じ、フォーカスを閉じ込める） | 1 カラム | 表 |
| 639px 以下 | 下部タブ 5 項目（ホーム／地域／建物／方法／設定）＋ドロワー。ヘッダーは追従させず（画面の半分を占めないため）、層ナビだけが上部に追従 | 1 カラム。層ナビは番号の下に文字 | **カードリスト**（`data-label` を見出しにする）。並べ替えは選択欄で行う |

- 375px で横スクロールを出さない（長い URL・コードは `pre-wrap`＋`break-all`、SVG は `width:100%`）。
- 文字サイズ「特大」や 200% 拡大でも 1 カラムに再配置される。

## 9. D分類（大企業品質）の基準との組み合わせ方

B は「誰に対しても誤解なく、長く公開し続ける」ことを優先し、D は「大規模な組織で品質を一定に保つ」ことを優先する。組み合わせるときは次のように分担する。

1. **トークンの階層化**: 本書のトークンを「意味（semantic）」層とし、D 側のブランド・プリミティブ層（色の原液）から参照する。B のルール（フォーカス専用色、状態色の三重表示、装飾用罫線を UI に使わない）は意味層で固定し、ブランド変更で崩れないようにする。
2. **コンポーネント単位の達成基準台帳**: D の部品カタログに、部品ごとの WCAG / JIS X 8341-3 達成基準・試験日・試験方法（自動／支援技術／利用者）を必須項目として加える（P10）。
3. **バージョンと変更履歴**: 文書・デザイン・コード別の更新履歴と非推奨期間を D の運用に合わせる。B 固有の要件として、恒久 URL・リダイレクト・終了時のデータ保存方針を公開する（P11）。
4. **品質ゲート**: D の CI に、コントラスト計算、375px での横スクロール検査、JS 無効時の本文表示検査、`lang` 検査、欠損値の表示検査（0 として描画していないか）を加える。
5. **中立性の監査**: 商用（C）の部品を流用する場合、特定企業・製品への誘導（ランキング、アフィリエイト、寄付バナー）を主要導線に置かないことをレビュー項目にする。
6. **多言語の運用**: 翻訳を後付けにせず、文言キー（`data-i18n`）を部品の仕様に含め、D の翻訳ワークフローに乗せる（P9）。

## 10. 未確定事項

- 区分の閾値・注意報の基準はダミーである。実運用では公的基準と一致させ、出典を示す必要がある。
- 英語・やさしい日本語は主要部分（ヘッダー・層名・第1層・ナビ）のみ翻訳した。
- ダークモードは未対応。災害時の軽量表示（高コントラスト）を優先した。
- 地図はタイル型の抽象配置で、実際の地理形状ではない。
