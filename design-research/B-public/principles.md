# B分類（国家規模・公共性の高いプロジェクト向けアプリ）— 設計原則

対象題材: 全国・自治体別の大気質（PM2.5・光化学オキシダント）と公共建築物の環境性能（LCA・CO2排出量・省エネ性能）の公開ダッシュボード（データは全てダミー、出典は架空の『環境データ公開基盤（ダミー）』）。

根拠は調査台帳 `data/ledger-B-1.json`（デザインシステム6件）と `data/ledger-B-2.json`（公共データ・公共サービス6件）の計12件。以下は事例紹介ではなく、複数事例に共通して現れた「なぜ効くのか」を設計判断のルールとして書き直したものである。

## 1. 共通する優れた設計原則（11項目）

### P1. 「公式らしさ」ではなく「運営主体の識別」を全ページ最上部に固定する
- **ルール**: 全ページの最上部に「識別帯」を置き、運営主体（例: ○○大学 △△研究室）・本サービスが政府サービスではないこと・データ出典・連絡先を示す。識別帯には操作ボタン・広告・外部企業リンクを入れない。内部フロー・完了画面・印刷・エラー画面でも省略しない。
- **根拠**: SGDS の Masthead（全ページ必須・最上部・改変禁止・操作の混在禁止）、USWDS の設計原則「Earn trust」と Identifier、DADS・GOV.UK・NHS・GC の台帳がいずれも「政府ブランドの模倣は誤認を招く」と指摘している点。
- **本題材への適用**: 公共的な見た目でありながら、大学研究であることを最初の 1 行で明示する。これが「信頼」と「誤認防止」を両立する唯一の方法。

### P2. 指標は「数値・区分名・色・意味・推奨行動」の5点セットで伝え、色単独に頼らない
- **ルール**: PM2.5 等の区分は常に「区分名＋数値範囲＋色＋形（記号/模様）＋平易な意味＋推奨行動」を一体で表示。影響を受けやすい人（高齢者・子ども・呼吸器疾患のある人）向けの区分とメッセージを独立させる。
- **根拠**: AirNow の「数値→色→言葉→行動」の一貫した対応と Sensitive Groups 区分、GOV.UK のエラー/成功専用色をテキストでも伝える運用、DADS のコンポーネント単位のアクセシビリティ達成基準。
- **本題材への適用**: 「区分2 やや注意 ▲ 14〜35 µg/m³（ダミー区分）: 屋外での長時間の激しい運動は控えめに」。CO2 排出量でも「基準値比 −22%（良い方向）」と方向を言葉で書く。

### P3. すべての図表に定型の「根拠ブロック」を付ける
- **ルール**: グラフ・地図・表の直下に、定義・単位・対象期間・出典・管理者・最終更新日・次回更新予定・ライセンス・処理方法へのリンクを同じ順番・同じ見た目で置く。転載されても出典が失われないよう、画像出力にも出典とライセンスを焼き込む。
- **根拠**: OWID の grapher ページ（Description / Data source / Unit / Date range / Last updated / Next expected update / Managed by / How to cite）、World Bank の指標ページ（出典・発行者・ライセンス・公開日・アクセス日）、OWID のチャート画像への出典・ライセンス表記。
- **本題材への適用**: LCA では「算定範囲（A1–A3 / B6 / C 段階等）・原単位データベース名・版・評価期間（例: 60 年）」を根拠ブロックの必須項目に加える。

### P4. データの「状態」を正式な区分として表示する（速報／確定／欠損／推計）
- **ルール**: 「速報値」「確定値」「推計値」「データなし」を凡例と表の正式な値として扱い、欠損をゼロ・良好・空白で表現しない。選べない条件は無効化し、**理由**を併記する。
- **根拠**: そらまめくん（環境省ページで速報値と確定値を区別）、World Bank の地図凡例の「No data」区分、AirNow の「No Data Available」、OECD Data Explorer のデータの無い組み合わせのグレーアウト（※検索結果ベース）。
- **本題材への適用**: 測定局の停止中は斜線模様＋「測定停止（保守）」と文字で示す。室内空気質センサーの暫定値と校正済み値も同じ仕組みで区別する。

### P5. 同じ「条件（クエリ）」から図・地図・表・ダウンロード・APIを生成し、URLで再現可能にする
- **ルール**: 表示切替（グラフ／地図／表）は同一の条件を共有する。条件は URL に保持し、共有・引用・再計算ができる。表示中データと全データの 2 段階ダウンロード、API URL とコード例（Python / R）を提示。利用上限などの制約は事前に明示する。
- **根拠**: OECD Data Explorer（表とグラフが同じクエリ、SDMX API URL の生成、60 クエリ/時の上限明示 ※検索結果ベース）、World Bank（Line / Bar / Map 切替、CSV / XML / Excel）、OWID（Quick download と Data API・コード例）。
- **本題材への適用**: 既存リポジトリの Math IR パイプラインと LCA 演算子は「条件→計算→結果」の構造を持つため、評価条件を URL／JSON で固定し、同じ結果を誰でも再計算できる形と相性が良い。

### P6. 入口は「場所から」「指標から」の 2 軸、操作は市民の実タスク単位で設計し、初期表示を空にしない
- **ルール**: トップに「地域から探す」「指標から探す」を並べ、同時に全国概況を既定表示する。画面とパターンは「自分の地域の今日の空気を知る」「近くの公共建築物の CO2 を比べる」のようなタスク名で整理する。
- **根拠**: World Bank の Economy / Indicator の 2 軸ブラウズ、GOV.UK の市民タスク単位の Patterns、AirNow の Location Search（と、位置指定待ちで初期表示が空になる弱点の指摘）。

### P7. 一般利用者と専門家を「別サイト」でなく「同一ページの段階的開示」で両立させる
- **ルール**: 第 1 層＝結論と行動（平易な文）、第 2 層＝図表と比較、第 3 層＝方法・根拠・データ取得。層の順番は固定し、どの層からでも上位層に戻れる。開閉はキーボード（Enter / Space）で操作でき、状態を支援技術に伝える。
- **根拠**: NHS の「複雑さを利用者に押し付けない」と患者・職員の双方を対象とする構図、OWID の一般利用者〜研究者が同じページで目的を果たせる構成（と縦積みしすぎる弱点）、World Bank の複数プラットフォーム並立による分かりにくさ、SGDS の開閉式説明のキーボード操作。

### P8. 緊急時表示と軽量表示を最初から部品として持つ（JS 非依存のコア）
- **ルール**: 「緊急時バナー」（高濃度汚染・注意喚起発令・災害時）を最上部に表示する部品を用意し、識別帯とは分離する。本文・数値・表はサーバー側で HTML として返し、JS は拡張として載せる。低速回線向けのテキスト版を用意する。
- **根拠**: DADS の緊急時バナー（emergency-banner）、USWDS の Site alert、AirNow の最上部アラートと煙マップ導線。反面教師として、そらまめくん・OECD Data Explorer のトップが JS 描画で本文が取得できなかったこと、World Bank の表が JS 描画依存と考えられること。

### P9. 多言語・国際表記は後付けの翻訳ではなく初期要件にする
- **ルール**: 言語切替を最上部に常設し、文言が長くなっても崩れないレイアウトにする。翻訳手順を開発フローに組み込む。日付は ISO 8601（2026-11-15）を併記し、単位は SI 記法（µg/m³、ppm、kg-CO2e/m²）で統一。
- **根拠**: GC Design System の Language toggle 常設・英仏ライブラリ・ISO 日付、DADS の言語セレクター、World Bank の 5 言語切替、東京都サイトの多言語 README と自動多言語生成ワークフロー。反面教師として AirNow のスペイン語別ページ分離。

### P10. 色・余白・動きは「意味（役割）」のトークンで定義し、アクセシビリティ基準を部品単位で紐付ける
- **ルール**: `--color-text`, `--color-focus`, `--color-status-caution` のように役割名でトークン化し、値の直書きを禁止。フォーカス色はフォーカス表示専用にする。各部品に対応する JIS X 8341-3 / WCAG 2.2 の達成基準を記録する。
- **根拠**: GOV.UK の functional colours（用途限定のフォーカス色・16 進値の直接コピー禁止）、DADS のコンポーネント単位の達成基準明示と基本デザイン 8 項目、SGDS の Motion・Layer までのトークン化、USWDS の Design tokens 体系。

### P11. 設計原則・検証結果・更新履歴・終了計画を公開し、長期維持を設計の一部にする
- **ルール**: 設計原則、アクセシビリティ方針と試験結果、更新履歴（文書・デザイン・コード別）、ロードマップ、恒久 URL とリダイレクト方針、サービス終了時のデータ保存先を公開する。特定企業・特定製品・寄付への誘導を主要導線に置かない。
- **根拠**: 東京都サイトの行動原則の公開（と終了計画の欠如という教訓）、NHS「公開して透明性を高める」、GC のアクセシビリティテスト結果とロードマップ公開、DADS の分類別更新履歴、USWDS の Maturity model、OWID の寄付導線を公共サービスでは抑えるべきという指摘、SGDS の識別帯への広告混在禁止。
- **本題材への適用**: LCA の建築物比較で建材メーカー名・製品名のランキングを作らない。省エネ設備の推奨は「仕様の種類」で書き、販売元へのリンクを置かない。

## 2. 避けるべき設計（7項目）

| # | 避けるべき設計 | なぜ問題か | 根拠（台帳） |
|---|---|---|---|
| X1 | 政府・公的機関のロゴ、公式バナー、書体、ヘッダー意匠の模倣 | 大学研究のアプリが行政サービスと誤認される。なりすましと区別できなくなる | GOV.UK / USWDS / DADS / NHS / GC / SGDS の各 avoid 欄 |
| X2 | JS が動かないと本文・表が空になる構成 | 災害時・低速回線・支援技術・検索で情報が届かない | そらまめくん（タイトルのみ取得）、OECD（本文が空）、World Bank（表が JS 描画依存と推定） |
| X3 | 状態を色（赤・緑・グレー）だけで伝える／無効化の理由を出さない | 色覚多様性に対応できず、なぜ選べないか分からない | AirNow avoid、OECD avoid（グレーアウトのみ） |
| X4 | 初期表示が位置指定待ちで空、または回復手段が「全部やり直し」だけ | 最初の数秒で離脱する。高齢者が操作に迷う | AirNow avoid、OECD 弱み |
| X5 | 全情報を 1 ページに縦積み、または目的別の別サイトに分断 | 目的の情報までの距離が長い／どこを探せばよいか分からない | OWID 弱み、World Bank 弱み、そらまめくん（注意喚起を複数サイトで探させる） |
| X6 | 申請フロー向けの「1画面1問」や単一テンプレートを、専門家の比較・分析画面に機械的に適用 | 多変量を比較する専門家の作業効率を大きく損なう | GOV.UK avoid、GC avoid |
| X7 | 速報値・研究段階の推計を確定値のように断定表示する | 健康・政策判断の誤りにつながる。重要情報の誤認 | NHS avoid（研究段階データの断定）、そらまめくん（速報値と確定値の区別） |

補足: 多言語を別ページに分離する扱い（AirNow）や、危機対応サイトの終了計画の欠如（東京都サイト）も避ける。上の P9・P11 で対策を規定した。
